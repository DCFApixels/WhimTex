# WhimTex FX Language Support

`// @control(_Parameter)` links an existing parameter to the FX block header. Place it immediately after the catalog marker, or first without one. Completion, highlighting and soft validation cover this directive; duplicates warn and the last wins.

WhimTex FX source uses HLSL with `// @param` metadata directives. This bundled extension adds directive highlighting, completions and validation to VS Code's HLSL language support. Types, modifiers, parameter names, numbers, colors, enum options, ranges and operators are highlighted too; tooltip comments retain comment styling. It does not register a separate language mode or replace the HLSL grammar.

Diagnostics cover optional defaults and tooltips, color/gradient defaults, curves, transforms, texture-reference syntax, numeric bounds, enum options, compatible repeated controls, conditions, layout containers and seed modifiers. The catalog marker is recognized. Asset existence, generated shader identifiers, includes and shader compilation are still checked by Unity.

`// @group("Color")` in the leading preset comments creates a flat group in Add FX.
Groups and presets sort alphabetically with separators between groups. This quoted metadata
has no closing directive; unquoted `@group(Title)` / `@endgroup` remains parameter layout.
Place it after the effect marker and optional `@control`, before HLSL declarations/includes.
Empty, duplicate and misplaced preset groups are diagnosed.

`// @enableif _Enabled == 1` / `// @endenableif` keeps fields, attached headers/help boxes and previews visible but disabled when false. Like `@if` / `@endif` for visibility, it accepts `==`/`!=` and a finite numeric literal against a float/bool/enum driver. Drivers may be forward references or declared under `@enableif`, but not under `@if`. Blocks without parameters or standalone previews create no driver dependencies; comparison syntax is always checked. Enabled blocks may nest with themselves and with one active `@if` in either order, with at most 16 combined condition levels. Nested `@if` is still invalid. End directives take no arguments and must match the innermost condition kind. All enclosing enable conditions must pass, without overriding a disabled/read-only ancestor. Values and uniform/render behavior are unchanged; use HLSL to define the effect's behavior.

Layout directives preserve non-collapsible `@group` / `@endgroup` and add `@foldout(Title)` / `@endfoldout`, plus `@tabs` or `@tabs(Title)` containing `@tab(Page title)` / `@endtab` pages, closed by `@endtabs`. Foldouts require a title; groups may remain untitled. Groups and foldouts accept `; _HeaderParameter`; a page accepts `@tab(Page title; _Enabled)` for a bool checkbox before its label. Declare a linked parameter once, outside both condition kinds and directly in its own container/page. A supported hidden header field is promoted into the header. Tab headers reject non-bool fields; the overall `@tabs` heading has no binding. The checkbox edits a value independently of folding or tab selection; use `@if` to hide dependent rows or `@enableif` to disable editing. Individual tabs share group-header Copy/Paste/Reset actions for all values in that page, including hidden/disabled fields and nested containers.

Tab titles must be non-empty and unique within their tabs block. Parameters and standalone previews belong inside pages, never directly under `@tabs`. Groups/foldouts may nest inside pages and one another, except that opening a group when the nearest active group/foldout is a group remains invalid. Tabs cannot nest, even through another container. Layout depth is limited to 16, counting pages. All container/page starts and ends must be outside both `@if` and `@enableif`; conditions are supported around rows inside containers/pages. Each container/page needs at least one non-hidden parameter declaration or standalone preview, including descendant rows; hidden declarations alone are insufficient.

WhimTex displays content-width window-style tabs with the active tab joined to its content, and no blank heading row for untitled `@tabs`. There are no close, new or reorder controls. Collapse and page choice affect only layout: every value is still uploaded and the effect still runs. Per-FX foldout and tab choices live in UI-local `SessionState`, keyed by stable FX `ShaderKey` and container kind/id/title, outside shader values and Undo. They survive reloads during the current Editor session, not a full Editor relaunch. See the [layout contract](../../Documentation~/ShaderFX.md#layout-containers) for metadata fields and examples.

Previews support both `preview(Function)` and `preview(Function, _A, _B)`, including standalone `// @preview(...)`. Explicit names refer to declared `@param` fields, with forward/hidden references allowed. Missing names warn locally; Unity validates exact UV-first function signatures and argument order. With no list, the existing UV-only/optional-own-value forms remain available.

`// @param preview(PreviewRange) float2 _Range = (0.2, 0.8) [0 .. 1]` declares an ordered interval with two finite hard limits. Omit `[ ]` for an ordinary vector field. The preview can take `float2 uv, float2 value`; value is the actual endpoint pair. Missing/soft limits and reversed or out-of-bound defaults are rejected.
Use `[0 % 360]` for a cyclic float2 interval: `(330, 30)` crosses the seam; `(0, 360)` is full and equal endpoints are empty. Defaults/API endpoints stay within the limits, but X may exceed Y. Scalar float accepts the same `%` syntax with ordinary slider dragging and repeating manual input. Both `%` types require two hard finite limits with min < max. Linked declarations must agree on cyclic semantics.

Use `// @param seed float _Seed = 0 [0 .. ~10000]` for a numeric field with Random in WhimTex. Seed bounds must contain an integer and stay within −16777216…16777216. Labels and hidden modifiers can appear in any order. The extension validates and highlights the modifier; only WhimTex performs randomization.

Type `// @if`, `// @enableif`, `// @group`, `// @foldout`, `// @tabs` or `// @tab` and press **Tab** to insert a block with its closing directive. Compact forms such as `//@enableif` work too. The enableif snippet supplies `==`/`!=` choices and a matching `@endenableif`. Tab moves through placeholders and into the block; **Shift+Tab** moves back. Group/foldout titles can contain `; _Parameter` for a header control. The tabs snippet starts untitled: enter `(Title)` in its first placeholder for an overall title, then name its first page. Use the tab snippet directly inside that tabs block to add more pages with distinct names. Fill each page/group/foldout with controls or a standalone preview. These are ordinary HLSL snippets, also available through **Insert Snippet** (insert after `// `). The extension defaults HLSL's `editor.tabCompletion` to `onlySnippets`, without writing user settings. If your settings override it, choose `onlySnippets` for direct Tab expansion, or select the snippet through **Ctrl+Space**.

Saving a working file opened from WhimTex requests Apply by writing a neighboring `.apply` signal; ordinary HLSL files do not send this signal. Save the TIFF separately in WhimTex. The extension supports Restricted Mode and never executes workspace code.

WhimTex checks the bundled VSIX contents when opening code and reinstalls changed bundles in its isolated profile. If that VS Code window is already running, use **Developer: Reload Window** after installation to load the updated extension.

For package development, rebuild the bundled archive with `node ExternalTools~/WhimTexVSCode/build-vsix.mjs` from the package root. Add `--check` to verify it without writing. Tests share metadata cases with the Unity parser and validate all built-in FX; the optional TextMate integration test uses an existing VS Code installation via `WHIMTEX_VSCODE_APP`.
