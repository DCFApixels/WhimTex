# Переиспользование буферов снимков — 2026-11-17

Реализовано в `TiledPaintSurface` и `TiledPagePool`. Сохраняются два буфера:
снимок выделения и снимок исходного straight-цвета для защиты каналов. Каждый
`Begin` выполняет полное `Graphics.CopyTexture`; содержимое не кешируется и
ревизии изображений не используются. Размер и graphics format должны совпасть;
filter/wrap обновляются. Потерянный неактивный буфер пересоздаётся, потеря активного
снимка по-прежнему считается ошибкой. Ошибка второго снимка не публикует мазок.

## Сравнение до → после

Unity 6000.7.0a6 / Direct3D12 / RTX 5060. Та же матрица, что в
[исходном исследовании](FrozenPaintInputsBenchmark.md): непустая HDR-подложка
8192², мягкая R8-маска, запись R/A с защитой G/B, Brush 2048/4096, source UV
0.5 или −0.25 с соответствующим Transform. Два запуска по восемь измерений
после прогрева, итого 16 образцов на режим/путь/положение. Порядок режимов
вращается, отдельно измеряются непрерывный первый `PaintPoint` и выделенная
стадия снимков с GPU-ожиданием. Время включает CPU и готовность GPU через
контрольную текстуру 1×1; это не FPS и не задержка физического ввода.

Перед production-изменением baseline снят заново, затем использован **тот же
файл стенда**. Старые числа из исходного исследования не подставлены в новый
baseline: текущие большие аллокации оказались дороже. Прогрев не включает
создание нового документа в каждой выборке. Образцы разделены обновлениями
Editor, другие согласованные агентские GPU-прогоны выполнялись по очереди.

Медиана первого штампа до готовности результата, мс:

| Кисть / Transform | Без снимков | Только маска | Только защита каналов | Оба |
|---|---:|---:|---:|---:|
| 2048 / внутри | 1.60 → 1.75 | 3.43 → 2.04 | 19.03 → 5.19 | 20.83 → 5.64 |
| 2048 / снаружи | 1.70 → 1.66 | 3.46 → 2.10 | 20.17 → 4.96 | 20.47 → 5.42 |
| 4096 / внутри | 2.91 → 2.99 | 3.93 → 3.09 | 20.38 → 6.41 | 21.46 → 6.63 |
| 4096 / снаружи | 2.77 → 2.94 | 3.86 → 3.32 | 19.48 → 6.26 | 20.29 → 6.52 |

Максимум с обоими входами: 27.70 → 6.50, 26.04 → 6.26,
25.75 → 7.84 и 25.56 → 7.37 мс соответственно. Максимум только с маской
4096 внутри вырос с 4.89 до 5.31 мс при уменьшившейся медиане: единичные
выбросы остаются. Контроль без снимков практически не ускорился.

Стадия двух снимков отдельно: 20.96 → 4.35, 20.22 → 4.25,
19.76 → 4.29 и 19.60 → 4.29 мс. Это отдельно синхронизированный путь;
складывать его с другими фазами для предсказания непрерывного пути нельзя.

Выигрыш относится к повторным мазкам после подготовки буферов. Первое
выделение памяти, изменение размера/формата и повторное создание после
вытеснения остаются холодными путями. Полная копия 8К всё ещё выполняется.
Фиксация/дисковая история не входят в эти времена и отдельно не ускорялись.

## Память

Общий лимит Drawing остаётся **2 ГиБ**. Снимки входят в `AllocatedBytes` и
тот же бюджет, что страницы. Перед отказом из-за нехватки места освобождаются
только неактивные снимки; текущий мазок, исходные тайлы и версии истории защищены.
Отдельный тест с лимитом 16 МиБ проверяет вытеснение 12 МиБ снимков ради 16 МиБ
страниц, а также атомарный отказ при слишком большом активном снимке.

Максимум учитываемого пула в матрице с обоими входами не вырос:
1144 МиБ для 2048, 1256/1264 МиБ для 4096 внутри/снаружи.
**Между мазками память выросла на 576 МиБ**: 64 МиБ маски и 512 МиБ RGBAHalf.
После отмены в этой матрице было 568/680/688 МиБ, стало 1144/1256/1264 МиБ.
Кеш остаётся и при последующих мазках без этих входов. Он ограничен двумя
последними буферами на surface, вытесняется при нехватке бюджета и удаляется
при освобождении surface. Нулевой `IdleBudgetBytes` отключает и его.
Ненулевой `IdleBudgetBytes` ограничивает пустые страницы отдельно от этих
двух буферов. Это учёт payload пула, не полный пик RAM/VRAM процесса.

## Проверки и воспроизводимость

- Before и after: по 8 PASS / 14 144 проверки; снимки в трёх точках 8К,
  исходная UV-рамка, реальное действие маски/защиты, отмена и стабильность
  между отдельным Capture и непрерывным PaintPoint. Контрольные байты штампа
  совпали между before/after во всех четырёх режимах и положениях.
- `frozen-inputs-reuse`: 25 847 проверок. Все байты небольших R8, RGBAHalf,
  RGBAFloat и RGBA32 sRGB снимков; новые данные при повторном использовании,
  неизменность активного снимка, смена размера/формата/filter/wrap, ресурсная
  потеря, уничтожение входа, ошибки и освобождение памяти.
- `tiled-paint-readiness-core`: 262 проверки; маски, HDR, protected channels,
  границы/поворот/внешние тайлы, preview/commit, история, ошибки, render state.
- `drawing-gpu-undo-budget`: 71 проверка неизменности leased-версий и лимита.
- Четыре `paint-undo-reuse-exact-*`: 6576 проверок настоящих Brush/Pencil,
  маски и точного Undo/Redo на 8К с 2048/4096 внутри/снаружи Transform.

Компиляция штатным Unity Pipeline завершилась без ошибок. Рабочие шейдеры,
формат истории и UV-расчёты не менялись. Чужие правки Median/Nodes сохранены.
Другие GPU/backend и длительная многочасовая сессия не проверялись.

Отчёты: `Temp/WhimTex/test-runs/frozen-reuse-{before,after,edges,regressions}.json`.
`Temp/WhimTex/frozen-reuse/comparison.json` фиксирует SHA исходника/стенда,
16 выбранных сырых файлов и статистику; рядом сохранены два исходника до правки.
Новые сценарии ничего не удаляют из пользовательской истории; дисковые проверки
используют изолированный журнал на диске проекта.
