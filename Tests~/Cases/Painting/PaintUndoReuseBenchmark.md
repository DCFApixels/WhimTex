# Повторное использование предыдущих тайлов Undo — 2026-11-17

Оптимизация включена для sparse Raster Brush/Pencil. Повторное чтение Before с GPU
заменено копированием точных предыдущих CPU-байтов перед обновлением тайла в FIFO.
При изменённом native Undo состоянии или уничтоженном CPU-кеше Before восстанавливается
из предыдущего After журнала. Неизвестная, импортированная или уже удалённая версия
использует прежний полный снимок страницы. После инвалидирования источника доказательство
версии сбрасывается; после публикации нового мазка устанавливается заново.

Сокращается **GPU staging/readback**, обычно с 16 до 8 байт на пиксель. Дисковая запись
по-прежнему содержит независимые Before/After: её размер, формат и правила удаления не
менялись. Постоянных ссылок между файлами истории нет. CPU-буфер Before создаётся только
после проверки бюджета writer; при ошибке подготовки освобождается до изменения CPU-тайлов.
Объекты версий выделяются до публикации Undo, чтобы ошибка выделения не оставляла
опубликованный шаг без состояния.

## Методика

Unity 6000.7.0a6, Direct3D12, NVIDIA GeForce RTX 5060, Linear project. Два полных
прогона исходного кода и три оптимизированного; последний — на итоговом коде.
8192×8192, signed HDR Half, неизменный двухстраничный планировщик. Дисковый журнал
в отдельном каталоге `Temp/WhimTex/paint-undo-lifecycle` на D: для обоих вариантов.
Пользовательские настройки, журнал и документы не менялись.

- Штампы: 8 отдельных штампов, interval 1/60 s.
- Спам: 24 коротких мазка по 3 точки, без искусственной задержки между update.
- Внутри/снаружи Transform: одинаковое размещение в viewport при сдвиге исходной рамки;
  снаружи используются UV за 0…1. Сравнивается источник и фиксируется корректность размещения.
- Скорость: штатные Prepare/Begin/Paint/EndStroke + RenderCanvasViewport через
  EditorApplication.update. Без мыши, окон и измерения вывода на экран.
- Маска, Pencil и точные Undo/Redo отдельно проверены полным 8К набором. Таблица скорости
  использует обычную Brush без маски; это не замеры всех сочетаний динамики кисти.

## Фиксация мазка

Время главного потока в `EndStroke`, мс. Медиана объединённых отдельных замеров из
всех повторов; max — наибольший наблюдавшийся вызов. Это не FPS, не GPU completion
и не задержка от физического ввода до экрана. Max чувствителен к Editor и фоновой нагрузке.

| Сценарий | Размер | Transform | Медиана до → после | Max до → после | Readback за серию, МиБ |
|---|---:|---|---:|---:|---:|
| Штампы | 2048 | внутри | 13.0 → 10.4 | 47.3 → 28.8 | 800 → 400 |
| Штампы | 2048 | снаружи | 7.7 → 8.1 | 14.3 → 26.1 | 800 → 400 |
| Спам | 2048 | внутри | 12.6 → 10.4 | 57.2 → 23.0 | 2016 → 1008 |
| Спам | 2048 | снаружи | 12.2 → 7.9 | 40.2 → 30.1 | 2016 → 1008 |
| Штампы | 4096 | внутри | 65.5 → 10.6 | 386.7 → 31.3 | 2592 → 1296 |
| Штампы | 4096 | снаружи | 70.1 → 9.8 | 270.6 → 22.4 | 2592 → 1296 |
| Спам | 4096 | внутри | 116.5 → 103.1 | 379.4 → 174.0 | 7072 → 3536 |
| Спам | 4096 | снаружи | 102.5 → 96.5 | 518.2 → 186.1 | 7072 → 3536 |

Самый заметный выигрыш — конечная серия штампов 4096: 1296 МиБ помещаются в staging
1536 МиБ, поэтому фиксация больше не ждёт освобождения очереди. Для 2048 универсального
ускорения нет; отдельные штампы снаружи в этих повторах даже немного медленнее.
Непрерывный спам 4096 всё ещё заполняет очередь: сохраняется обратное давление.

## Память и оставшаяся работа

Лимиты не подняты: source GPU pool 2 ГиБ, staging максимум 1536 МиБ,
writer 64–256 МиБ в зависимости от числа CPU. CPU payload остаётся 16 байт/пиксель.
Native idle pool и число одновременно читаемых страниц не менялись.

Максимум staging в матрице: 1529 → 1535.5 МиБ, оба под тем же потолком;
для отдельных штампов 4096: 1524 → 1296 МиБ. Source pool неизменен по каждому сценарию
(до 464 МиБ). Максимум sampled active+idle native buffers: 145 → 148 МиБ;
это небольшое изменение заполнения пула, не уменьшение всей CPU-памяти и не новый лимит.
Значения снимаются после update и не являются полным пиком памяти процесса/драйвера.

Диск побайтно того же размера в соответствующих сериях: около 108/516 МиБ для
штампов/спама 2048 и 345/1710 МиБ для 4096. Следовательно, нагрузка на запись и
кодирование журнала не сокращена вдвое.

Ожидание хвоста после последнего мазка (медиана повторов, секунды):

| Сценарий | Transform | До → после |
|---|---|---:|
| Штампы 2048 | внутри / снаружи | 4.06 → 3.19 / 4.29 → 2.95 |
| Спам 2048 | внутри / снаружи | 10.18 → 7.63 / 9.98 → 6.95 |
| Штампы 4096 | внутри / снаружи | 9.05 → 10.29 / 8.45 → 10.18 |
| Спам 4096 | внутри / снаружи | 9.32 → 12.74 / 8.13 → 13.06 |

У 4096 часть ожидания переехала из фиксации в фоновый хвост. Это улучшение отзывчивости
ограниченной серии, а не двукратное ускорение полного сохранения истории.

## Корректность и отдельный найденный сбой

Прошли:

- 4 новых сценария, 74 проверки: очередь перекрывающихся masked HDR мазков, немедленный
  native Undo, ветвление, уничтоженные CPU-тайлы/созданный слой, fallback после импорта
  и очистки истории, ошибка чтения предыдущей страницы и точный повтор после её восстановления.
- 4 полных 8К сценария, 6576 проверок: 2048/4096 внутри/снаружи, маски, Brush/Pencil,
  signed HDR, побайтовые Undo/Redo. Ожидаемые данные сняты с GPU до отмены, не из журнала.
- 5 прежних сценариев, 301 проверка: существующий слой/ветвление/checkpoint/cancellation,
  dense/sparse bridges, освобождение квоты, native pages и managed fallback без Burst.
- Все 40 запусков скоростной матрицы прошли, по 12 проверок состояния/точного последнего Redo.
- Компиляция Unity успешна. SHA256 1958 остальных файлов `src` совпадают с сохранёнными:
  правки другого чата и предыдущие изменения Undo не перезаписывались.

**Отдельная ошибка, найденная при замерах:** `RunStorageConversions` падал при native Undo
HDR → 8-bit. На исходных пяти файлах до оптимизации — ровно то же расхождение 75753 байта.
Диагностика после Undo показывает правильные CPU Half-байты каждого тайла (0 отличий)
при неактуальной GPU-копии; курсор pixel history не меняется. После Redo CPU тоже верен,
GPU оставался устаревшим. Первоначальные замеры не считали весь профиль
`paint-undo-reuse-existing` прошедшим. В отдельной последующей правке исправлены загрузка
восстановленных CPU-данных на GPU и запись чистого превью поверх исходных HDR-байтов перед
конвертацией. Теперь весь профиль проходит (315 проверок), вместе с `drawing-native-undo`
(213 проверок), повторными `paint-undo-reuse` и `paint-undo-reuse-8k`. Итоговые отчёты:
`hdr-native-undo-final-focused-r2.json` и `hdr-native-undo-final-regressions.json`.

Первый запуск старого существующего теста был остановлен защитой свободного места C:
до проверок. Повтор с изолированным журналом на D: прошёл; исходный C: журнал не очищался.

## Воспроизведение и отчёты

Профили: `paint-undo-reuse`, `paint-undo-reuse-8k`, `paint-undo-reuse-existing`,
`paint-undo-reuse-benchmark`. Обычный review/opt-in flow описан в
[RUNNING_TESTS.md](../../RUNNING_TESTS.md). Тесты требуют idle Editor без существующей
пользовательской paint history; тяжёлые тесты используют собственный журнал на диске проекта.

Raw receipts в проекте `Temp/WhimTex/test-runs/`:

- `undo-reuse-before.json`, `undo-reuse-before-r2.json`;
- `undo-reuse-after.json`, `undo-reuse-after-r2.json`, `undo-reuse-after-final.json`;
- `undo-reuse-final-regressions.json`, `undo-reuse-existing.json`, `undo-reuse-existing-rest.json`;
- `undo-reuse-conversion-isolated.json`, `undo-reuse-conversion-baseline.json`.

Каждый benchmark receipt указывает уникальный подробный файл в `raster-cycle-audit`.
Агрегация, исходные хеши и отдельная conversion CPU/GPU диагностика лежат в
`Temp/WhimTex/undo-reuse-20261117/`. Нет runtime-переключателя старого/нового пути;
исходный код для сравнений сохранялся и возвращался только по проверенным хешам пяти файлов.
