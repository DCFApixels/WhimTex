# Миграция тестов: неизменяемый архив и новая основа

> Исторический отчёт первого пилотного этапа. Актуальная полная сверка,
> реальные Player/reload проверки и оставшиеся ограничения описаны в
> [MigrationFull.ru.md](MigrationFull.ru.md). Три пилотные пары повторно
> прошли в одном отчёте `2026-10-04T15-35-57.541Z-21160.json`;
> это не расширяет их доказательство на остальные оригиналы.

Первый этап выполнен локально в `dev`. Это **не завершённый перенос всего набора**.
Рабочий код WhimTex и версия пакета не менялись; commit/push не выполнялись.

## Архив

Все 466 исходных файлов `Tests~` перенесены в `Tests~/Legacy`, включая прежние тесты,
runner, отчёты и fixtures. SHA-256 каждого файла совпадает с байтами до переноса.
База — состояние после коммита `1269df5`. Архив и его manifest не редактируются.
Runner проверяет весь инвентарь и хеши перед запуском и между сценариями.
Зафиксированный хеш manifest не позволяет незаметно пересоздать его после правок архива.

В `Fixtures/` оставлена побайтово одинаковая копия общих тестовых данных, включая
шаблоны интеграционных проб. Это сохранение путей ресурсов, а не новые версии старых тестов.
Исторические инструкции внутри самого архива не переписывались; их относительные пути
могут больше не подходить для прямого запуска из новой папки.

## Новая основа

- `Framework/`: общий структурированный результат для C# и Node, assertions и счётчики.
- `Cases/`: независимые новые проверки; они не вызывают старые тесты.
- `scripts/test-catalog.json`: единственное описание сценария и его запуска.
- `migration.json`: полный инвентарь файлов и явное сопоставление проверок старого/нового кода.
- `scripts/check-migration.mjs`: сравнение пар из одного успешного отчёта; устаревшие receipts,
  дубли, пропущенные результаты и уменьшение числа проверок не принимаются.

Синхронный C# вход — `Run`. Асинхронный контракт — `Start/Poll/Cancel/Cleanup` с собственным
GUID запуска. Для нового Node-теста — именованные последовательные cases и один итоговый JSON.
Пустые тесты не зелёные. SKIP, отмена, ошибка протокола или очистки не считаются успехом.
После неоднозначного Unity-таймаута блокировка сохраняется даже при успешной очистке.

Выбор ограниченного набора: один `--id`, список `--ids`, `--group`, `--profile`.
`--all` выбирает только весь **явно зарегистрированный каталог**, не все файлы архива.
Никаких скрытых добавлений остальных тестов к выбранному набору нет.

Для старых Node-файлов создаётся отдельный Temp-снимок с прежней структурой путей
и текущими исходниками проекта. Их исходники не переписываются, `Legacy` не модифицируется.
Для C# общий helper и выбранный тест собираются в один проверенный временный input;
компиляция идёт через подключённый Unity Editor, без постоянной тестовой сборки в production.

## Проверенная эквивалентность пилота

Сопоставлены входные данные, условия assertions и очистка, затем обе версии выполнены
попарно на текущем коде в одном отчёте `migration-pilot`.

| Старый файл | Новый файл | Результат |
| --- | --- | --- |
| `Legacy/DisplayChannelsSmoke.cs` | `Cases/Rendering/DisplayChannels.cs` | 96 проверок: 6 samples × 16 masks; формулы и допуск сохранены |
| `Legacy/DocumentMigrationProbe.cs` | `Cases/Serialization/CanonicalReader.cs` | Все 11 проверок канонических имён и неизвестного поля сохранены |
| `Legacy/Compatibility0125.test.mjs` | `Cases/Files/Frozen0125.mjs` | Все прежние assertions сохранены: 30 SHA-256, 7 поддерживаемых документов, отрицательный `.asset`, рендерные данные и снятые пути |

Новый файловый тест учитывает 24 685 assertions. Старый не выдавал общего счётчика;
здесь сравнение основано на проверенных условиях/данных, старом итоговом контракте и новых facts,
а не на придуманном старом числе assertions. Пары отмечены `equivalent-tested` в machine-отчёте.

## Проверки основы и запуска

- Новый Node framework: **34 cases / 109 assertions**, включая прежние 24 сценария runner
  и новые проверки выборок, структурированного протокола, пустых тестов, отмены и сравнения.
- Старые 24 Node-сценария runner отдельно проходят в неизменённой версии.
- Общий C# API: **11 проверок**, включая JSON escaping, expected/actual, пустой тест,
  погрешность и исключение при cleanup.
- Асинхронный протокол: Start → Running → Passed → Cleanup; дополнительно **8 проверок**
  жизненного цикла, повторного Start, Cancel, подтверждения отмены и удаления своего состояния.
- Прежние **11 read-only проверок документации** проходят через `legacy-docs` и через
  реальную точку входа `ci-docs.mjs`. Workflow адаптирован без снятия этих проверок.
- `--ids` реально запустил только `frozen-files-v2,archive-integrity`; `--group rendering`
  реально запустил только `display-channels-v2`.
- Документация: source-check **84 страниц** прошёл; внешние ссылки на перенесённые файлы обновлены.
- В конце Editor Test6.6 ready/stopped, без компиляции/reload; runner.lock отсутствует.

При первом подключении C# helper обнаружилась неоднозначность `JsonConvert` между загруженными
сборками Editor. Helper переведён на публичный `JsonUtility`; повторные проверки прошли.
В рабочем коде проекта ничего для обхода этой ошибки не менялось.

## Что ещё не доказано

Остальные исходники/entry points архива ещё не перенесены и не признаны лишними.
Успех пилота не разрешает их удалять. Старый Node live-integration не зарегистрирован:
его автоматическое вычисление project path нельзя безопасно переносить в Temp-снимок.
Он сохранён без правок и требует отдельного нового сценария.

Новая async-проверка — протокольный fixture без фоновой задачи. Реальные UI callbacks,
отмена запланированных работ и очистка окон проверяются при переносе соответствующих тестов,
а не считаются покрытыми этим fixture. Тесты записи/import/export ассетов и player build
не запускались. Полный исторический набор и полная Unity-перекомпиляция не выполнялись.

Jekyll production build сейчас не выполнен: Ruby/Bundler не обнаружены на PATH;
ничего не устанавливалось. Проверены исходные ссылки/навигация и все прежние Node CI-контракты,
но это не подтверждение сборки/деплоя GitHub Pages.

Далее — переносить подсистемы ограниченными группами, записывать assertions/fixtures/cleanup
в карту покрытия и проверять пары. Удаление архива — отдельный завершающий этап после закрытия
всех исполняемых источников/точек входа и рассмотрения диагностик/ручных помощников.
