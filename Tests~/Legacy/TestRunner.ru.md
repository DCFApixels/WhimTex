# WhimTex: R14 — воспроизводимый запуск проверок

Дата: 4 октября 2026 года. Изменения локальные; commit/push и версия не менялись.

## Результат

Добавлены [явный каталог](scripts/test-catalog.json), [единый runner](scripts/run-tests.mjs) и [инструкция запуска](RUNNING_TESTS.md). Ссылки на инструкцию добавлены в AGENTS и HANDOFF.

Теперь агент выбирает профиль, читает его исходники и зависимости, получает fingerprint и запускает ровно этот набор в явно указанном проекте. Runner не угадывает методы по имени файла и не запускается автоматически.

Каталог содержит **14 сценариев**, из которых в этом проходе выполнены **13/13**. Восемь записей — существующие Unity-регрессии, но asset-writing export-parity не запускался: фактически проверены семь. Остальные записи — source guards и проверки самого runner.

Это ограниченный законченный пилот R14, а не перенос всей тестовой базы. **344 верхнеуровневых C#/Node-файла** пока вне каталога; runner перечисляет их без автоматической классификации. Вложенные наборы тоже не считаются проверенными.

## Что упрощено

- Invocation, prerequisites, effects, cleanup и final-result protocol больше не нужно восстанавливать из старого отчёта.
- Раздельно проверяются транспорт, ответ команды, compile/execute result и собственный результат теста.
- `Started` не является pass; async ждёт финальный verdict. SKIP не превращается в зелёный профиль.
- После первого non-pass профиль останавливается; оставшиеся сценарии отмечены `notRun`.
- Пересмотр исходников привязан к fingerprint. Это не разрешение на ассеты и не гарантия достаточного покрытия.
- Параллельный запуск этим runner блокируется project-local lock. При неоднозначном Unity timeout lock сохраняется: остановка CLI не доказывает остановку Editor task.
- Отчёты пишутся только в `Temp/WhimTex/test-runs`; существующий output не перезаписывается. Для сохранения этого прогона в репозитории создан [машинный снимок](TestRunner.results.json).

Универсальный reflection adapter и production test bridge не добавлялись: явные сигнатуры тестовых entry points и проверка ошибок Pipeline решили текущую задачу без такого слоя.

## Проверки окончательной версии

Окружение: Node v24.19.0; подключённый Editor **D:/DCFA/Projects/Test6.6**, Unity 6000.7.0a6. Навык `unity-cli` использован для discovery, проверки состояния и штатной компиляции/выполнения C# через Pipeline; отдельные сборщики не запускались.

| Профиль | Завершённый результат |
| --- | --- |
| runner-unit | 24/24 Node-кейса: каталог, выбор, fingerprint, разные уровни ошибок, timeout, async и cleanup |
| source | 2/2 существующих source guards |
| core | 6/6 существующих Unity-регрессий |
| layer-preview | 1/1 существующая асинхронная регрессия, дождались финального результата |
| runner-protocol | 2/2 положительных fixture: обычный и Start → Running → Passed с cleanup |
| runner-live | Ожидаемые отрицательные verdicts и проверка cleanup корректно распознаны на живом Editor |

Core: R01–R04 — 2382 проверки; SharpenMaterialOrder — 3309; EditableCopy — 8; Compatibility0125Reader — 20; DocumentMigrationProbe — 11; DisplayChannels — 96. LayerPreviewReuse — 2 752 550 assertions.

В живом runner-live проверены внутренний `success:false`, исключение, неверные аргументы, отсутствующий entry, SKIP, async failure и последующая чистота fixture. Отрицательные результаты здесь намеренные: это проверка распознавания, не оставшиеся красные регрессии проекта.

Дополнительно проверены семь CLI guards: устаревший receipt, отсутствие явного project path, неподтверждённые effects, неизвестный профиль, конфликт profile/id, недопустимый output и существующий output. Эксклюзивный lock проверен отдельным запуском; отказ перезаписи подтверждён неизменным SHA-256 существующего отчёта.

В первом запуске runner-unit sandbox заблокировал Node child process с `spawn EPERM`. После разрешения среды тот же механизм успешно отработал; platform-specific обходы или изменения производственного кода не добавлялись. Проверки CLI exit codes учитывали именно native exit code, а не булевый статус оболочки PowerShell.

На завершении Editor доступен, не компилирует, не перезагружает domain и не в Play mode. Временный lock тестового прогона освобождён.

## Границы

- Производственный код, файловые контракты, frozen fixtures и существующие тесты не изменялись. Новые C# fixture находятся в ignored-for-import `Tests~`.
- Не выполнялись export-parity с временным TIFF asset, полный предыдущий набор из 31 сценария, весь исторический набор или все Node-файлы.
- Блокировки timeout/cleanup failure проверены управляемыми mock transports. Настоящий зависший Editor task намеренно не создавался.
- Каталог не проверяет все prerequisites автоматически, не координирует другие инструменты и не заменяет чтение кода.
- Существующий Layer Preview сам закрывает своё окно в callback, но не имеет внешнего cancel entry. Timeout требует проверки фактического завершения/cleanup.
- Production Jekyll/GitHub Pages и player build не запускались: изменения касались тестовой инфраструктуры и внутренних инструкций.
- R05 и ограниченный R09 пока не реализованы. Следующий самостоятельный этап — R05.
