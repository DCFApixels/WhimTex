# F30. Общая CPU-модель градиентов и последующее обновление GPU-палитр

- Назначение: объединить алгоритмы интерполяции и цветовые модели в общую систему градиентов WhimTex.
- Статус: 2026-10-24 пользователь ограничил первый этап CPU-алгоритмами и цветовыми моделями; существующие GPU-кеши остаются. CPU и UI выполнены 2026-10-25. Обновление GPU отложено; альтернативное ограничение цвета через уменьшение насыщенности — неподтверждённая идея. Проверки и границы указаны ниже.
- Источники: обсуждение с пользователем; [текущий CPU-расчёт](../../src/WhimTexGradient.cs), [сегментная палитра](../../src/WhimTexGradientPalette.cs), [общая LUT](../../src/WhimTexGradientTexture.cs), [палитра кисти](../../src/Layers/DrawingLayerBehaviour.BrushGradient.cs), [чтение сегментной палитры](../../src/Shaders/GradientPalette.cginc).

## Выполнено

CPU-модель, интерфейс, API и сохранение настроек реализованы. Штатная компиляция Unity
прошла; десять существующих сценариев проверили ключи/midpoint, HDR, сериализацию,
Undo/Redo, GPU-палитру, Gradient Map/FX, Reverse, группы/Target/clipping и экспорт.
Новые тесты и постоянный внешний эталон не добавлялись. Численное совпадение всех
возможных комбинаций новых алгоритмов отдельным набором не проверялось.
Применимые проверки находятся в [Cases/Color](../../Tests~/Cases/Color), контракт —
в [руководстве](../../Documentation~/ru/color.md).

### Реализованный CPU-этап

Перенести согласованную математическую основу максимально точно, сохранив
существующие способы передачи цветов на GPU. Число отсчётов, форматы текстур,
фильтрация, mipmaps и GPU-поиск сегментов в этот этап не входят.

### Алгоритмы и цветовые модели

- Разделить цветовую модель интерполяции и алгоритм построения перехода.
  Цветовые модели: Linear (linear RGB), Gamma (encoded RGB), Perceptual (OKLab),
  Hue (OKLCH с отдельной обработкой направления hue и ахроматических участков).
- Алгоритмы: Blend, Balanced, Smooth, Adaptive; существующий Fixed сделать ещё
  одним режимом интерполяции, сохранив поведение ступеней и граничных значений.
- Перенести настройки Chroma Correction, Smoothness и Hue Path с их реальной
  областью действия в исходной реализации. Hue Path: Shortest, Longest,
  Increasing, Decreasing. Не заменять разные алгоритмы одним smoothstep.
- Сохранить midpoint-семантику каждого алгоритма. В частности, у Adaptive
  midpoint управляет формой кривой и не обязан означать точный полусмешанный цвет.
- Альфа использует выбранную интерполяцию как отдельная скалярная кривая со
  своими ключами и midpoint. Цветовая модель, Hue Path и Chroma Correction
  не применяются к альфе. В исходном прототипе alpha нет: это расширение WhimTex.
- Сохранить Clamp / Repeat / Mirror, HDR и значения ключей. По уточнению пользователя
  2026-10-25 ограничивать RGB общими расширяемыми границами по ключам, как описано ниже.
  Не смешивать модель интерполяции с техническим кодированием цветов при хранении и передаче в рендер.
- Подготовку кривых и преобразования выполнять в double, затем выдавать float
  существующим потребителям. Тяжёлую подготовку, особенно Adaptive, кешировать
  по данным градиента; не решать её заново для каждого отсчёта или Repaint.

### Ограничение RGB: действующее поведение

Для каждого сегмента между цветовыми ключами A и B используется один общий диапазон:
`min(0, A.r, A.g, A.b, B.r, B.g, B.b)` … `max(1, A.r, A.g, A.b, B.r, B.g, B.b)`.
Границы подготавливаются вместе с кривыми. Результат ограничивается после интерполяции,
преобразования обратно в RGB и Chroma Correction; ключи и результат берутся в одном
RGB-кодировании. Ограничения по отдельным каналам нет. HDR и отрицательные ключи,
точные значения ключей и Fixed сохраняются; alpha по-прежнему ограничена 0..1.
При выходе ключа за 0 или 1 граница расширяется непрерывно, без отключения ограничения
всего сегмента. GPU-кеши остаются прежними.

После добавления ограничения штатная компиляция Unity и существующие сценарии
`whim-tex-gradient-v2`, `whim-tex-gradient-contract-v2`, `whim-tex-gradient-pipeline-v2`
прошли повторно. Новые тесты не добавлялись; отдельного полного перебора новых границ
для всех цветовых моделей и интерполяций нет.

### Неподтверждённая идея: уменьшение насыщенности вместо обрезки

Статус: не утверждено к добавлению; рассматривать только при обнаружении проблем
действующего ограничения — сдвига оттенка или заметных плоских участков перехода.
Возможная альтернатива: уменьшать цветность (насыщенность) до попадания RGB в допустимый
диапазон, стараясь сохранить оттенок и светлоту. Нужно отдельно определить поведение
для расширенных HDR-границ и отрицательных значений; текущую Chroma Correction
не считать готовой реализацией этого подхода.
Справка: [W3C — Gamut Mapping](https://www.w3.org/TR/css-color-4/#gamut-mapping).
Этот пункт не поручает реализацию и не меняет согласованный этап GPU.

### Граница переноса

Внешний прототип используется только во время реализации. Постоянной зависимости,
замороженного эталона и новых тестов не создавать. После переноса система самостоятельна.
Применимые лицензии и авторские уведомления сохраняются в ThirdPartyNotices.md.

Особенно сверить Balanced с дополнительными midpoint-узлами и PCHIP, табличную
кривую Smooth, подготовку Adaptive, signed color conversions, обработку серого
в Hue и коррекцию chroma. Старый Rounded/Perceptual не считать эквивалентом
новой математической основы и не накладывать поверх неё как дополнительный фильтр.

### Интеграция первого этапа

- Все существующие потребители Evaluate/Bake получают новые алгоритмы через
  общую CPU-модель: слои, Fill/Stroke, Text/Character, параметры FX, кисти и превью.
  Пространственные координаты и манипуляторы градиентов не перерабатывать;
  Freeform не заменять одномерной моделью.
- Отразить новые настройки согласованно в модели, редакторе градиента,
  копировании/равенстве/revision, Undo/Redo, текущих форматах документов и пресетов,
  clipboard и API. Обновить документацию фактически реализованного контракта.
- Изменение новых параметров должно инвалидировать существующие кеши цветов.
  Это адаптация зависимостей к новой модели, а не замена GPU-кешей.
- Названия UI: Color Mode и Interpolation. Контракт: ColorMode = Perceptual,
  Interpolation = Balanced, HuePath = Shortest, ChromaCorrection = 0, Smoothness = 1.
  ColorSpace остаётся техническим кодированием Gamma/Linear, WrapMode — Clamp/Repeat/Mirror. Совместимость форматов — по действующим AGENTS.md, без молчаливой
  переинтерпретации неподдерживаемых данных.

### GPU-пути, которые пока сохраняются

| Текущий путь | Что сохраняется |
| --- | --- |
| WhimTexGradientPalette: Gradient, Shape, Vector/Boolean и Text | 256 отсчётов на интервал, отдельные строки RGBAFloat, текущая билинейная выборка и массив границ в шейдере. |
| WhimTexGradientTexture: параметры FX, Noise, SDF, Pattern | Обычно 512 отсчётов на весь градиент, две одинаковые строки RGBAHalf, текущая фильтрация с отдельным поведением Fixed. |
| Градиент наконечника кисти | 1024 отсчёта на весь градиент, две строки RGBAHalf, premultiplied alpha, mipmaps и Trilinear. |

Запекаемые цвета изменятся вслед за выбранной математикой. Сохранение GPU-путей
не означает сохранение прежних цветов или обещание точного воспроизведения
новой CPU-кривой существующими LUT. Их текущие ограничения точности сохранены.

## Custom: выполнено

Реализовано собственное окно ручных кривых и независимые каналы.
Автоматические данные сохраняются отдельно; первое включение
Custom приближённо повторяет текущий градиент, последующие возвращают ручные кривые.
Convert Color Mode явно перестраивает их с приближённым сохранением вида; число ключей,
и касательные могут измениться. Наблюдаемая ошибка преобразования не является
доказанной верхней границей на всём интервале.

API/clipboard, native JSON/TIFF и настройки инструментов сохраняют customKeys,
customColorMode, идентификаторы и касательные, включая неактивный набор.
Native-документ также сохраняет диагностическую customApproximationError; API и
standalone-пресеты её не восстанавливают. Невалидные данные отклоняются. Двухцветный
HLSL-default не может представить Custom и отклоняет экспорт даже неактивных ручных
кривых. Форматы документа v3 и gradient clipboard v2 остаются; GPU-кеши не меняются.
Контракт: [Custom channel curves](../../Documentation~/AI/README.md#custom-channel-curves),
[C# API](../../Documentation~/AgentAPI.md#custom-gradient-settings).

В первоначальной реализации до удаления Link Keys проверено 2026-10-25:
штатная компиляция Unity без ошибок; семь существующих сценариев
(`whim-tex-gradient-v2`, `whim-tex-gradient-contract-v2`, `whim-tex-gradient-window-v2`,
`whim-tex-gradient-pipeline-v2`, `gradient-reverse-v1`, `gradient-defaults-smoke-v2`,
`gradient-gpu-smoke-v2`) прошли. Новые тесты не добавлялись.
На временных объектах через публичные API отдельно просмотрены Custom-сериализация,
JSON roundtrip документа, переключение автоматических/ручных данных, Convert и Link Keys.
Unity Undo/Redo восстановили положение ключа 0.4 → 0.7.
Нативные жесты нового окна и всех манипуляторов вручную не проверялись; существующие
сценарии не заявляют полного покрытия Custom. GPU-кеши, форматы и фильтрация сохранены;
ступени Constant не получают специальную GPU-ветку Fixed.

### Замена постоянных связей группировкой маркеров

По новому решению постоянное поле `link`, LinkCustomKeys и UnlinkCustomKeys удалены.
API, JSON, TIFF и настройки инструментов отклоняют явное устаревшее поле `link`,
включая нулевое значение; миграции нет. Существующие пользовательские файлы не изменяются.

Группировка вычисляется по всем каналам, включая альфу: ключи сортируются по t,
затем ID; очередная группа включает ключи в пределах CustomMarkerTimeTolerance = 0.00001
от самого раннего оставшегося ключа. Цепочки близких соседей не объединяются транзитивно.
Фильтр цвет/альфа применяется внутри этих же групп; представителем становится первый
подходящий ключ. GetCustomMarkers(null) возвращает представителей общего трека.
GetCustomMarkerGroup(id) возвращает все ID группы в порядке t/ID, не изменяя сами ключи.

MoveCustomKey/RemoveCustomKey затрагивают только один ключ. Для жеста общего маркера
его ID фиксируются в начале и передаются в MoveCustomKeys(ids, deltaTime): один общий
сдвиг ограничивается 0..1 и ближайшими невыбранными соседями того же канала, сохраняя
порядок и относительные расстояния с учётом округления float. Если округление нарушает
минимальный интервал, общий сдвиг дополнительно уменьшается. RemoveCustomKeys(ids)
атомарно удаляет набор, но отклоняет опустошение любого канала. Новые соседи не входят
в фиксированный набор автоматически. AddCustomColorKeys создаёт независимые ключи
трёх цветовых каналов на общем t. Полный контракт и оставшиеся лимиты — в C# API выше.

Эта замена проверена только просмотром исходников; Unity и тесты для неё не запускались.
Предыдущие результаты не подтверждают новую группировку и атомарные операции.

## Отложено: общая адаптивная GPU-палитра

Сохранённое предложение для следующего этапа; сейчас не внедрять.

- Разбивать градиент по объединённым позициям цветовых и альфа-ключей.
  Для каждого интервала подбирать своё число равномерных отсчётов по ошибке
  восстановления, а не по размеру изображения. Плотно размещать их в общей
  палитре RGBAFloat без сжатия и автоматических mipmaps.
- Каждая запись таблицы содержит **Start, End, Offset, Count**. Пользователь
  явно выбрал хранение обеих границ в каждой записи: они нужны одновременно
  для локальной координаты; не восстанавливать Start чтением соседа.
- Таблицу читать через Texture2D.Load по целочисленному индексу, без фильтрации.
  Для выбора интервала предложен двоичный поиск по End; преимущество по времени
  на коротких списках не измерено. Обе границы затем доступны из той же записи.
- Для цвета предложены два Load соседних отсчётов и lerp в float32. Это один
  способ вычисления цвета: два чтения, затем математическое смешивание.
  Fixed читает нужную ступень без смешивания через границу.
- Явный lerp позволяет хранить мало отсчётов на простых участках без ограничения
  дробной позиции аппаратного фильтра. Он не устраняет погрешности t, границ
  или запекания; ускорение относительно аппаратной фильтрации не обещано.
- Контроль ошибки должен учитывать восстановление между отсчётами и округление
  до float32, RGB/HDR и alpha. Конкретные допуски, пределы памяти и поведение
  при достижении лимита ещё не выбраны. Набор проверенных точек сам по себе
  не доказывает строгую верхнюю границу ошибки на всём интервале.
- Правила точности общие для слоёв и параметров FX. Не передавать запросы на
  повышенную точность от Normal Map или другого потребителя назад через слои:
  оборачивание Gradient в группу не должно менять качество исходного градиента.
- Общий кеш зависит от данных градиента. Перемещение манипуляторов не требует
  перепекать цвета. Для кистей допустимо специальное производное представление
  с нужной premultiplication/фильтрацией, но не отдельная математика интерполяции.

Порог ошибки, размещение отсчётов, стоимость поиска/чтений и качество после
последующих Height/Normal-преобразований требуют отдельного решения. Не считать
их утверждённой или реализованной частью CPU-этапа.
