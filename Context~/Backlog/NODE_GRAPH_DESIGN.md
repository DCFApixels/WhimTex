## Предлагаемая основа

Сначала читать [уточнения обсуждения](#уточнения-layers-и-fx-перед-доработкой-sdf).
Они дополняют первоначальный дизайн и уточняют статус решений; наличие
технической рекомендации ниже не означает её согласование пользователем.

Граф — источник истины для вычисления. Layers — редакторская проекция композиции
и доступных входных веток этого же документа, а не второй список со своей моделью.
Художник может продолжать работать слоями и прикреплять FX как сейчас; Graph
открывает источники, ответвления, параметры, повторения и несколько выходов.

| Решение | Рекомендация | Зачем |
| --- | --- | --- |
| Композиция | Специальный узел Stack с упорядоченными участниками. | Перестановка слоя меняет композицию, но не подменяет ссылки на источники. |
| Layers | Композиционное дерево плюс вложенные ветки, обозначенные по входам слоя/FX. | Позволяет редактировать древовидную часть графа через слои; произвольные связи остаются доступны в Graph. |
| FX | Упорядоченный стек на поддерживающем его узле. | Не превращать каждую простую коррекцию в отдельную карточку. |
| Соединения | Стабильные ID узлов и ключи портов. | Переименование, сортировка и изменение UI не ломают адреса. |
| Выполнение | Типизированные значения и явно объявленные стадии. | Изображения, векторы и числа не обязаны превращаться в текстуру на каждом ребре. |
| Transform | Матрица на данных до явно заданной границы растеризации. | Последовательные геометрические операции не пересэмплируют растр без необходимости. |
| Пространственные FX | Явное пространство выборок; по умолчанию Document. | Толщина контура не должна неожиданно зависеть от растяжения источника. |
| Шейдерный подграф | Отдельное позднее расширение. | Общий граф изображения не равен автоматически собранному HLSL-шейдеру. |
| Редактор графа | Публичный UI Toolkit, совместимый с Unity 6.0. | Модель и файл не зависят от конкретного UI-фреймворка графов. |

Названия `DocumentGraph`, `GraphNode`, `Stack` и остальных новых типов ниже
рабочие. `ToolGraph` не закрепляется как название модели: документ содержит
вычисление изображения, а не только инструменты Canvas View. Существующие
`WhimTexDocument` и `WhimTexWindow` сохраняют свои роли владельца и окна.

## Что есть сейчас и что подтверждено исследованием

Сейчас `Layer` хранит поведение, Transform, Rendering, ссылки FX и детей группы.
`ApplyTransformAndFx` материализует трансформированный источник в RenderTexture,
затем запускает FX. Рендер групп, clipping, Target, Processor и экспорт имеют
собственные контексты. `Previous`, `AllBelow` и texture-layer параметры уже
создают зависимости; это ещё не универсальный типизированный граф.

Текущая защита от циклов неоднородна. [Перетаскивание в Layers](../../src/WhimTexWindow.Selection.cs)
меняет порядок без предварительной проверки всех зависимостей; рендер затем
не использует циклический Target/AllBelow, а [FX texture input](../../src/ShaderFX.TextureLayers.cs)
при недопустимом источнике получает прозрачную заглушку. Для AllBelow UI показывает
предупреждение. [Агентский batch](../../src/Automation/WhimTexApi.cs) сначала проверяет
копию модели и отклоняет обнаруженные циклы явных источников/FX/AllBelow до
применения. Это не универсальная проверка будущего графа стадий. Единое атомарное
отклонение переноса ниже — целевое поведение, не уже реализованное правило UI.

Исследованная открытая реализация подтверждает следующие приёмы, но не задаёт
контракт WhimTex:

- Рёбра могут ссылаться на поставщиков типизированных значений, а не только на готовые изображения. GPU-коррекция цвета при этом действительно создаёт новую текстуру; автоматического слияния произвольной цепочки в один shader из этого не следует.
- Transform может перемножать матрицы в атрибутах результата. Это не решает пространство выборок каждого последующего фильтра: локальный Blur сохраняет матрицу, а согласование радиуса с пространством документа отдельно отмечено как незавершённое.
- Repeat вычисляет ветку с индексом повторения и собирает список результатов; геометрия не обязана проходить через растр между копиями.
- Структура Layers восстанавливается из композиционных связей графа. Перенос слоя — операция переподключения, с ограничениями и транзакцией, а не независимая сортировка UI.
- Перенос может переподключать и других потребителей композиционного выхода. Поэтому утверждение «все боковые провода всегда сохраняются» было бы неверным. Запрещаются вложение в себя и некоторые недопустимые переносы; общая запись соединения проверяет цикл. Это не доказательство атомарности любого сложного переноса.

Для WhimTex предлагается собственный контракт Stack ниже, с более строгим
разделением композиционных и явных зависимостей.

## Модель и стабильные адреса

`WhimTexDocument` остаётся владельцем сериализованной модели и Undo. Не требуется
делать каждый узел, слой и порт отдельным ScriptableObject ради графа. Такой
переход можно оценить отдельно в F01; он не должен менять адреса соединений.

| Запись | Сохраняемые данные | Не сохраняется как источник истины |
| --- | --- | --- |
| DocumentGraph | Узлы, Inputs, Outputs, ссылки на ресурсы, корневые Stack. | Скомпилированный план и граф зависимостей кеша. |
| GraphNode | `id`, `typeKey`, `typeVersion`, settings, входы по ключам, упорядоченные `fxIds`, необязательный Layer envelope. | VisualElement, Material, RT и делегаты исполнителя. |
| Layer envelope | Имя, Transform, Rendering, visibility и признаки композиционного поведения. | Вторая копия соответствующей строки Layers. |
| Stack | Упорядоченные `layerNodeIds`, режим композиции. | Сериализованные копии автоматически созданных Merge-стадий. |
| FX instance | `id`, ссылка/снимок определения, values, bindings, enabled. | Индекс в стеке как идентификатор. |
| Input | `id`, key, label, type, default, constraints, необязательная роль Time. | Текущее значение проигрывания таймлайна. |
| Output | `id`, label, endpoint, размер, encoding и назначение. | Текущий выбранный preview как источник импортируемого результата. |
| Resource | `id`, тип, сохранённое содержимое или явная внешняя ссылка. | Владение GPU-копиями через Unity instance ID. |

`Layer envelope` — общая оболочка существующих слоёв, не новая разновидность
shader FX. Effect Layer остаётся отдельным вычислительным узлом/слоем, например
Outline или SDF; FX остаётся добавляемым шейдерным блоком.

Для простого слоя Noise или Drawing генератор и envelope можно хранить в одном
узле и показывать одной карточкой. При использовании общей ветки несколько
слоёв становятся узлами размещения с входом `content`, подключённым к одному
источнику. Отделение общего источника — явная команда, не дублирование настроек
между двумя моделями. Узлы без envelope, например Math, не становятся
самостоятельными участниками композиционного Stack; при раскрытии входной
ветки их можно показывать как источники/ссылки без фиктивного Layer envelope.

Адреса:

```text
Endpoint       = nodeId + outputKey
FieldTarget    = nodeId + fieldKey [+ componentKey]
FXFieldTarget  = fxId   + parameterId [+ componentKey]
Stack position = stackId + beforeLayerId | end
```

FX ID уникален внутри документа независимо от своего узла-владельца. Один
экземпляр имеет одного владельца выполнения. Добавление того же пресета дважды
создаёт два экземпляра с независимыми значениями; определение/скомпилированный
shader можно разделять. Существующее совместное использование SO нельзя молча
превратить в независимые значения: при переходе выбрать явную политику создания
экземпляров, не скрытую синхронизацию.

Ключи портов и полей задаёт descriptor; имя в UI, порядок controls и массивов
не является адресом. У изменяемого списка входов каждый элемент имеет свой ID.
Удалённый ключ оставляет диагностируемую потерянную ссылку, не выбирает соседний.
`typeVersion` описывает схему узла, Source ID/Version FX из F14 — его источник,
а версия файла — весь контракт документа. Эти номера не взаимозаменяемы.

## Типы и правила соединения

| Тип | Значение | Типичные операции |
| --- | --- | --- |
| Number, Integer, Bool | Одно значение на вызов ветки. | Math, сравнение, Seed, Inputs. |
| Vector2/3/4, Color | Типизированное значение; Color хранит назначение пространства. | Transform, цвет, параметры генератора. |
| ImageFrame | Растровый ресурс, pixel-to-document матрица, bounds и описание каналов. | Raster FX, семплирование, Merge. |
| VectorGeometry | Контуры, геометрия, стили, матрица и bounds. | Curves, Shape, Transform, Repeat. |
| DistanceField | Float field с sign, distance units и bounds; предварительный растровый контракт F19, векторное расширение F08 позднее. | Feather, offset и SDF-обработка; не неявная Color-картинка. |
| Scene | Упорядоченные объекты с локальными атрибутами. | Собрать вектор и растр без преждевременного запекания. |
| List&lt;T&gt; | Однородный список типизированных объектов. | Repeat, Map, фильтрация, размещение. |
| PixelProgram / UVProgram | Позднее расширение: вычислимая попиксельная функция. | Процедурный источник и изменение координат до его вычисления. |

ImageFrame не является только Texture2D: editor-исполнение может держать RT, а
сохранение — ссылку на CPU-ресурс/контейнерный блок. Порт передаёт handle с
описанием, не копирует все пиксели. Векторные данные неизменяемы во время
вычисления; новые объекты могут разделять геометрию и иметь разные матрицы.

Descriptor объявляет входы, выходы, fallback, ограничения, зависимость выходов
от входов, поддерживаемые пространства и эффект отсутствующего входа. Использовать
белый список типов и операций, а не вызывать произвольный сериализованный C#.

Автоконверсии MVP: Integer → Number. Scalar → Vector/Color только через явно
указанный режим broadcast; Vector → Image, Image → Scalar и Vector3 → Color
не угадываются по числу компонентов. Несовпадение типов показывает причину
отклонения провода. Rasterize, Sample, Pack и преобразование пространства цвета
являются явными операциями. Доступность конверсии в UI не делает её скрытой
переменой модели после загрузки.

Изображение объявляет color/data intent, encoding, alpha representation и
диапазон. Числовые и HDR/data ветки сохраняют отрицательные значения; clamp
появляется только на объявленной границе Standard/output encoding. Не переносить
скрытый `saturate` в каждое ребро. Для переноса существующего рендера сохраняются
его текущие FinishStage-границы; изменение этой политики — отдельное решение.
Нормали и displacement не декодируются как sRGB без явно указанной операции.

## Layers и Stack

Stack хранит композиционный порядок сверху вниз, как текущий список слоёв.
Исполнитель складывает снизу вверх. Основные строки Layers строятся обходом
Stack и композиционных групп; под обычным слоем дополнительно можно раскрывать
его входные ветки. Это вычисляемая структура UI. Перемещение карточки по XY
в Graph не меняет Stack. Перемещение композиционной строки вызывает `MoveLayer`;
перенос между входными ветками означает другую graph-команду, описанную ниже.

У LayerNode не более одного композиционного родителя. Один и тот же источник
может питать сколько угодно LayerNode и Outputs; повторное размещение создаёт
новый LayerNode со своим envelope, а не второго родителя прежнего слоя.
Stack создаёт композиционные строки только для своих LayerNode. Источники
входных веток могут отображаться под потребителем, не становясь участниками
его внешнего Stack. Произвольный DAG нельзя превратить в обычное дерево
с единственным родителем каждого узла: общий источник требует представления
ссылкой/повторным показом того же узла либо редактируется в Graph. Вложенность
UI не создаёт копию источника или второго композиционного родителя.

### Выход слоя и выход композиции

`content` слоя означает результат его источника, размещения, прикреплённых FX,
Mapping и Color Range, **до** зависящего от Stack clipping и внешнего blending.
Он не включает накопленный фон снизу. Descriptor может отдельно открыть `source`
до размещения/FX; это другой ключ, не переключение смысла `content`.

Stack имеет `composite`. Внутри плана каждый участник получает вход `below`
и при необходимости результат `previousContent`. Эти промежуточные значения
не выдаются за собственный `content` слоя. Исходные подписки Target и texture FX
сопоставляются по их действующей семантике, включая group color/alpha варианты;
при необходимости вводятся явно названные отдельные порты, не скрытая смена
смысла общего Image-порта.

`Previous` и `AllBelow` сохраняются как контекстные входы LayerNode в Stack.
Это сохранённый способ выбора, который compiler раскрывает по текущему порядку.
У контекстного входа один владелец Stack; свободный узел вне Stack должен иметь
явный источник. Перестановка ожидаемо меняет Previous/AllBelow, но не явный
`nodeId + outputKey`. FX texture-параметры становятся явными зависимостями
экземпляра, а не повторным поиском слоя по позиции в UI.

Для переноса текущих texture inputs закрепить разные выходы, не переименовать
все запросы в `content`:

| Источник | Контракт стадии |
| --- | --- |
| `content` | До outer opacity/blend и Stack clipping, как определено выше. |
| `textureInput` обычного слоя | Его готовый растр с clipping, без внешнего blend/opacity; разрешает явное чтение hidden source. |
| `textureInput` группы | Изолированный собственный color result с её FX/Mapping, clipping и group opacity; не внешний backdrop. |
| `coverage` группы | Отдельный запрос mask/alpha с действующими правилами coverage и диапазона. |
| FX `Self` | `StageInput` непосредственно перед данным FX, после предыдущих FX. Не endpoint итогового `host.content`. |

`Self` — сохранённый вариант input selection, который compiler разрешает по
FX ID в стеке. Перестановка FX ожидаемо меняет Self, не создаёт циклическую
подписку на будущий результат. Clipping-зависимость `textureInput` тоже участвует
в полной проверке циклов. Target/Previous descriptors выбирают соответствующий
color/coverage порт по существующему контракту, а не одному универсальному alias.

### Вложенные ветки входов в Layers

Дополнение обсуждения: Layers и Graph должны редактировать одну модель.
Слоевое представление можно расширить так, чтобы обычный слой содержал
вложенные источники его входов, прежде всего масок. В древовидном случае
вложенность выражает вычислительные связи, а не только папки и порядок наложения.
Наличие общего источника в нескольких ветках не ограничивает полный граф
возможностями дерева UI.

При нескольких входах требуется обозначить, какой вход питает каждая ветка.
Пользователь предложил группы/папки внутри слоя: в каждой свои слои, а результат
группы подключён к определённому входу родителя или прикреплённого FX.

```text
Layer
├─ Input: Image
│  └─ Group
│     ├─ Drawing
│     └─ File
├─ Input: Mask
│  └─ Group
│     ├─ Shape
│     └─ Noise
└─ FX Distortion: Map
   └─ Noise
```

Это пример для обсуждения, не окончательные UI labels или обещание универсального
Mask-порта во всех текущих типах. В Graph выход первой группы подключается к
image input, второй — к mask input, отдельный Noise — к texture input выбранного
FX. Содержимое этих веток не накладывается поверх родительского слоя в основной
композиции. Если группа собирает несколько изображений, она имеет собственный
Stack, и в порт поступает его результат; нельзя подавать массив изображений
в одиночный Image-порт без объявленной операции сборки.

Рекомендация для дальнейшего дизайна — различать заголовок входа и настоящий
вычислительный узел группы. Заголовок только обозначает связь/роль и может
раскрывать один источник, группу с композицией либо ссылку на общую ветку.
Он не требует нового Merge/Stack для каждого одиночного подключения. Нужно
различать служебную секцию входа и обычную группу; направление секций поддержано
пользователем в последующем обсуждении. Детали строки и действий описаны в
[уточнениях Layers](#уточнения-layers-и-fx-перед-доработкой-sdf), а не считаются
утверждёнными этой первоначальной схемой.

Правила предлагаемого расширения:

- Вложенные строки выводятся из реальных connections и descriptors, не сохраняются вторым независимым деревом. Можно хранить editor-local expansion/layout, но не дублирующую связь в «списке детей входа».
- Вход слоя адресуется по node ID и port key, вход FX — по FX instance ID и parameter ID. Перестановка FX не переназначает папку входу другого блока с тем же индексом.
- Древовидную ветку можно создавать/править в Layers; сложные перекрёстные зависимости остаются доступны в Graph. Общий источник не клонируется из-за повторного отображения. Конкретный UX ссылок и Edit Source/Make Unique ещё согласовать.
- Композиционные группы и input-группы имеют разные роли. Вложенность источника под потребителем сама по себе не наследует его Transform, opacity или clipping; пространство и место применения маски/входа должны быть явными в контракте порта.
- Previous/AllBelow остаются позиционным выбором источника. Раскрытие входа может показать текущий разрешённый источник как ссылку; оно не превращает его в owned child. Подключение собственной группы явно заменяет этот режим на connection, а не незаметно меняет смысл «предыдущего».
- Reorder слоёв внутри настоящей input-группы меняет её Stack. Перенос ветки между входами означает Connect/Disconnect с проверкой типов и циклов, а не обычный `MoveLayer` внешнего Stack. Точный жест и последствия для других потребителей пока не выбраны.
- Удаление заголовка/разрыв связи не равны удалению источника. У общего источника могут остаться другие потребители; destructive delete требует отдельной команды по правилам общей модели.

Перед реализацией остаётся выбрать: вид строк и меню входов; владение входной
веткой или только ссылкой; fallback пустой папки и портов; отображение shared
sources и «ромбов»; разрешённые drop actions и multi-selection; системы координат
и порядок Mask относительно Transform/FX. Предварительное одобрение направления
не утверждает эти детали и не поручает реализацию.

#### Входные секции отключённого FX

Отключение FX исключает его обработку из текущего результата, но не удаляет
экземпляр FX, его входные секции, подключённые источники или композицию внутри
веток. Стабильные адреса входов и connections остаются в модели и сохраняются
в документе. Повторное включение использует прежние подключения без пересоздания
дерева или повторного назначения источников.

В Layers заголовок секции и вложенные строки отображаются приглушёнными, с
пониженной визуальной непрозрачностью и понятной причиной «FX disabled».
Приглушение не должно делать текст нечитаемым. Секцию по-прежнему можно раскрывать,
выделять и редактировать: неактивно использование результата данным FX, а не
управление веткой. Отключение FX не меняет собственные visibility/enabled
настройки источников.

Неактивность относится к конкретному использованию входа. Если тот же источник
питает включённый FX, другой слой или Output, его активное представление и
вычисление для этих потребителей сохраняются. Ветку, нужную только отключённому
FX, не требуется вычислять ради итогового рендера; отдельный запрос превью или
миниатюры может вычислить её независимо. После включения проверяется актуальность
кеша, чтобы изменения, сделанные при отключённом FX, не заменялись устаревшим
результатом.

Это согласованное правило дизайна. Удаление FX или изменение объявления его
портов — отдельные операции; правила отключения не означают молчаливого удаления
оставшихся источников.

### Уточнения Layers и FX перед доработкой SDF

Итог обсуждения 2026-10-12. Сначала дорабатываются SDF/Outline по [F19](SDF_OUTLINE_DESIGN.md).
После этого нужно вернуться к этой модели: обычные FX с SDF-входом могут заменить
часть вложенных эффектных слоёв. Веб-макет показывает взаимодействие строк,
но не реализует Unity-рендер, граф документа или сохранение новой структуры.

#### Поддержанное направление входных секций

- Граф остаётся основной моделью; Layers и Graph редактируют одни связи. Дерево показывает древовидную часть, не ограничивает общий DAG и не клонирует общие источники.
- FX можно прикреплять к узлу как сейчас к слою, без обязательной отдельной видимой ноды для каждого FX. Отдельные ноды для ветвления остаются возможным расширением.
- Секция обозначает конкретный вход слоя или экземпляра FX. Один источник помещается сразу под ней; пользователь не обязан создавать группу ради одной маски. Несколько изображений собираются в изолированную композицию входа. Служебный заголовок сам по себе не является пользовательской группой; вычислительный Stack создаётся только когда нужен.
- У обычного слоя вложенные источники принадлежат обозначенным входам. У группы обычные дочерние строки продолжают собирать её содержимое; дополнительные входы FX показываются отдельно. Позднее обсуждённые эффекторы над/под изображением — ещё одна роль, не разновидность маски и не обычные дети группы.
- Mask в текущем продукте — FX с текстурным входом. Не показывать его в новой модели как необъяснимый универсальный порт любого слоя. Несколько FX/входов различаются по экземпляру и имени порта; ID связи не зависит от номера FX в списке.
- Назначение owned-источника видно по входной секции. Для этого сценария отдельные команды Assign Input / Use in Composition признаны лишними; сами переносы Connect/Disconnect ещё требуют контракта и drop preview.
- Если источник находится в другом месте, заголовок входа показывает выбранный источник и переход к оригиналу, без второй полноценной строки с Name/Alpha/Blend. Одна иконка ссылки у дублирующей строки проблему не решает. Для перемещения настоящей owned-ветки не сохраняется её копия на прежнем месте.
- Self означает вход непосредственно перед данным FX. Пример Noise с Distortion использует свой уже доступный вход, не будущий итог Noise. Ссылки на произвольные стадии другого FX обсуждены, но их набор и UI ещё не утверждены.
- Отключение FX сохраняет секции и связи, приглушает только представление у этого потребителя и не блокирует редактирование. Правило выше остаётся действующим для нескольких портов и общих источников.

Layers должен сохранять компактную таблицу текущего интерфейса: Visibility,
Name, Alpha, Blend; последние три редактируются в строке. Отступ дерева и
миниатюра находятся в Name, остальные колонки остаются выровненными.
Layer Settings — отдельный блок сверху. Служебные строки входов не получают
фиктивных Alpha/Blend. Числовые/цветовые/векторные порты не следует превращать
в несуществующие слои; их компактное представление остаётся предложением.

#### Выбранное правило FX и сценарий эффекторов

Пользователь выбрал: FX родителя обрабатывают его собственное изображение,
а не итоговый пакет с вложенными эффекторами. Outline и SDF читают результат
после этих FX, применяют собственные FX, затем композитятся с родителем.
Чтобы обработать весь пакет, Drawing помещается в обычную изолированную группу
и FX добавляется группе. Два постоянных списка FX «до/после» не требуются.

Сценарий для возвращения к дизайну:

1. Drawing генерирует своё изображение и применяет FX Mask.
2. Outline и SDF получают замаскированное изображение Drawing, не его будущий итог с ними же.
3. Outline создаёт внешний контур под Drawing с заполненным центром, чтобы не вырезать полупрозрачный шов из исходника. SDF с собственным оформлением создаёт Rim Light над Drawing.
4. Результаты собираются в пакет слоя и поступают во внешний Stack.
5. FX внешней изолированной группы обрабатывает этот пакет целиком.

При добавлении через контекстное меню внешнему Outline предлагается задавать
положение снизу и Fill Center, внутреннему — сверху без Fill Center. Это defaults
создания, не пожизненная связь типа контура с положением: ручные настройки
доступны в Properties. Rim Light в примере — оформление SDF, не обязательный
новый тип слоя. Source SDF/Outline по умолчанию наследует собственное обработанное
изображение владельца; лишняя строка для очевидного автоисточника нежелательна.

В модели понадобятся различимые стадии собственного обработанного изображения
и пакета с эффекторами. Их точные port keys ещё не выбраны. Нельзя незаметно
менять смысл исходных `source`/`content` из раздела выше или давать эффекторам
будущий пакет: это создаст цикл. Положение Mapping, Color Range, Alpha, Transform
и clipping относительно этих стадий ещё требует согласования.

#### Перемещение и обычные группы

Направление общего дизайна: reorder меняет композиционный Stack, явные входы
остаются привязаны к стабильным источникам, Previous/AllBelow пересчитываются
по новой позиции. Источник может быть выше потребителя в Layers, если полный
граф вычислений ацикличен. Менять входы всех FX из-за перемещения строки нельзя.

Обычная группа имеет собственный Stack детей и отдельные входные секции своих
FX. Перенос в Stack меняет композицию, перенос в порт означает подключение;
drop preview должен различать эти операции. Предлагается проверять полный
кандидатный граф стадий и отклонять циклический перенос атомарно, одинаково
в UI/API. Не считать защиту от циклов при рендере эквивалентом такого отказа.

Группа эффекторов из элементов над и под Drawing не решена. Обычная
композиционная группа занимает одно место целиком; скрыто раскладывать её детей
по обе стороны родителя нельзя без иной семантики. При промежуточной группе
также нужно выбрать владельца Auto Source: предполагается Drawing, а не результат
самой группы, содержащий этот Outline. Это предложение, не выбранный контракт.

#### Outputs и обтравочные маски

Пользователь хочет выбирать публикуемые выходы в WhimTex, не искать слои
в импортёре. Предложены Create Output в меню, метка у имени и параметры
в Layer Settings. Output хранит собственный ID и endpoint, поэтому не ломается
после rename/reorder и не обязан быть простой галочкой слоя. UI, доступные стадии
и число выходов одного источника ещё согласовать с [F09](WHIMTEX_IMPORTER.md#выходы-документа).

Для clipping предлагается сохранить отдельную связь участников одного Stack,
не превращать её во вход Mask FX. Источник базы выбирается в том же контейнере;
виртуальные заголовки портов не участвуют в поиске базы. Цепочку нужно показывать
компактным признаком и подсветкой, не дополнительной обязательной папкой.
Это предложение; новая семантика с эффекторами не утверждена.

При возвращении проверить: hidden base не подменяется другим видимым слоем;
сирота не начинает свободно рисоваться; перенос одиночного участника показывает
смену базы; перенос всей цепочки сохраняет внутренний порядок; удаление базы
имеет явные последствия. Входной Stack ограничивает собственную цепочку,
внешняя ссылка не становится clipping base. Мягкая альфа применяется без
повторного умножения; coords общей базы и участников согласованы; Undo и
циклический drop атомарны. У группы отдельно определить Pass Through и
изолированный запрос; у Outputs различать собственный результат, clipped result
и всю цепочку. Нынешние правила находятся в [Clipping](../../src/WhimTexDocument.Clipping.cs).

#### Что полезно и что пересмотрено

Полезные основания: одна модель для обоих редакторов, стабильные адреса входов,
прикреплённые FX, изолированные входные ветки без обязательной группы для одного
источника, раздельные стадии собственного изображения/пакета и внешняя группа
для общей обработки. Общий SDF-запрос из F19 может упростить их UI.

Пересмотренные или недостаточные предложения:

- FX родителя по умолчанию поверх всего пакета и второй обязательный стек Source/Result FX заменены выбранным правилом собственного изображения и внешней группы.
- Заголовки Above/Below в макете создают перегруз. Убрать их пользователь попросил рассмотреть, но итоговый вид пока не выбран. Вариант с тонкой чертой, знаками над/под и автопереносом строки недостаточен без правил групп/drag-and-drop.
- Скрытая сортировка рендера при другом видимом порядке вводит в заблуждение. Скрытое изменение размещения/Fill Center после каждого переключения типа Outline тоже не выбрано.
- Дублирующая полноценная строка источника плюс иконка ссылки не решает путаницу. У Mask нельзя молча менять принадлежность с FX на общий вход слоя.
- Blend в раннем макете — условный пример FX с текстурным портом, не добавленная функция продукта. Source — основной вход процессора, не новая группа.
- Сквозная группа не равна текстуре на прозрачном фоне. Наличие FX сейчас временно изолирует её по действующему контракту; это не подтверждает сохранение внешнего смешивания в новой модели. Не менять сохранённый режим молча.

### Что делает перенос

```text
Noise N → Layer A ┐                    Layer A = Noise + свой FX
Drawing D → B    ├→ Stack [A, B] → Output
Noise N → Height → Normal → другой Output
```

После Stack `[B, A]` меняется порядок A/B и результат смешивания. Ссылка Height
на N остаётся прежней. Перенос A не должен менять её на B или на composite.

Команда переноса:

1. Разрешает стабильные ID и позицию, нормализует мультивыделение: родитель и ребёнок не перемещаются повторно; относительный порядок сохраняется.
2. На кандидатной структуре меняет членство/порядок Stack, не мутируя рабочую модель по одному ребру.
3. Пересчитывает контекстные Previous/AllBelow, clipping base, group inheritance и связанные effective values.
4. Проверяет дерево владельцев, типы, ограничения, блокировки и **полный раскрытый граф стадий**, включая texture FX, bindings и условные композиционные зависимости.
5. При успехе одним Undo-коммитом публикует модель, новую Layers projection и invalidation. При ошибке не меняет ничего и сообщает путь цикла/причину.

Например, B читает `A.content`, а A — AllBelow. Перенос A над B замыкает
`A → B → below(A) → A`. Drop запрещён; нельзя автоматически удалить связь B,
переключить A на иной источник или оставить половину переносов.

Удаление слоя из Stack — `DetachLayer`: узел и потребители остаются в Graph.
Удаление самого узла — другая команда с проверкой ссылок. При внешних подписках
UI показывает последствия и предлагает отменить, удалить ссылки явно или
оставить узел вне Layers. Добавление источника в Stack не забирает его выходы
у других потребителей.

Detach слоя с Previous/AllBelow запрещён, пока пользователь явно не заменит
контекстные входы на допустимые explicit sources. Превращение их в ссылки на
нынешний below/previous требует отдельной команды и подтверждения новой семантики;
обычный Detach не делает это молча. Аналогично проверяется contextual Processor.

### Группы и clipping

Isolated group вычисляет дочерний Stack, затем group FX/Mapping/Color Range,
после чего outer opacity/blend применяются в родительском Stack. Group Transform
наследуется детьми; он не применяется к собранному изображению второй раз.
Сохраняется текущая frame-семантика группы, не подмена её bounds всех детей.

Pass Through не эквивалентен изображению группы на прозрачном фоне: его дети
работают с нижней родительской композицией. Компилятор раскрывает его в fold
родителя; opacity и действующие ограничения Mapping/FX учитываются так же,
как сейчас. Нельзя кешировать такой участок только по детям, забыв фон.
Для запроса самостоятельного изображения Pass Through нужен явно обозначенный
изолированный snapshot и предупреждение о другом композиционном контексте.

Backdrop для blending детей Pass Through и область их AllBelow — разные входы.
Сохранение текущего поведения означает: дети смешиваются с родительским backdrop,
но AllBelow дочернего слоя выбирает нижние элементы **дочернего Stack**, не весь
родительский фон. Compiler держит отдельные локальный prefix и inherited backdrop.
Processor/Apply FX используют свои объявленные запросы backdrop, не наследуют
правило AllBelow по совпадению слова «ниже».

Clipping base разрешается из Stack и входит в зависимости результата композиции.
Перемещение одиночного clipped слоя может изменить base, как и сейчас; drop
preview показывает новую связь. Перенос выделенной цепочки сохраняет её порядок.
Mask/coverage и цвет не объединяются без descriptor: группа может иметь разные
семантики этих результатов.

При переносе между группами по умолчанию сохраняется положение в документе:
`newLocal = inverse(newParent) * oldWorld`. Для вырожденной/недопустимой матрицы
команда отклоняется с объяснением. Изменение parent может законно менять blending,
clipping и Local-space FX; сохранение world transform не обещает неизменность
всей картинки. Явный режим сохранения local transform допустим позднее.

## FX как прикреплённые блоки

Поддерживающий FX узел содержит упорядоченные `fxIds`. Properties показывает
тот же список, controls, `@control`, custom editors, Reset и меню групп, что
обычный слой. Новым FX не требуется менять генератор или писать специальные
ветки поведения в LayerBehaviour.

Компилятор раскрывает стек во внутренние стадии:

```text
Source → Placement → Materialize(Document) → FX 1 → FX 2
       → Mapping / Range → content → Stack Blend
```

Эти стадии участвуют в зависимостях, диагностике и кешировании, даже когда
показана одна карточка. В Graph у неё компактный признак FX; `Show FX` раскрывает
визуальные карточки стадий без изменения документа. Сворачиваемый стек не
означает одну GPU-операцию: текущие FX по-прежнему могут требовать отдельные passes.

Параметры FX можно подключать из Graph. На карточке по умолчанию показываются
только подключённые или явно exposed порты; пустые иконки связи возле всех
controls в Properties не добавляются. Stage ID основан на FX ID, не на индексе
в стеке. В MVP не предоставлять внешние подписки на каждую промежуточную текстуру:
сначала достаточно стабильных `source`/`content` узла.

Это исходное ограничение MVP нужно пересмотреть после F19: независимые SDF FX
могут нуждаться в выборе общей предыдущей стадии, например после Mask и до
Outline. Набор доступных стадий и внутренние/внешние подписки ещё не утверждены.

Отдельный Shader FX node допустим для ветвления и повторного использования
результата. Он вызывает тот же evaluator, metadata и diagnostics, а не вторую
реализацию ApplyFX. В нём свой FX instance; общим остаётся определение shader.
Перевод произвольной середины стека в настоящий узел не является просто сменой
UI-флага: он может менять frame, порядок Mapping и сторонние зависимости.
Автоматическое Extract в MVP не включать. Позднее — атомарная команда с явным
переносом параметрических ссылок и проверкой эквивалентности всех выходов.

FX разрешены на Image-producing host, включая групповую границу. На
VectorGeometry/Scene/List сначала требуется явная граница Rasterize; полезные
поздние операции `Map FX` и `FX после сборки` имеют разный смысл и не выбираются
автоматически. UI может предложить создать Rasterize, но показывает добавляемую
операцию до подтверждения. FX не превращает векторный источник тайно в растр.

Нешейдерный Material в нынешнем `Layer.fx` учитывать как явно недетерминированный
Raster stage с внешними зависимостями. Не считать весь текущий список ShaderFX
по предположению. Решение сохранить этот escape hatch или удалить его из нового
контракта требует отдельного согласования.

## Координаты и границы растеризации

Различать Local, Document и View. View — только zoom/pan окна, никогда не единицы
параметров FX. ImageFrame содержит `pixelToDocument`, фактический размер растра,
логические bounds и sampling policy. Transform умножает матрицу: при column
vectors `Mresult = Mnew * Mold`; pivot обрабатывается теми же командами инструмента.

Чистый Transform над Geometry/Scene и свободным ImageFrame может оставаться
отложенным. Компилятор не вправе переносить Transform через неизвестный shader
по догадке, что он «только цветокор». Для existing FX безопасный default —
материализация в Document перед стеком. Оптимизация local/color-only допустима
только по явному контракту evaluator и проверенной эквивалентности.

| Операция | Предлагаемое поведение |
| --- | --- |
| Transform → Transform | Накапливать матрицу, не делать два resample. |
| Transform → color-only → Transform | Color-only может обработать исходный растр с сохранением frame; матрицы продолжают накапливаться. Только у явно поддерживающей это операции. |
| Transform → Edge Outline в Document | Materialize в сетку документа; Thickness измеряется в document pixels, затем ApplyFX. |
| Edge Outline в Local → Transform | Контур относится к локальному изображению и трансформируется вместе с ним. Это художественно другой результат. |
| Transform → Blur в Document | Радиус задаётся в документе; сетка materialization зависит от качества/размера Output, не от zoom UI. |
| Layer FX coordinates | Передавать отдельно inverse layer frame для их Input/Output/handles. Она не меняет единицы всех sample offsets автоматически. |

Материализация фиксирует bounds, origin, density, формат, sampling и border mode,
выдаёт новый ImageFrame с правильной матрицей. Для Canvas она сохраняет текущую
область документа; для свободной ветки — заданный Output/region. Прозрачный Clip,
Clamp, Repeat, Mirror и Source различаются. Unbounded для функции генератора
не равен Repeat растровой текстуры.

Обратная матрица может корректировать offsets отдельных kernel, но не является
общим решением всех FX: нелинейное искажение, min/max, изменение topology и
анизотропия требуют собственного контракта. В MVP использовать явный resample,
а не обещать универсальную компенсацию.

Будущий F07 подключается до источника через UVProgram; Texture FX работает после
материализации через ApplyFX. Shader с двумя функциями вызывается в выбранной
стадии. Наличие общего графа не требует реализовать F07 сейчас.

## Входные параметры и UI подключений

Общий descriptor поля обслуживает обычный control, exposed порт, validation,
agent API и mixed values. Не нужна независимая карта для каждой панели.
Любое **разрешённое descriptor** поле можно expose; ID, пути, дети, GPU-буферы
и служебные состояния не становятся портами произвольным reflection.

В Properties: контекстное действие `Connect / Expose Input`. Не показывать
кнопку-цепочку у каждого несвязанного поля. Связанное поле получает компактный
источник и режим; команда Edit Base меняет сохранённое базовое значение.
Inputs — сворачиваемый список/узел Graph и компактный popup в слоях, не постоянная
широкая панель. Порты, задающие смысловой набор настроек, разрешены наряду с
отдельными полями; descriptor явно объявляет конфликты с компонентными bindings.

Для F02 сохраняются Replace/Multiply/Add:

```text
effective = source                  // Replace
effective = base * source           // Multiply
effective = base + source           // Add
```

Ограничения применяются после разрешения effective value; базовое значение не
перезаписывается. Bool и строго типизированный enum допускают только Replace;
нечисловая арифметика не угадывается. Для неподдерживаемой/потерянной связи
показывается ошибка поля с base fallback, а строгий Bake не выдаёт это за успех.
Схема гарантирует один активный binding на компонент и диагностирует пересечение
compound-порта с отдельными компонентами.

При Error разрешён только явно помеченный diagnostic preview с fallback;
он не считается успешным новым результатом и не попадает в обычный reusable
output cache. Shader Apply (компиляция кода) может отдельно завершиться успешно,
но destructive Apply to pixels/Bake зависимых Outputs блокируется до исправления
binding. Независимые Outputs продолжают работать. Save Data Only сохраняет
модель и диагноз без выдачи fallback за актуальные запечённые пиксели.

Shader inputs могут читать объявленные входы документа через resolver F02:
явная декларация → Input ID → uniform. Не публиковать любой Input как глобальную
переменную и не переопределять Unity `_Time`. Наименование `@input`/uniforms ещё
не закреплено; MVP может обойтись обычной привязкой `@param`. Пользовательский
HLSL компилируется при изменении исходника/структуры, не при изменении Time.

Мультиредактирование сравнивает совместимые descriptors, base values и bindings
отдельно. Разные типы Noise показывают пересечение доступных полей. Random Seed
и Random All исполняются независимо для каждого экземпляра, одной транзакцией;
Seed остаётся сохранённым числом, не скрыто обновляемым при Play. Для связанных
полей Random меняет base с явной подсказкой, если Replace скрывает результат.

## Выполнение повторений и веток

План вычисляет только зависимости запрошенных Outputs. Вход провода — ссылка
на producer, scalar/lazy source либо готовый ресурс по объявленному типу.
Генерация Raster Noise и растровый FX по умолчанию остаются GPU-проходами.
Это не CPU-вызов функции на каждый пиксель из UI и не обязательный shader fusion.

Repeat — структурированный вызов подграфа с LoopContext, а не обратное ребро:

```text
Circle(radius = base + index * step)
    → Transform(position = loop.position)
    → Repeat(count, placement) → List<VectorGeometry> → Scene → Rasterize
```

LoopContext хранит iteration index, count, необязательный placement/position и
путь вложенных вызовов. Индекс целочисленный; nested loop читается через явно
выбранный уровень. Случайность вычисляется из сохранённого Seed + стабильного
пути instance/loop + выбранного random stream, не из часов или порядка jobs.
Одна и та же ветка при том же контексте воспроизводима. Placement применяется
однократно: descriptor отмечает, выдаёт ли ветка local content либо уже positioned
result. Иначе легко получить двойной Transform.

Ветка, не использующая index/position, может разделить вычисленную геометрию между
копиями; ветка с `radius(index)` вычисляется для каждого контекста. Это определяется
descriptor/context dependencies, а не поиском слова в пользовательском HLSL.
Материализация списка в RT происходит только на явной границе. Repeat над
изображениями может требовать больше ресурсов, чем повтор геометрии; cost preview
показывает count, ожидаемые размеры и лимит, а не обещает одинаковую цену.

Общие циклы запрещены. Итерационные numerical algorithms и stateful particles —
отдельные исполнители с ограниченным числом шагов/явной историей, не разрешение
произвольных обратных проводов. Проигрывание Time и Bake используют неизменяемый
EvaluationContext, не меняют saved fields и не создают Undo каждого кадра.

## План, кеш и владение ресурсами

Порядок подготовки: validate → resolve descriptors/links → expand Stack/FX/loops
→ build stage dependencies → topological plan → execute requested roots.
Нужно проверять раскрытые зависимости стадий, а не только видимые карточки:
group frame для детей зависит от transform values группы, не от её готового
изображения. Это не цикл `group image → child image → group image`.
В MVP Image → Number readback не допускается; позднее он должен участвовать
в той же проверке реальных data dependencies.

EvaluationContext: Input snapshot/overrides, document size, requested region,
quality, Output ID, время/кадр, working precision, cancellation и path вызова.
UI viewport не является общим stamp документа; если stage действительно использует
viewport для интерактивного качества, это объявленная отдельная зависимость.

Output ID нужен маршрутизации запроса, но не автоматически входит в ключ каждой
стадии. Если size/quality/region и прочие используемые входы совпадают, два Outputs
разделяют upstream кеш; output-specific encoding — уже отдельная downstream stage.

Ключ кеша включает type/schema/code/include revisions, settings revision,
stamps реально использованных входов и нужную часть EvaluationContext. Structural
revision пересобирает план; value revision инвалидирует downstream. Переименование
узла/движение карточки не инвалидирует shader output. Поиск reflection, JSON
serialization и построение схемы выполняются при изменении структуры, не на
каждый stamp/каждый кадр. Dependency masks объединяются с зависимостями FX.

Cached result неизменяем; consumers получают lease. Cache entry удерживает
собственную owning reference, preview также удерживает lease. RT pool учитывает
allocation-совместимость размера/формата; новый владелец отдельно инициализирует
frame, sampling и содержимое, не получает старые атрибуты как semantic результат.
RT возвращается в pool только после удаления cache entry **и** освобождения
всех leases; uncached intermediate — после последнего потребителя. Eviction
удаляет запись, но не освобождает leased RT до завершения потребителей.
Copy-on-write используется для редактируемых Drawing/геометрии; GPU uploads,
Material/CommandBuffer и Unity object lifetime остаются main-thread границей.
Data-only подготовку допустимо вынести в portable Jobs/Burst после измерения.

Не сохранять RT для каждой ноды навсегда. Кешировать дорогие/повторно используемые
стадии по общему бюджету; дешёвые значения и chain intermediates могут жить до
последнего потребителя. Outputs одного запроса разделяют общие стадии. Export
с повышенным разрешением получает отдельный вариант, не портит editor preview.

Unity time uniforms и произвольный Material сохраняют warning/non-cacheable
политику: такой shader разрешён, но недетерминированность видна в UI и API.
При Bake контекст входов фиксируется, однако Unity time нельзя выдавать за
воспроизводимый вход документа. Строгий deterministic Bake отдельно решает,
отклонять ли такой источник; обычный Apply не блокируется warning.

Automatic и On Refresh из F04 остаются будущей политикой стадии: dirty/stale
не означает автоматически пересчитать On Refresh при каждом Preview/Save.
Граница замороженного результата и сохранение snapshot должны согласовываться
с F04; graph cache сам по себе не является этой функцией.

Отменённый или устаревший запрос не публикует результат. Авария освобождает все
leases и временный render state; последний успешный preview остаётся видимым
с явным stale/error статусом, но не сохраняется как успешный новый Bake.

## Команды, Undo и общая диагностика

### Модули первого технического среза

Названия и границы предлагаемые; таблица определяет ответственность, не требует
создавать отдельный файл/assembly для каждой строки.

| Модуль | Вход → выход | Ограничение |
| --- | --- | --- |
| GraphNodeRegistry / descriptors | typeKey + schema → typed ports/settings/capabilities. | Один registry для UI, validation, evaluator и JSON; не выполняет документный код. |
| GraphValidator | Кандидат модели + schema → diagnostics/dependency paths. | Без GPU и mutations; включает Stack/FX/binding dependencies. |
| GraphCompiler | Valid model revision + request shape → immutable stage plan. | Разрешает contextual inputs и формирует lifetimes; shader compilation отдельна. |
| GraphEvaluator | Plan + EvaluationContext → Output leases + result status. | Unity GPU-работа на main thread; результат публикуется только для актуальной revision. |
| GraphResourceStore / cache | Owned data + stage stamps → immutable handles/leases. | Считает pool, cache и ещё leased retired entries в одном memory budget. |
| LayerProjectionBuilder | Graph + выбранный Stack → readonly layer rows. | Не хранит вторую authoritative иерархию; редактирование вызывает команды. |
| GraphEditorAdapter | Model snapshot + selection → node/port/wire views. | View не исполняет nodes и не меняет модель из draw callbacks. |
| GraphPersistence | Модель + resource table + prepared snapshots → container/JSON. | Не запускает importer внутри Save; roundtrip и atomic candidate commit. |

Stage plan хранит producer slots, dependency masks, evaluator key, parameter
addresses, output frame contracts и lifetime counts. Сами scalar values приходят
из EvaluationContext/effective settings; они не встраиваются в новый HLSL каждый
кадр. Исполнитель стадии получает read-only input handles и отдельный writable
output lease либо возвращает разделяемое immutable значение. Нельзя передать
cached input как writable output без явного copy-on-write.

Существующие LayerBehaviour и ShaderFX сначала подключаются через adapters к
этому плану. Один RenderRequest используется composite/group/Target/clipping,
thumbnail/export, но descriptor сохраняет разные смыслы их входов, а не сводит
их к одинаковому texture вызову. После проверки можно заменить старые обходы;
не держать два независимых cache/invalidation механизма после завершения перехода.

Если memory budget занят leased результатами и новый запрос не помещается,
исполнитель выдаёт `resource_limit` с оценкой требуемой памяти. Interactive
request может явно предложить lower quality; Final не снижает его молча и не
перезаписывает leased RT ради продолжения. Pixel/graph/recursion/Repeat limits
валидируются до выделения; на срезе использовать действующие DocumentLimits
и дополнить их измеренными graph-specific пределами.

### Транзакции и сообщения

Один DocumentGraphService обслуживает Layers, Graph, Properties и agent API.
Команда готовит кандидат, валидирует, формирует Undo и change set; editor UI не
пишет прямо в ports/Stack в обход сервиса. Batch является одной атомарной
транзакцией, `dryRun` не компилирует и не изменяет ресурсы. Если проверка требует
shader compilation, это отдельный явно обозначенный этап, не успешный dryRun.

Минимальный набор будущих команд: CreateNode, SetValue, Connect, Disconnect,
MoveLayer, AttachToStack, DetachLayer, DeleteNode, Add/Move/RemoveFX, SetBinding,
CreateOutput и SetOutputSource. API возвращает созданные ID и revision;
`whimtex_*` остаётся продуктовой convention. Имена новых CLI-команд не закреплены.

Undo владеет сохранённой моделью, FX values и изменёнными документными ресурсами;
он не записывает кеш и pool. Один drag — одна запись. После Undo план и Layers
projection восстанавливаются из модели, никакой синхронизации двух Undo-стеков.
Редактирование Drawing по ссылкам выбирает ресурс явно: shared edit влияет на
все его instance, `Make Unique` создаёт новый ресурс по запросу. Инструменты
рисования не пишут в вычисленный результат procedural node.

Live locks защищают узлы/ресурсы/FX и зависящие от перестановки stages, а не только
старый индекс слоя. Revision check выполняется при коммите. Агент не может
переставить чужую заблокированную ветку через изменение Stack «с другой стороны».

Расширить существующий механизм диагностики, не создавать отдельные строки
ошибок для Graph и Layers. Общая запись: code, severity, message, node/FX/field
адрес, source location, dependency path, revision и suggested action. UI,
agent API и Console получают одинаковые severity/message. Console дедуплицирует
по субъекту, содержанию и версии причины; повторный repaint/неизменный запрос
не печатает warning заново. После исправления диагноз исчезает; новая причина
с тем же полем может быть сообщена снова. Только Error блокирует соответствующий
успешный результат/Bake; явно помеченный diagnostic preview может показать
fallback по описанному выше правилу. Warning не становится ошибкой Apply.

## TIFF, JSON, Outputs и импорт

Для нового формата сохранять graph, Inputs, Outputs, FX instances и resource
table, а не одновременно старое дерево слоёв и его графовую копию. Layout
карточек можно сохранять в отдельном editor metadata; UI zoom, hover, selection
и текущий preview не влияют на semantic content hash. Явные Outputs определяют
предназначенные для Save/import результаты.

Пример состава модели, не готовая схема JSON и не текущий контракт:

```text
document
  schemaVersion
  canvas
  graph: nodes + connections / input selections
  inputs
  outputs: outputId → endpoint + render settings
  fxInstances
  resources: resourceId → container block | external reference
  editorMetadata: layout
```

Дублировать connection одновременно отдельным edge и записью входа не нужно:
рекомендуется одна сохранённая input selection, а UI edges строятся из неё.
Stack order хранится только в Stack settings. TIFF несёт ту же модель, блоки
владеемых Drawing/vector resources и запечённый primary Output. Для остальных
подготовленных Outputs предлагаются отдельные контейнерные pixel blocks и manifest:
Output ID, block ID, render settings, dependency/Input snapshot stamp, encoding,
precision и stale state. Importer не получает произвольный Output только из
primary TIFF pixels.

Рекомендация для F09: Save candidate обновляет статические Outputs, явно
отмеченные для сохранения/импорта, одним планом и атомарно принимает модель
со всеми их пикселями. Animation Sheet — отдельный Bake. Будущий On Refresh
не пересчитывается неявно; manifest указывает фактически использованный frozen
result и stale состояние. При ошибке доступен Save Data Only: прежние snapshots
сохраняются как stale, не маркируются актуальными и не импортируются молча как
новый результат. Политику использования stale/frozen outputs выбрать с F04/F09.
Изменение FX source во время Save/Bake не смешивает версии в одном snapshot.

JSON сохраняет те же узлы и resource table без Unity instance IDs. Для полного
document roundtrip собственные пиксели обязаны присутствовать: inline typed
binary payload либо явно связанный portable resource bundle с проверяемыми
размером/форматом/hash. Пути project assets и GUID остаются внешними ссылками,
не изображают встроенный ресурс. Существующее опускание Drawing pixels при
экспорте recipe нельзя считать complete document export. Новый API различает
complete document и recipe с отсутствующими ресурсами; незавершённый recipe
не открывается как успешно восстановленный документ. Конкретный payload encoding
и limits входят в согласование схемы перед реализацией.

До реализации выбрать новую schema version отдельно от версии UPM-пакета.
Не менять версии сейчас. Старый формат можно явно отвергать без aliases и
автоматической миграции; это не разрешение перезаписать пользовательский файл.
Текущий-format roundtrip, resource ownership, резервный исходник FX и atomic Save
остаются обязательными.

Unknown node/порт/FX сохраняет opaque payload и диагностируемый unresolved link
при lossless roundtrip поддерживаемого контейнера. Он не выполняется как иной
узел. Частично открытый документ нельзя успешно запекать с молча пропущенными
узлами; Save original data и Bake имеют разные проверки. Неподдерживаемая версия
всего контейнера открывается только в явно поддержанном read-only/recovery режиме
либо отклоняется, не обещается произвольная forward compatibility.

Copy/paste создаёт новые node/FX/resource IDs там, где создаются независимые
объекты; внутренние ссылки remap единым списком. Внешние ссылки на Inputs и
ресурсы другого документа требуют import/remap/fallback выбора, не совпадения
имён. Definition ID пресета F14 не заменяет instance ID. Удаление Output не
удаляет общий источник без отдельной операции.

F09 импортирует подготовленные pixels по Output ID; F10 использует несколько
Outputs одного плана. Выбранный Canvas preview не меняет primary Output.
Sprite/atlas generation F06 выполняется после Bake кадров с закреплёнными
Input/Time/source snapshots. Importer не обязан запускать живой editor graph
или GPU в AssetImportWorker. Пользовательский C# из документа не выполняется.

## Интерфейс и редакторские инструменты

Layers, Graph и Properties могут открываться в одной рабочей области; Graph
не обязан постоянно занимать место Canvas. Выделение имеет ID и editor-local
state, а Properties использует общие descriptors. Связанный слой выделяет
соответствующий узел; utility node показывает свои properties без фиктивной
композиционной строки, но может быть виден как источник раскрытого входа.
Для нескольких placements общего источника Canvas выбирает
конкретный LayerNode/instance path, не случайного потребителя.

Node card: заголовок, тип, exposed/connected ports, короткий FX-признак и статус.
Узлы Stack можно показывать компактной ordered-группой. Source/FX expansion и
группировка карточек — layout, пока команда явно не создаёт subgraph. Соединение
показывает тип; inline type conversion имеет видимую запись в модели. Drop
preview для Layers показывает меняющиеся контекстные зависимости и ошибки.

Редактор строится на публичных VisualElement, Painter2D для wires и переиспользуемых
PointerManipulator. Model mutation не выполняется из generateVisualContent.
Capture/cancel/Detach завершают drag без потерянной блокировки и лишнего Undo.
Node views и hit-test ограничиваются viewport, wire geometry кешируется.
Не делать внутренних GraphView API или новых версий Graph UI обязательной
зависимостью для Unity 6.0. Такой UI-adapter можно заменить без изменения файла.

Canvas Transform, Text, Gradient и временные handles остаются инструментами
редактирования соответствующих данных узла. Векторные handles описаны в F08.
Выделение render instance отличается от редактирования общего source. Guides
сохраняют наименьший hit/draw priority; graph editor не меняет эту договорённость.

## Этапы реализации и критерии приёмки

| Этап | Состав | Условие завершения |
| --- | --- | --- |
| 0 — вертикальный технический срез | Два источника, Stack, один FX со вторым texture input, два Outputs, порт Number, перемещение слоя. Без переписывания всех типов. | Один сервис для Layers/Graph/API; атомарное отклонение цикла; общий источник вычисляется один раз на контекст; существующий render результат сохранён. |
| 1 — растровая модель | Перенос текущих behaviours, group/Target/Processor/clipping, прикреплённые FX, Input bindings, Undo, TIFF/JSON. | Проверены все действующие пути рендера, roundtrip, paint/resource ownership и аварийный Save. Только после этого заменять основной editor path. |
| 2 — пользовательский Graph и Layers | Canvas графа, exposed ports, вложенные входные ветки в Layers, branch preview, Inputs popup, несколько Outputs. | Оба редактора меняют один граф; группировка входов не создаёт копий источников или внешнего наложения; preview не меняет импортируемый Output; нет пустых chain-кнопок на каждом поле. |
| 3 — вектор и Repeat | Геометрическая модель/Canvas tools, Transform, Lists, Rasterize и SDF по F08. | Круг с параметром index даёт разные копии без промежуточного растра; source/instance selection и bounds корректны. |
| 4 — расширения | UV/PixelProgram, анимация/Bake, On Refresh, custom FX editors, сложные strokes. | Каждый контракт согласован отдельно; нет автоматического обещания реализации всех карточек беклога. |

Срез 0 — предлагаемое начало самого F18 после одобрения дизайна и возвращения
к графу по результатам F19. Это не ближайшая задача: пользователь выбрал сначала
SDF/Outline. Создание экспериментального asset/окна и изменение формата документа
сейчас не поручены.

При реализации нужны целевые сценарии, а не тысяча тестов после каждого control:

- Explicit source/FX texture link не меняется после reorder; Previous/AllBelow меняется ожидаемо; цикл отклоняется без partial commit, в UI/API одинаковая причина.
- Вложенные группы основного входа, маски и FX texture input адресуют разные порты; reorder FX сохраняет принадлежность input-ветки; Layers/Graph показывают одну связь. Shared source, disconnect и отказ циклического drop не создают копий/частичного изменения.
- Отключение FX сохраняет входные секции и connections, приглушает только их представление у данного потребителя и не блокирует редактирование. Включение, Undo/Redo и current-format roundtrip сохраняют ветки; изменения при отключении учитываются после включения. Общий источник продолжает работать для других активных потребителей.
- Multi-move, self-parent, detach, delete с external consumers, duplicate и copy между документами; Undo/Redo восстанавливают ID и порядок.
- Isolated/Pass Through, clipping, отключённый Processor, hidden Target, group alpha/color и reparent с nonuniform/projective/singular transform.
- Transform → spatial FX → Transform в Document и Local; 90°/неравномерный scale; Thickness не зависит от zoom; Clip/Repeat и borders без UV clamp сюрприза.
- Прикреплённый FX и отдельный FX node совпадают при одинаковом frame/pipeline; Reset и Random сохраняют базовые данные/Undo и действуют по экземплярам.
- Несколько Outputs используют общий upstream, output scale разделяет кеш; rename/layout не запускает перерасчёт; устаревший job не публикуется.
- Nested Repeat, нулевой/предельный count, deterministic Seed, ветка с/без index dependency, budgets и cancel.
- Signed/HDR и data maps без скрытого clamp/sRGB; alpha representation совпадает на всех границах; preview, thumbnails, PSD/export и import выбирают одинаковый RenderRequest.
- Unsupported format, unknown node, missing preset/include/resource, повреждённый блок, atomic Save, current TIFF/JSON roundtrip; warnings не спамят.
