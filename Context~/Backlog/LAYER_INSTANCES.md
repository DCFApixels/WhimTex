# F27. Экземпляры слоёв и Instance Index

- Назначение: повторять слой несколькими экземплярами и получать воспроизводимые различия через индекс каждого экземпляра.
- Статус: требование пользователя записано 2026-10-17 в беклог. Механизм создания экземпляров, UI и точный контракт ещё не утверждены; реализации нет.
- Источники истины: запрос пользователя; предложения [повторений и контекста F18](NODE_GRAPH_DESIGN.md#выполнение-повторений-и-веток), [времени F06](ANIMATION_DESIGN.md), [параметров документа F02](DOCUMENT_PARAMETERS.md). Это будущая возможность, не описание текущей реализации.

## Требование пользователя

- Система времени для создания анимаций остаётся отдельным направлением
  [F06](ANIMATION_DESIGN.md).
- Нужен механизм повторения слоя несколькими экземплярами, помимо обычного
  ручного дублирования Ctrl+C / Ctrl+V.
- Каждому экземпляру назначается собственный Instance Index.
- Эффекты и другие вычисления с Seed или рандомизацией могут использовать этот
  индекс для подмешивания в Seed, чтобы у повторов получались разные результаты.
- Индекс должен быть доступен вычислениям экземпляра, а не только подписью в UI.

## Предложенная модель

Предусмотреть общий контекст экземпляра и передавать его генераторам, слоям и FX
соответствующей ветки. Это развитие уже предложенного Repeat/LoopContext из F18,
а не вторая независимая модель повторений. Наличие этой связи не поручает
реализовывать весь граф для первого прототипа экземпляров.

Технический кандидат: вычислять effective Seed из сохранённого базового Seed,
индекса/пути экземпляра и идентификатора потока случайности. Конкретный способ
смешивания ещё выбрать. Сохранённый Seed источника при этом не переписывается;
разные FX могут сохранять собственные базовые Seed и использовать общий индекс.

Пример: один слой шума с FX повторяется 10 раз. При включённом использовании
Instance Index повторы получают разные варианты шума и эффектов; изменение
базового Seed меняет набор вариантов воспроизводимо. Без использования индекса
одинаковые входы могут давать одинаковые результаты у всех повторов.

Индекс экземпляра — не Unity instance/entity ID и не случайное число, создаваемое
на каждой перерисовке. При одинаковых сохранённых входах и контексте повторный
расчёт, preview и экспорт должны давать согласованные вариации. Анимация времени
сама по себе не меняет индекс и не запускает скрытую перерандомизацию.

## Дополнительные идеи пользователя: общие входы и оптимизация

Уточнение от 2026-10-17. Следующие пункты сохранены как идеи для проектирования,
а не утверждённый контракт или поручение на реализацию.

- **Time и Instance Index доступны и свойствам слоя, и его FX.** Их использование
  не ограничивается Seed: значения могут участвовать в вычислении других
  параметров. Для FX нужен общий механизм входных параметров, через который
  эффекты смогут считывать время и индекс текущего экземпляра. Имена параметров,
  способ объявления/привязки и интерфейс HLSL ещё выбрать; связать это с F02/F06/F18.
- **Определять зависимость от Instance Index.** Нужна система, которая понимает,
  запрашивают ли индекс сам слой, его свойства или хотя бы один из его FX.
  Предусмотреть учёт косвенных зависимостей через привязки и входы; точный механизм
  определения пока не выбран. Само наличие доступного входа не равно его запросу.
- **Быстрый путь для независимых повторов.** Если слой вместе со всей его цепочкой
  FX не использует Instance Index и остальные влияющие входы одинаковы, достаточно
  получить его текстуру один раз и повторно использовать/копировать её для
  экземпляров, без новой генерации слоя и повторного выполнения тех же FX.
  Размещение экземпляров выполняется отдельно, если оно не влияет на сами пиксели.
- **Зависимый путь.** Если индекс нужен слою или FX, рассчитывать соответствующий
  результат в контексте экземпляра. При проработке можно также оценить частичное
  переиспользование: общий источник слоя, но отдельный FX, использующий индекс.
- **Время учитывать отдельно.** Независимый от индекса анимированный слой всё ещё
  может разделять одну текстуру между экземплярами при одинаковом Time. Изменение
  времени обновляет общий результат, если он зависит от Time; независимость от
  Instance Index не означает бессрочную валидность кеша.

## Что согласовать при реализации

- Как создаются и размещаются экземпляры: Repeat, отдельный тип слоя или другой
  интерфейс; как управляются количество, трансформы и порядок композиции.
- Какие параметры общие с источником, какие задаются для экземпляра; как работает
  редактирование источника и превращение экземпляра в независимую копию.
- Нумерация и стабильность индексов при добавлении, удалении, перестановке и Undo;
  индекс не обязан служить постоянным идентификатором самого объекта.
- Вложенные повторы: путь/уровень экземпляра и выбор контекста для конкретного FX.
- Подключение индекса к Seed: явная настройка, привязка параметра или доступ из
  HLSL; не навязывать вариации всем эффектам без выбора пользователя.
- Учитывать зависимости от времени/индекса в кеше; повтор, который не использует
  индекс, может переиспользовать общий результат, а зависимый от него должен
  рассчитываться в соответствующем контексте.
- Сериализация, Undo/Redo, агентский API и совпадение preview/export; лимиты
  количества экземпляров и стоимости расчёта.

Сейчас сохранены требования и технические кандидаты. Реализация, проверки,
сроки и приоритет относительно других направлений не назначены.
