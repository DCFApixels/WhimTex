# F02. Параметры документа и привязки полей

- Назначение: управлять связанными настройками разных слоёв и FX из одного списка параметров документа.
- Статус: обсуждено; требование сохранить в дизайне модели данных, без окончательного контракта.
- Источники истины: требования пользователя, сохранённые здесь 2026-10-08; текущие [Layer](../../src/Layers/Layer.cs), [FX и их параметры](../../src/ShaderFX.cs), [JSON](../../Documentation~/JSON_FORMAT.md), [TIFF](../../Documentation~/TIFF_FORMAT.md).

## Требования из обсуждения

Пользователь создаёт список параметров документа. Поле слоя или FX можно связать
с параметром как минимум в трёх режимах:

| Режим | Смысл |
| --- | --- |
| Replace | Параметр полностью заменяет значение поля. |
| Multiply | Значение поля умножается на параметр. |
| Add | Параметр прибавляется к значению поля. |

Названия режимов здесь рабочие, окончательный UI и имена сериализованных полей
не выбраны. Это не ручные декларации FX: действующие FX-параметры по-прежнему
объявляются через `@param`.

## Что нужно определить

- Типы параметров, допустимые поля и совместимость скаляров, векторов, цветов и остальных значений. Поддержка арифметики для enum/texture/transform не согласована.
- Где хранить базовое значение и связь; когда вычислять эффективное значение без перезаписи исходных данных.
- UI списка и подключения поля, переименование/удаление параметра, диагностика потерянной ссылки.
- Undo, зависимости кеша, сохранение и текущий TIFF/JSON roundtrip.
- Copy/paste слоёв между документами и политика ID/ссылок.
- Совместная работа с [F01](MULTI_EDITING.md): mixed values для разных связей и смысл группового изменения.

## Следующий шаг

При возвращении к задаче сначала выбрать минимальный набор типов и показать
один связанный параметр на слое и один на FX. Решение о новой модели Layer/SO
должно учитывать хранение связей; внедрять всю систему в рамках рефакторинга
мультиредактирования автоматически не нужно.

## Связь с анимацией и наборами текстур

Дополнение обсуждения 2026-10-09: пользователь предлагает управлять анимацией
через параметр документа, например `Time`, к которому привязываются поля слоёв
и FX. В [F06](ANIMATION_DESIGN.md#спрайтовая-анимация-и-animation-sheet)
предложено явно назначать параметру роль времени таймлайна, не распознавать её
по имени. Связь должна переживать переименование параметра.

Вычисленные значения для текущего кадра отделены от сохранённых базовых значений.
Таймлайн и возможный шейдерный вход управляемого времени используют один контекст
расчёта, не два независимых счётчика. Проигрывание не создаёт Undo и не меняет
сериализованные поля каждый кадр. Роль времени, единицы и допустимые привязки
пока требуют выбора.

Для [F10](TEXTURE_SETS.md) один параметр может одновременно управлять связанными
ветками Albedo, Normal, Roughness и остальных карт. Это использование общих
привязок F02, а не отдельная система параметров для каждого выхода.
