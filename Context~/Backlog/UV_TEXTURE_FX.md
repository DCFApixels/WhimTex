# F07. Разделение UV FX и Texture FX

- Назначение: отделить изменение координат процедурного источника от обработки уже рассчитанного изображения.
- Статус: отложено пользователем; обсуждение переключилось на режимы Tiling, которые не нужно заново включать в очередь.
- Источники истины: обсуждение пользователя, сохранённое здесь 2026-10-08; текущие [FX-контракт](../../Documentation~/ShaderFX.md), [ShaderFXSourceBuilder](../../src/ShaderFXSourceBuilder.cs), [Layer](../../src/Layers/Layer.cs), [Noise](../../src/Layers/NoiseLayerBehaviour.cs).

## Предложенная модель

1. В разделе UV FX последовательно вычисляются координаты через `ApplyUV`.
2. Итоговые координаты поступают генератору слоя, например Noise.
3. Раздел Texture FX обрабатывает полученное изображение через `ApplyFX`.

Один шейдер может реализовывать обе функции. Блок в UV FX вызывает только
ApplyUV, блок в Texture FX только ApplyFX. Перетаскивание между разделами
служит переключением режима использования, а не обязательным вызовом обеих функций.

Цель обсуждения: дать процедурным источникам возможность вычисления по
координатам вне исходного растра. Обычный выбор Clamp/Repeat/Mirror/Clip для
готового изображения решает другую задачу и не заменяет такой конвейер.

## Что ещё не решено

- Контракт входов/выходов ApplyUV, порядок преобразований и система координат.
- Какие слои имеют процедурный источник для такого пути; что означает UV FX для Drawing, File, группы и Processor.
- Поведение шейдера, реализующего только одну функцию, при перетаскивании.
- Взаимодействие с Transform, Input/Output, Target, выборками других слоёв и Tiling.
- Сериализация двух списков, агентские операции, кеш и диагностика неподдерживаемого режима.
- Семантика Unbounded и её пределы: разделение функций ещё не гарантирует непрерывный источник у любого слоя.
