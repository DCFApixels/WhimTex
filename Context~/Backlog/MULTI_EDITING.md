# F01. Мультиредактирование Layer Settings и FX

- Назначение: редактировать несколько выбранных слоёв без последовательного повторения одинаковых действий.
- Статус: обсуждено; окончательная модель данных и способ интеграции не закреплены.
- Источники истины: требования пользователя, сохранённые здесь 2026-10-08; текущие [Layer](../../src/Layers/Layer.cs), [ShaderFX](../../src/ShaderFX.cs), [Layer Settings](../../src/WhimTexUI.cs), [Rendering](../../src/LayerRenderingSettingsView.cs), [FX-параметры](../../src/Editor/ShaderFXParameterView.cs).

## Требования из обсуждения

- Показывать смешанное значение, если выбранные объекты отличаются; изменение поля применять ко всем подходящим объектам.
- При разных типах слоя или режимах показывать общие применимые поля, скрывать не общие. Например, Perlin и White Noise не должны выводить взаимоисключающие блоки настроек как общий блок.
- Random Seed, Random All и другие кнопки с логикой изменения выполнять независимо для каждого объекта. Нельзя вычислить одно случайное значение и скопировать его всем выбранным слоям.
- Поддержать мультиредактирование FX с теми же принципами, Undo и сохранением документа.
- Переиспользовать описание параметров и условия их видимости; не заводить отдельную ручную карту соответствий для каждого режима без необходимости.

## Обсуждавшаяся основа

`WhimTexDocument` уже является SO-моделью в памяти, но `Layer` сейчас сериализуемый
класс, не отдельный ScriptableObject. `ShaderFX` является ScriptableObject;
список FX принадлежит слою. Поэтому наличие SO у документа само по себе не даёт
мультиредактирование внутренних слоёв через `hasMultipleDifferentValues`.

Обсуждались `SerializedObject`/`SerializedProperty`, привязка полей и перенос
Layer и/или LayerBehaviour в SO. Layer SO исследовался как прототип;
интегрированная новая модель этим обсуждением не утверждена. Перед продолжением
нужно найти результаты прототипа либо повторить ограниченную проверку, не считать
его готовой частью продукта.

Для FX нужно определить соответствие самих блоков и параметров. Сравнение по
индексу обсуждалось для блоков одного шейдера с одинаковыми декларациями;
не закреплено правило сопоставлять любые выбранные FX по одному индексу.

## Что решить перед изменением кода

- Какие поля действительно можно обслужить общим SerializedProperty, а где нужен собственный механизм для динамических FX-параметров.
- Владение SO, жизненный цикл, Undo, сериализация TIFF/JSON и замена поведения слоя без потери оболочки/ID.
- Как рассчитывать пересечение видимых полей, когда управляющий enum сам имеет mixed value.
- Как сопоставлять FX при разном количестве, порядке, пресете или ревизии кода.
- Как показывать базовое значение и будущую привязку к параметру документа при мультивыделении: см. [F02](DOCUMENT_PARAMETERS.md).

## Проверка результата при реализации

Одинаковые и смешанные значения; разные типы Noise; независимая рандомизация;
Undo/Redo; изменение и перезагрузка FX-деклараций; текущий TIFF/JSON roundtrip.
Проверять встроенную панель и отдельное окно Layer Settings. Создание карточки
не разрешает создавать новые Unity-ассеты или запускать весь набор тестов.
