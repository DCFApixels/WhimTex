# T05. Кандидаты для дисперсии Caustics

- Статус: для обычной Caustics выбран CIE/D65 на шести полосах. Кайма из Value с насыщенностью ×2 и растяжение пятен остались экспериментами.
- Объём: цветовой выход обычной Caustics на входной карте Height.
- Контекст: [контракт Caustics](../../Documentation~/ShaderLayer.md#caustics-nodes), [накопление света](../../src/ShaderProgramRuntime.Caustics.cs), [источник длин волн](../../ThirdPartyNotices.md#spectral-caustics-weights).

## CIE/D65

В Unity использованы те же шесть проекций, что и у текущей ноды. Сравнивались
стандартный Spectrum с White Balance и веса CIE 1931 под D65. Разрешение 384×384,
свет сверху, `Dispersion = 0.6`, `Softness = 1`, `Strength = 0.06`, `Intensity = 0.12`.
Карта высот `sin(2πx) + cos(2πy) + 0.5 sin(4π(x+y))`.
Экспозиция и тональная кривая одинаковые. Отрицательные RGB-компоненты CIE
сохранялись при накоплении. Если после сложения оставались отрицательные каналы,
перед тональной кривой превью снижало насыщенность с сохранением яркости.

При `Depth = 1`, `IOR = 1.333` у CIE/D65 более насыщенная сине-зелёная кайма.
Тёплый оттенок внутри светлых полос частично сохранился. При `Depth = 0.1` или
`IOR = 1.03` на этой поверхности оба результата почти серые. Накопленные
вклады отдельных полос воспроизводят текущий Spectrum с максимальной абсолютной
ошибкой около `3.2e-6` в линейном RGB.

Картинка, параметры и временный скрипт сравнения находятся в
`Temp/WhimTex/DispersionResearch/` под именами `cie-d65-comparison.png`,
`cie-d65-comparison.txt` и `CieD65Comparison.cs`.

В ноде шесть весов заранее переведены из XYZ в линейный RGB. Знаковые вклады
накапливаются в существующем float-буфере. При выборке из него отрицательные
каналы убираются с сохранением яркости. CIE/D65 применяется, когда у Spectrum
нет градиента. Режим Custom и подключённый градиент используют свои веса.

## Кайма из Value с насыщенностью ×2

Одна проекция Value даёт монохромную карту. Для каймы используются шесть
смещённых выборок этой карты с весами CIE/D65. Смещение направлено поперёк
локальной границы яркости. Маска по градиенту концентрирует цвет на краях.
Цветность усиливается вдвое относительно серого с яркостью исходного Value.

Пользователь выбрал насыщенность ×2 при исходной ширине из сравнения с базовым
вариантом и удвоенным смещением. Параметры прежние, максимальное смещение
около 3.6 пикселя. При `Depth = 0.1` использован рельеф с частотой ×4, чтобы
сохранить светлые линии. Максимальная ошибка яркости Value до преобразования
для показа около `2.4e-7` в линейном RGB. Цвет в прототипе собирался на CPU
по карте, отрисованной в Unity. Стоимость обработки на GPU пока не измерена.

Артефакты сравнения в той же папке: `value-fringe-comparison.png`,
`value-fringe-strength.png`, отчёты `.txt` и `ValueFringeComparison.cs`.

## Сглаживание вдоль спектра

Временный рендер в Unity сопоставляет 6 полос CIE/D65, те же 6 полос
с растяжением пятен и эталон на 24 длинах волн. У каждой полосы направление
растяжения задано разностью мест попадания луча на `λ ± σ`. Дисперсия длин волн
`σ²` рассчитана по табличным весам внутри полосы. Пятна нормированы по энергии,
`Softness = 1` во всех вариантах.

При `Dispersion = 1`, `Depth = 1` разрывы между цветами сгладились. Ошибка RMSE
в отображаемом RGB относительно эталона снизилась с 0.0591 до 0.0353.
При `Dispersion = 0.6`, `Depth = 1` она снизилась с 0.0225 до 0.0184.
При `Depth = 0.1` и частоте рельефа ×4 картинки близки, ошибка выросла с
0.0043 до 0.0049. Средняя линейная яркость во всех вариантах около 0.12.

Артефакты: `spectral-footprint-comparison.png`, отчёт `.txt`,
`SpectralFootprintComparison.cs` и `spectral-band-data.py` в той же папке.
Эталон использует [таблицы PBRT](https://github.com/mmp/pbrt-v4/blob/master/src/pbrt/util/spectrum.cpp).
Метод основан на [спектральных дифференциалах лучей](https://elek.pub/projects/EGSR2014/index.html).

Для следующего сравнения собрать выбранные варианты на одних условиях.
В прототипе растяжение использует две дополнительные карты попадания лучей на
полосу, переиспользуемые между полосами. Перед переносом в ноду нужно проверить
более дешёвый расчёт растяжения, измерить время GPU и оценить стабильность
цвета при анимации.
