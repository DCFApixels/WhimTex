# F16. Chroma Key FX

- Назначение: удалять фон по выбранному цвету с мягкой альфой и отдельным подавлением цветного ореола.
- Статус: дизайн по запросу пользователя от 2026-10-11, без реализации. Минимальный состав предложен; качество краёв, диапазоны и defaults требуют проверки на изображениях.
- Источники истины: [контракт Shader FX](../../Documentation~/ShaderFX.md), [передача параметров](../../src/ShaderFX.cs), [цветовые преобразования](../../src/Shaders/HdrColor.cginc), [каталог](../../src/FXPresets/), [глоссарий](../DECISIONS.md#глоссарий). В текущем каталоге отдельного Chroma Key нет.

## Проблема → решение

Threshold/Mask умеют менять покрытие, но не предоставляют вместе выбор цвета фона,
мягкую границу совпадения и удаление цветного рефлекса на объекте. Предлагается
самостоятельный `Color/Chroma Key`, обычный shader-блок в списке FX, не Effect Layer
и не специальная ветка Drawing/File. Он применим к результату предыдущих FX,
группе и Shader Processor через общий ApplyFX/SampleInput.

## Основа алгоритма и источники

[Референс realtime shader](https://github.com/obsproject/obs-studio/blob/master/plugins/obs-filters/data/chroma_key_filter_v2.effect)
использует расстояние в Cb/Cr, мягкую маску, отдельный spill и несколько соседних
выборок для сглаживания. [Контракт chromakey/colorkey](https://ffmpeg.org/ffmpeg-filters.html#chromakey)
различает поиск по цветности и RGB; [Despill](https://github.com/FFmpeg/FFmpeg/blob/master/libavfilter/vf_despill.c)
показывает подавление избыточной компоненты отдельно от создания альфы.

Для WhimTex предлагаются эти принципы, не буквальная копия shader. Внешние
референсы имеют собственные цветовые/alpha conventions и лицензии. В этой задаче
никакой сторонний код не переносится; при будущем заимствовании проверить
лицензию и необходимые notices отдельно.

## Минимальный интерфейс

| UI / параметр | Начальное предложение | Назначение |
| --- | --- | --- |
| `Key Color` / `_KeyColor` | Зелёный; alpha игнорируется. | Цвет удаляемого фона. Штатный color picker, включая пипетку, без отдельной специальной кнопки. |
| `Distance` / `_Distance` | Enum `Chroma` / `RGB`, default Chroma. | Chroma сравнивает цветность с меньшей зависимостью от яркости. RGB подходит в том числе для чёрного/белого фона и точного удаления цвета. |
| `Tolerance` / `_Tolerance` | 0.10, диапазон 0–1. | Радиус полного удаления вокруг выбранного цвета. |
| `Softness` / `_Softness` | 0.05, диапазон 0–1. | Ширина плавного перехода от удалённого к сохранённому цвету; это не радиус blur в пикселях. |
| `Despill` / `_Despill` | 0, диапазон 0–1. | Подавление примеси цвета экрана в сохранённом объекте. Ноль не меняет RGB. |
| `Spill Range` / `_SpillRange` | 0.10, диапазон 0–1; только при Despill != 0. | Дополнительная область цветового сходства, в которой может подавляться ореол. Не меняет alpha. |
| `Output` / `_Output` | `Result` / `Matte`, default Result. | Обычный результат или непрозрачное чёрно-белое изображение итогового покрытия. |
| `Opacity` / `_Opacity` | 1, диапазон 0–1; `@control` в шапке. | Смешивание полного выбранного RGBA-результата с оригиналом, не ещё один множитель alpha. |

Использовать существующие `@param`, `@group`, `@if _Despill != 0` и `@control`.
Группы: Key, Spill, Output. Скрытые значения сохраняются; Distance/Output — обычные
uniform enums, не shader variants. F13 не является условием первой реализации.
Начальные числа выше — ориентиры для тестов, не обещание подходящих defaults для
всякой фотографии.

## Технический контракт предложения

### Поиск и alpha

1. Вход и выход — straight RGBA, как требует FX wrapper. Рабочий RGB линейный. Не делать собственный второй unpremultiply/premultiply; не брать размеры из Texture2D ассета вместо текущего FX input.
2. Для поиска получить display-encoded RGB через общий `SpriteEncode`, как у HSV. Ограничить только анализируемую копию цвета до 0–1; исходный HDR/signed RGB не обрезать до SDR. Key Color получает ту же конверсию ровно один раз после штатной передачи color uniform.
3. Chroma: сравнивать две координаты Cb/Cr. Предлагается фиксированная full-range матрица с весами Y `(0.2126, 0.7152, 0.0722)`, Cb `(B-Y)/1.8556`, Cr `(R-Y)/1.5748`. Это координаты анализа, не конвертация всего документа в YUV.
4. RGB: нормированное евклидово расстояние RGB. Для обоих режимов нормировка должна давать 0 при полном совпадении и не более 1 для допустимого SDR-диапазона. RGB можно делить на sqrt(3), расстояние Cb/Cr — на sqrt(2); шкалы двух режимов не обещают одинаковую художественную чувствительность.
5. При `Tolerance = 1` сохранить нулевую matte явно. Иначе `keep = smoothstep(Tolerance, Tolerance + Softness, distance)`. При Softness = 0 использовать определённую жёсткую ветку: `distance <= Tolerance` удалён, больше — сохранён. Не вызывать smoothstep с одинаковыми границами.
6. Итоговая альфа `aOut = aIn * keep`. Частично прозрачный вход не становится непрозрачным; совпадение цвета не заменяет уже существующую альфу. Полностью прозрачные пиксели не участвуют в восстановлении RGB.
7. Для Result сохранить straight RGB, изменённый только Despill. Для Matte вернуть `float4(aOut.xxx, 1)`: белое — итоговое покрытие, чёрное — отсутствие покрытия. Это явный альтернативный выход FX, не скрытая маска слоя.
8. Итоговый `lerp(input, selectedOutput, Opacity)` смешивает все четыре компоненты. Opacity = 0 возвращает input без дополнительных цветовых преобразований даже в Matte.

Chroma не является автоматическим решением для нейтрального Key Color: при нулевой
цветности разные серые яркости не различимы. Tooltip Distance должен объяснять
выбор RGB для такого случая. Не вводить специальную проверку имени пресета в
модель слоя или общий renderer ради этого уведомления.

### Despill без изменения matte

Предпочтителен направленный Despill, а не обесцвечивание всего полупрозрачного
края. Оценивать положительную примесь вдоль цветности Key Color; плавно ослаблять
её по расстоянию до ключа в пределах Tolerance + Softness + Spill Range.
Дальний от ключа цвет не должен меняться даже при Despill = 1.

Зафиксировать вес для прототипа: `outer = Tolerance + Softness + Spill Range`;
при outer > Tolerance использовать
`spillWeight = 1 - smoothstep(Tolerance, outer, distance)`.
Если интервал нулевой — 1 при distance <= Tolerance, иначе 0. Не нормировать
weight по alpha; верхняя граница outer может быть больше 1 без деления на ноль.

Для первого прототипа: в линейном RGB построить направление `q = keyRGB - Y(keyRGB)`.
Вычитать только положительную проекцию цветности входа на q, умноженную на
Despill и вес сходства. Поскольку Y(q) = 0, такая коррекция сохраняет линейную
яркость до ограничений диапазона. Ограничить величину вычитания до появления
отрицательных RGB, а не применять saturate ко всему HDR-цвету. При q ≈ 0
Despill равен нулю; для signed входа с отрицательными компонентами коррекцию RGB
пропустить. Это предложенная адаптация, качество которой нужно сравнить с
простым green/blue excess и нейтральной десатурацией.

Spill mask должен рассчитываться независимо от готовой alpha: ореол может быть
на полностью непрозрачной части объекта. Изменение Despill/Spill Range не должно
менять aOut. Не считать обычный Despill восстановлением исходного цвета волос
или смешанного foreground/background.

### Края и стоимость

Первая версия — один обычный FX pass, анализ текущего пикселя, без readback,
дополнительного кеша и многопроходной маттинговой системы. Параметры меняются
без компиляции shader. Это ожидаемая структура, не замер производительности.

Если тесты показывают шум на краях, отдельно оценить Advanced `Edge Filter` с
радиусом в canvas pixels, default 0: несколько соседних SampleInput в том же
pass сглаживают только оценку расстояния/matte, не RGB изображения. Учитывать
render scale, alpha соседей и граничные UV; не применять эту фильтрацию скрыто.
Она может терять мелкие волоски и расширять переход, поэтому не обязательна
для начального варианта. Эрозия/расширение и очистка дыр связаны с кандидатами
обработки масок из F12, но не блокируют Chroma Key.

## Ограничения и edge cases

- Объект того же цвета, что фон, неотличим по одному цвету. Нужны внешний ограничитель/маска или иной метод; не обещать автоматическое распознавание объекта.
- Неровный фон, очень тёмный цветной фон, белые блики и сильное загрязнение краёв могут не укладываться в один ключ. Hue- или multi-key подход можно оценить позднее, не раздувать первую версию тремя наборами порогов.
- У полупрозрачных краёв исходный RGB уже содержит фон. Полная decontamination по `C = a*F + (1-a)*K` требует оценки a и защиты от деления на почти ноль; оставлена отдельным кандидатом, не выдана за решённую Despill.
- Светимость HDR не должна неожиданно обрезаться, но clamp анализа до SDR означает намеренное ограничение различения цветов за SDR. Хромакей предназначен цветным изображениям, не произвольным packed/signed картам данных.
- Сохранённый скрытый RGB прозрачных пикселей и straight-alpha фильтрация могут давать ореол при дальнейшей обработке. Dilate/Color Bleed и корректный alpha sampling — отдельные задачи, не основание умножать RGB на alpha дважды в FX.
- Сложность поиска не зависит от числа слоёв; сам вход группы/Shader Processor готовит общий renderer. FX не должен читать слои заново ради ключа.

## Проверки и следующий шаг

Проверить зелёный/синий и произвольный ключ, RGB-ключ чёрного/белого, exact match,
порог и Softness = 0, крайние диапазоны, прозрачный/полупрозрачный вход, волосы,
motion-like мягкие края, светлый объект на светлом фоне, цветные детали объекта,
HDR, signed/неопределённый цвет и нейтральный ключ. Отдельно: Despill не меняет
matte и не затемняет нейтральный объект; Opacity = 0 — точный identity.

Сверить основной Canvas, group/Target/Shader Processor, clipping, thumbnail и
экспорт. Параметры/условия/Output должны проходить HLSL preset, TIFF/JSON,
Undo/Redo и агентский API. При программной ошибке — общий FX diagnostic mechanism,
не новая консольная ветка для конкретного пресета.

Следующий шаг — небольшой разрешённый прототип базового shader и визуальная
матрица matte/краёв, затем выбор Despill и defaults. Общая система масок,
мультиредактирование F01 и привязки F02 могут расширить применение, но не нужны
для первой версии. Эта карточка не разрешает реализацию, ассеты или push.
