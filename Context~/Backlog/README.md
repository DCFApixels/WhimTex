# Беклог WhimTex

- Назначение: единый список открытых направлений, технических кандидатов и вопросов для согласования; выполненные пункты собраны отдельно.
- Статус: собран 2026-10-08; 2026-10-12 пользователь выбрал сначала доработку SDF/Outline, затем возврат к графу и Layers. Остальной порядок и сроки не утверждены. Наличие пункта не поручает начать его автоматически.
- Источники истины: [AGENTS.md](../../AGENTS.md), [действующие договорённости](../DECISIONS.md), код по ссылкам в карточках. Новые записи из обсуждения пользователя отделены от уже реализованного поведения.

## Как читать

В таблицах приведены краткие задачи; подробности, ограничения и открытые вопросы находятся в карточках.
F обозначает продуктовую возможность, R сохраняет номер прежнего аудита рефакторинга,
T обозначает технического кандидата, Q вопрос для решения, D документацию и проверки.
Номера нужны для ссылок, не задают приоритет.
Открытые части задач находятся в тематических таблицах; завершённые — в
[блоке «Выполнено»](#выполнено). Один ID может встречаться в обоих блоках,
если выполнена только часть направления; состав каждой части указан явно.

| Статус | Значение |
| --- | --- |
| Отложено | Пользователь попросил сохранить направление и вернуться позже. |
| Обсуждено | Пожелания записаны, окончательный дизайн не закреплён. |
| Дизайн согласован | Контракт выбран пользователем; реализация и проверки ещё не выполнены. |
| Дизайн подготовлен | Есть техническое предложение и этапы; пользователь ещё не утвердил контракт и реализацию. |
| Черновик | Сырые предложения сохранены для обсуждения; необходимость, состав, дизайн и приоритеты не подтверждены. |
| Кандидат | Предложение для оценки по текущему коду и измерениям. |
| Требует решения | Без выбора пользователя изменение может оказаться неверным. |
| Не проверено | Нужна проверка; наличие записи не утверждает, что обнаружен дефект. |
| Сообщено | Пользователь наблюдает проблему; причина и способ исправления ещё не проверены. |
| Идея | Обсуждалась возможность, объём и обязательство реализации отсутствуют. |
| Выполнено | Указанный объём реализован; оставшиеся идеи не входят в этот статус. |

## Связи между направлениями

- F19 предшествует возврату к F18 по решению пользователя. Его общий distance field и возможный `sdf`-параметр FX влияют на представление вложенных эффекторов, но не требуют сначала внедрять весь граф. Детали кеша и алгоритмов принадлежат F19, не дублируются в F18.
- [F18](NODE_GRAPH_DESIGN.md) объединяет проектирование вычисления, Stack/Layers, прикреплённых FX, Inputs и Outputs. Это новое предложение, не реализация и не утверждение всех прежних идей. [F08](VECTOR_GRAPHICS_DESIGN.md) описывает его векторную часть и установку Unity-backend.
- F01 и F02 стоит проектировать совместно: редактирование базового значения и привязки должно иметь понятный смысл при мультивыделении. Это рекомендация, не требование реализовать оба сразу.
- F04 позволяет рассматривать F05 как процедурный слой с ручным пересчётом. Запекание в Drawing и FX остаются альтернативами до выбора формы функции.
- F03 и F07 связаны через искажение координат процедурного генератора; векторные карты сами по себе не требуют разделения FX.
- F04 и F06 должны согласовать зависимости от времени и актуальность результатов, если обе возможности будут реализованы.
- F09 связан с T01 через стоимость Save и актуальность запечённых выходов. Результаты On Refresh из F04 потребуют явного правила импорта, если этот режим появится.
- [Outputs в F09](WHIMTEX_IMPORTER.md#выходы-документа) — предложенная общая основа F06 и F10: результат выбранной ветки документа, рассчитанный с заданными параметрами и временем. Полный графовый редактор не требуется.
- F02 управляет связанными настройками карт F10 и временем анимации F06. F09 создаёт текстуры, атласы и Sprite из подготовленных результатов; полный Animation Sheet предлагается обновлять отдельным Bake, не при каждом Save.
- Рекомендуемый порядок: Outputs и статический набор текстур → привязки параметров → управляемое время и таймлайн → Animation Sheet. Приоритеты не утверждены; F03/F07 и частицы не являются обязательными условиями первого этапа.
- F11 использует независимую рандомизацию объектов из F01; поведение связанных значений нужно согласовать с F02. Seed остаётся сохранённым входом, не рандомизируется автоматически при проигрывании F06 или Bake.
- F12 собирает неподтверждённые дополнения генераторов и обработки изображений. Векторные поля остаются в F03; предложения по картам материала связаны с F10, но не утверждают новые зависимости или приоритеты.
- F13 меняет представление существующих параметров FX. При проектировании учитывать мультиредактирование F01, привязки F02 и общие действия F11; эти связи не поручают реализовать все направления одновременно.
- F14 может дать стабильную привязку редакторов F13 и управляемую версию FX при импорте F09 и Bake F06/F10. Выбор источника не означает обязательной миграции старых документов или автоматической совместимости параметров.
- F15.8–9 расширяют получение направления и координат мазка, не заменяют выполненное сглаживание ввода и не требуют остальных черновых улучшений кистей.
- F16/F17 — самостоятельные FX, не новые Effect Layer. Их обычные параметры доступны без F13; F13 позднее позволит добавить наглядный редактор диапазонов Hue. Маски двух эффектов имеют разное назначение, не объединять их настройки в один блок.
- R05/R09 независимы от этих продуктовых решений. Их польза должна уменьшать контекст работы агента, а не только менять оформление кода.

## Что сюда не включено

Завершённые R01–R04/R14, миграция тестов и удаление Legacy, переименование
Document/Window, Mapping/Rendering, общий механизм FX-диагностики и warning-only
политика Unity time uniforms не являются открытыми задачами. История находится в Git
и [аудите переименований](../RENAME_CLEANUP_AUDIT.ru.md).

Исторический баг или перечисление непроверенных платформ не означает текущий дефект.
Отклонённые варианты Healing/Make Seamless не возвращаются в очередь автоматически.
Отсутствие совместимости со старыми версиями не отменяет безопасность текущего сохранения.

## Как поддерживать

- Новую задачу добавлять сюда с целью, статусом, источниками и нерешёнными вопросами. Не хранить второй полный список в HANDOFF/DECISIONS.
- Перед началом читать только выбранную карточку, действующие правила и затронутый код. Повторно проверять старые предположения.
- После реализации и необходимой проверки переносить завершённый объём из открытого списка в «Выполнено» здесь и в соответствующей карточке. Сохранять ID, краткий результат и ссылки на контракт/проверки; не превращать блок в журнал запусков.
- Для частично выполненной задачи оставлять в открытом блоке только оставшуюся часть. Прототип, согласованный дизайн и непроверенная реализация сами по себе не закрывают функцию; ограничения проверки указывать явно.
- Закреплённое поведение переносить в соответствующий контракт. Старые подробности и журналы сохраняет Git; карточки не удалять только ради очистки очереди.
- Документацию и проверки можно обновлять пакетно после нескольких правок. Непроверенное записывать в D02 до итоговой сверки; старые результаты не считать новым PASS.
- Прототипы, тестовые ассеты, установки зависимостей, Player build, commit/push и релиз требуют разрешений по действующим правилам; карточка сама их не предоставляет.
