# F13. Пользовательские редакторы параметров FX

- Назначение: позволить создавать собственное отображение блока параметров FX по аналогии с пользовательскими редакторами компонентов Unity.
- Статус: частично выполнено 2026-10-18. Реализованы HLSL-превью и встроенные подложки Slider; произвольные пользовательские редакторы и другие способы встраивания остаются предложениями.
- Источники истины: запрос пользователя, сохранённый ниже; текущие [редактор FX](../../src/Editor/ShaderFXEditor.cs), [генератор полей](../../src/Editor/ShaderFXParameterView.cs), [параметры](../../src/ShaderFX.cs), [контракт метаданных](../../Documentation~/ShaderFX.md), [HSV](../../src/FXPresets/HueSaturation.hlsl).

## Требование пользователя

В [F18](NODE_GRAPH_DESIGN.md#fx-как-прикреплённые-блоки) один редактор FX instance
обслуживает и прикреплённый стек, и отдельный FX node; раскрытие карточек не
создаёт другой набор параметров. F13 не должно требовать отдельного custom
inspector для каждого размещения одного определения.

Нужен механизм подключения собственного редактора параметров для конкретного FX.
Речь о блоке параметров FX, а не о новом виде слоя или изменении алгоритма эффекта.
Пример применения — градиентные слайдеры для HSV вместо обычных одноцветных шкал.

## Выполнено

- Один синтаксис: отдельный `// @preview(Function)` или `preview(Function)` внутри `@param`. Встроенный Slider использует дорожку; остальные поля получают прямоугольник справа. У превью нет собственных редактируемых параметров.
- Функция возвращает RGBA, принимает `float2 uv` первым и необязательное типизированное значение вторым. Для Slider это кандидат вдоль шкалы, для остальных полей — выбранное значение; обычные uniforms не подменяются. Самостоятельное превью принимает только UV.
- Общие параметры, группы, условия, Reset/Undo и сохранение HLSL сохраняются. Превью имеет собственные GPU-ресурсы; `WHIMTEX_PREVIEW` изолирует код визуализации от основного FX.
- Единый HSV использует цветовые шкалы и текущие диапазоны. Общая float Hue LUT доступна глобально и через helpers в FX/кистях; превью не подменяет расчёт основного эффекта.
- Контракт и ограничения входных изображений: [Inspector previews](../../Documentation~/ShaderFX.md#inspector-previews), [Hue lookup](../../Documentation~/ShaderFX.md#shared-hue-lookup).
- Проверки: `shader-fx-preview-v1` (метаданные, типы, экспорт, GPU, 20 встроенных превью и LUT) и `shader-fx-preview-ui-v1` (временная attached UI, дорожки и fallback справа). [Запуск](../../Tests~/RUNNING_TESTS.md). Сложные live-входы групп/Target, ручное перетаскивание, все типы шейдерных ресурсов и поведение на других GPU не покрыты этим ограниченным прогоном.

## Осталось обсудить

- Встраивание в CurveField и другие контролы, отдельные настройки размера/компоновки превью, подготовка гистограмм.
- Мультиредактирование, привязки и произвольные интерактивные пользовательские редакторы. Эти расширения не следуют автоматически из реализации превью.

## Предлагаемая основа

Ниже — исходное предложение для более широких C#-редакторов, не контракт реализованных HLSL-превью и не утверждённое расширение.

- Editor-расширение на C# создаёт UI для выбранного FX; обычный генератор из `@param` остаётся вариантом по умолчанию и запасным отображением, если расширение отсутствует.
- Дать возможность заменить отдельные поля или весь блок, переиспользуя стандартные поля для остальных параметров. Для одного градиентного слайдера не должно требоваться переписывать весь редактор.
- Пользовательский UI редактирует те же `ShaderFXParameter`, а не отдельную копию значений. Undo/Redo, обновление рендера, блокировки агентского редактирования и ограничения диапазонов проходят через общий механизм изменения параметров.
- Настройки эффекта по-прежнему сохраняются в TIFF/JSON и HLSL-пресете и доступны агентскому API независимо от наличия пользовательского редактора. C#-код расширения не загружается и не исполняется из документа.
- Метаданные `@param`, `@group`, `@if` и `@control` не должны теряться при замене представления. Поведение нестандартного поля при этих директивах нужно определить явно.
- Не вводить проверку имени HSV в общем генераторе: он предоставляет механизм расширения, а редактор HSV использует его наравне с другими FX.

## Первый пример: HSV

Показать градиенты на шкалах Hue, Saturation и Value, сохранив числовой ввод,
перетаскивание label и текущие диапазоны. Градиент служит подсказкой к параметру;
он не меняет shader и не ограничивает HDR или ввод за мягкую границу.

У HSV сейчас Hue — сдвиг, а Saturation и Value — множители входного изображения.
Единственного исходного цвета у такого FX нет. При проектировании выбрать опорный
цвет для градиентов и решить, зависят ли они от других параметров или образца
изображения; не выдавать условную шкалу за точный результат для каждого пикселя.

## Связи и открытые вопросы

- Подключение: как связать редактор с FX — стабильным идентификатором, декларацией в HLSL или регистрацией на стороне C#; названия API и синтаксис пока не выбирать.
- [F14](FX_IDENTITY_VERSIONING.md) предлагает необязательный Source ID и версию FX: при выборе такого подключения редактор должен проверять подходящий набор параметров, не привязываться только к пути и сохранять стандартное запасное отображение.
- Область действия: использовать ли один редактор в Layer Settings и отдельном окне FX, и как он сочетается с компактным контролом `@control` в шапке блока.
- [F01](MULTI_EDITING.md): предусмотреть mixed values, общие поля и работу действий для каждого выбранного FX; пользовательский UI не должен обходить мультиредактирование.
- [F02](DOCUMENT_PARAMETERS.md): оставить место для отображения привязок и редактирования базового значения без отдельной модели данных для каждого редактора.
- [F11](FX_SEED_PARAMETERS.md): переиспользовать общий механизм кнопки Random, не дублировать его в пользовательских редакторах.
- Определить приоритет при нескольких зарегистрированных редакторах, реакцию на смену параметров shader и диагностику ошибки расширения через общий механизм FX. При отсутствии подходящего редактора параметры должны оставаться доступны.

## Следующий шаг

Расширять встроенные способы отображения только по новому запросу. Для интерактивных
C#-редакторов отдельно согласовать способ подключения и общий API изменения параметров;
мультиредактирование и привязки не считать проверенными текущими тестами превью.
