# F14. Идентификатор, версия и выбор источника FX

- Назначение: находить FX независимо от пути и опционально выбирать между текущим пресетом и резервной копией по версии, сохранённой в документе.
- Статус: обсуждено 2026-10-10; пользователь предложил возможность в продолжение беклога. Политики, синтаксис и хранение ниже — предложения, не реализованный контракт.
- Источники истины: запрос пользователя, сохранённый здесь; [ссылки на каталог](../../src/ShaderFX.Catalog.cs), [восстановление FX](../../src/ShaderFX.cs), [каталог](../../src/ShaderFXCatalog.cs), [обработка includes](../../src/ShaderFXSourceBuilder.cs), [TIFF-сериализация](../../src/WhimTexDocumentSerializer.cs), [JSON](../../src/WhimTexDocumentJson.cs), [экспорт пресетов](../../src/ShaderFXPresetWriter.cs).

## Требование пользователя

Добавить необязательный GUID или другой стабильный идентификатор FX, чтобы
идентификация не зависела от пути. Добавить необязательную версию: документ
сможет по ней выбирать текущий пресет или сохранённую резервную копию.
Управление этим поведением тоже должно быть опциональным.

## Что уже есть

- Связанные project/package HLSL-пресеты используют Unity asset GUID: `CatalogPath` получает путь через `GUIDToAssetPath`. Перемещение с сохранением `.meta` уже не требует фиксированного пути. Внешние пользовательские пресеты сейчас встраиваются.
- FX хранит код для восстановления. `RestoreDocumentShader` предпочитает доступный связанный пресет; при неудаче пытается использовать сохранённый код. Хеш зависимостей обнаруживает изменения, но не является объявленной версией FX и не задаёт политику выбора версии.
- TIFF сохраняет код через `DocumentCode`, а JSON разворачивает доступные project/package includes через `ExportIncludes`. В JSON поля `catalogGuid`, `catalogSourcePath` и `catalogDependencyHash` сейчас исключены. Не считать текущие TIFF и JSON одинаковыми по ссылкам и резервным зависимостям.

Новое направление — идентификатор в самом описании FX, независимый от Unity
`.meta`, плюс версия и явная политика источника. Это не повторное введение
миграции старых версий документа или обязательной совместимости продукта.

## Предлагаемая модель

Разделить три понятия:

- **Source ID** — какой это FX. Необязательная стабильная строка; GUID подходит, но конкретный формат ещё не выбран. Путь остаётся подсказкой для поиска, Unity GUID — дополнительным способом разрешения ссылки.
- **Source Version** — какая редакция реализации используется. Для первого варианта предложен целый номер ревизии без диапазонов совместимости. Это не версия WhimTex, TIFF/JSON или ID экземпляра FX в документе.
- **Source Policy** — какой источник предпочитает конкретный FX-блок в документе. Один и тот же пресет может обновляться в одном документе и оставаться зафиксированным в другом.

Пример будущих деклараций, пока не поддерживаемый; имена директив не согласованы:

```hlsl
// @whimtex-effect Color/Example
// @whimtex-id 12bc047d-f5b2-43e4-91fd-84e0c2276cde
// @whimtex-version 2
```

## Предлагаемые политики

| Рабочее имя | Выбор источника |
| --- | --- |
| Follow Preset | Использовать доступный текущий пресет независимо от версии; резервную копию пробовать при отсутствии или ошибке пресета. |
| Match Version | Использовать пресет только при совпадении его объявленной версии с сохранённой. При другой или неизвестной версии оставить резервную копию и предложить явное обновление. Более новый номер сам по себе не доказывает совместимость. |
| Embedded | Всегда использовать сохранённую копию, не обновлять её автоматически из каталога. |

ID и Version независимы и необязательны. При отсутствии ID возможна нынешняя
Unity GUID/путь-ссылка; при отсутствии версии нельзя выдавать результат за
проверенное совпадение версий. В предложенном Match Version отсутствие версии
означает выбор резервной копии, а не неявную версию 0. Обычный FX без новых деклараций должен оставаться допустимым.
Режим по умолчанию и окончательные UI-названия пока не согласованы.

## Сохранение, обновление и диагностика

- Хранить выбранную политику, идентификатор, принятую версию и резервный код в документе. Не подменять сохранённую версию при одном только просмотре каталога или обнаружении обновления.
- Обновление сначала проверяет новый код и объявления параметров, затем принимает новую версию и обновляет резервную копию. Общий путь нужен как явному обновлению, так и автоматическому Follow Preset. Сохранённые значения нельзя молча сбрасывать; удалённые или изменившие тип поля требуют понятного решения пользователя. Автоматическая миграция параметров не входит в это предложение.
- Резервный исходник не гарантирует прежний результат, если изменились его внешние `#include`. Определить единый для TIFF/JSON снимок project/package зависимостей. Engine includes, внешние текстуры и другие входы остаются отдельными зависимостями; не обещать полную воспроизводимость между любыми версиями Unity.
- Хеш кода и зависимостей дополнительно выявляет изменение без повышения номера версии. Он не заменяет ID/Version; реакцию на такой случай согласовать отдельно.
- Дубли одного ID нельзя разрешать выбором случайного файла. Определить допустимость нескольких версий одного ID, правила выбора и диагностику конфликтующих источников одной версии.
- Если Source ID задан, сохранённый путь не разрешает подменить источник другим FX с несовпадающим ID, даже когда файл по этому пути существует.
- Несовпадение версии при работающей резервной копии — предупреждение, не ошибка рендера. Если оба допустимых источника недоступны или не компилируются, использовать общий механизм ошибок FX. UI, агент и Console получают одинаковые сообщения без спама при каждом рендере.
- Copy/paste и экспорт пресета должны различать экземпляр FX, обновление того же источника и создание независимого варианта. Для независимого варианта нужен новый Source ID; правила Save Preset и изменения defaults ещё согласовать.
