# F17. Selective HSV FX

- Назначение: независимо корректировать несколько диапазонов Hue, с плавными границами и без изменения остальных цветов.
- Статус: дизайн по запросу пользователя от 2026-10-11, без реализации. Состав параметров, число диапазонов, defaults и смешивание пересечений — предложения для проверки, не утверждённый контракт.
- Источники истины: [HSV](../../src/FXPresets/HSV.hlsl), [Hue-анализ Edge Outline](../../src/FXPresets/EdgeOutline.hlsl), [метаданные FX](../../Documentation~/ShaderFX.md#parameter-declarations), [цветовой include](../../src/Shaders/HdrColor.cginc), [F13 — редакторы FX](FX_CUSTOM_EDITORS.md).

## Проблема → решение

Обычный HSV меняет всё изображение. Маска отдельным FX позволяет ограничивать
действие, но не даёт компактной настройки нескольких цветовых диапазонов с
разной коррекцией. Предлагается отдельный `Color/Selective HSV`: shader FX,
не Effect Layer и не новый режим, усложняющий обычный HSV.

Пример задачи: сдвинуть синие к бирюзовым, сделать зелёные темнее и красные менее
насыщенными в одном FX. Цветовые зоны определяются исходным Hue, а не уже
изменённым результатом соседней зоны.

## Референсы и границы заимствования

[Huesaturation](https://ffmpeg.org/ffmpeg-filters.html#huesaturation) подтверждает
практическое применение коррекции выбранных цветов, а
[HSV key](https://ffmpeg.org/ffmpeg-filters.html#hsvkey) — выделение по HSV с мягким
переходом. Это ориентиры, не готовый алгоритм нескольких произвольных зон.
Формулы круговой маски и смешивания ниже предлагаются для WhimTex. Сторонний
код не переносится; при заимствовании в будущей реализации проверять лицензии.

Не подменять HSV моделью HSL/LCh: S/V остаются множителями с нейтральной единицей,
Hue — сдвигом в градусах, как у текущего HSV. Перцептуально сохраняющая яркость
коррекция может иметь другой художественный результат и не входит в этот дизайн.

## Редактор и параметры

### Минимум без новой инфраструктуры

Предложены четыре независимые зоны в одном FX. Каждая — группа `Range 1`…`Range 4`
с linked checkbox Enabled в заголовке; поля отключённой зоны скрываются через
`@if`. Включённые зоны содержат одинаковые поля:

| UI / имя для первой зоны | Тип и диапазон | Смысл |
| --- | --- | --- |
| `Enabled` / `_Range1Enabled` | bool | Выключенная зона не участвует ни в коррекции, ни в пересечениях. Значения не стираются. |
| `Center` / `_Range1Center` | float, 0–360° | Центр исходного диапазона Hue; 360° равнозначны 0°. |
| `Width` / `_Range1Width` | float, 0–360° | Полная ширина зоны с полным действием: 60° означает ±30° от центра. 360° охватывают весь круг. |
| `Feather` / `_Range1Feather` | float, 0–180° | Дополнительная плавная граница с каждой стороны, не размытие соседних пикселей. |
| `Hue` / `_Range1Hue` | float, -180–180° | Сдвиг внутри зоны; нейтрально 0. |
| `Saturation` / `_Range1Saturation` | float, 0–~4 | Множитель S; нейтрально 1. |
| `Value` / `_Range1Value` | float, 0–~4 | Множитель V; нейтрально 1, HDR поддерживается. |

Общие четыре параметра:

- `_Opacity`: 0–1, default 1, hidden с `@control(_Opacity)` в шапке.
- `_MinSaturation`: 0–1, начальный default 0.05; подавляет нестабильный Hue почти серого цвета.
- `_SaturationFeather`: 0–1, начальный default 0.05; плавное включение после Min Saturation.
- `_Output`: enum Result / All Ranges Mask / Range 1 Mask…Range 4 Mask. Default Result; переключение на mask является явным выходом FX, не скрытым режимом host renderer.

Итого 4 × 7 + 4 = 32 параметра: укладывается в текущий лимит live authoring API.
Парсер FX допускает до 128 деклараций, но это не означает, что агентское API
автоматически поддерживает столько же. Четыре — предложенный начальный объём,
не принципиальное ограничение алгоритма.

Первую зону предложено включить с Center = 0°, Width = 60°, Feather = 15°;
остальные выключить и задать центры 120°, 240° и 60°. Все Hue/S/V нейтральны,
поэтому добавление FX изначально не меняет изображение. Defaults уточнить по
тестам, не выдавать заранее выбранные центры за обязательные цветовые категории.

### Наглядный UI позднее

Через F13 можно заменить Center/Width/Feather полосой полного Hue-круга с центром,
двумя границами полного действия и двумя внешними границами feather. Ручки должны
проходить через 0° без разрыва; числовые поля остаются доступны. Добавить выбор
центра пипеткой и градиентные шкалы коррекции через общий механизм редакторов FX,
без проверок имени Selective HSV в ShaderFXParameterView.

Редактор меняет те же обычные параметры, не собственную копию диапазонов.
Undo/Redo, TIFF/JSON, HLSL preset, API и будущие привязки F02 сохраняют одну модель.
Произвольный список Add/Remove/Move — дальнейшее расширение модели повторяемых
параметров и лимита API, не обязательный рефакторинг для четырёх зон. Первоначальный
fallback UI должен быть полноценным без пользовательского C#-редактора.

## Shader: круговая маска

Hue, S и V получить один раз из `SpriteEncode(max(input.rgb, 0))`, совпадая
с текущим HSV. Не обрезать V до 1; не считать raw linear RGB оттенками picker.
У черного/серого Hue неопределён: для начального варианта считать его
недостоверным при display-encoded value <= 0.00001, chroma <= 0.00001 или
saturation <= 0.00001, как у существующего Hue-анализатора. Маска тогда равна
нулю даже при Min Saturation = 0. Числа не являются пользовательскими полями;
их общую реализацию сверить с Edge Outline. Вход с нулевой alpha не
корректировать по скрытому RGB.

Для каждой включённой зоны при Hue/Center в долях круга:

```text
d = abs(frac(hue - center + 0.5) - 0.5) * 360
r = Width / 2
f = min(Feather, max(0, 180 - r))
если Width = 360: hueWeight = 1
иначе при f > 0: hueWeight = 1 - smoothstep(r, r + f, d)
иначе: hueWeight = (d <= r), кроме Width = 0, где hueWeight = 0
```

Width = 0 с ненулевым Feather даёт плавный пик вокруг Center без плоской середины.
Width = 0 / Feather = 0 — пустая зона. Ограничение f применяется к эффективному
расчёту, сохранённый Feather не переписывается. Так ширина не создаёт вторую
ступеньку на противоположной стороне круга, и можно затем уменьшить Width.

Общая saturation gate g плавно возрастает от Min Saturation до
`min(1, Min Saturation + Saturation Feather)`. При нулевом/вырожденном интервале
использовать явную ступеньку; Min Saturation = 1 допускает только полностью
насыщенный цвет. g умножает действие после нормировки пересечений, чтобы несколько
пересекающихся зон не отменяли защиту почти серых пикселей.

## Пересечения: коррекция по исходному цвету

Не запускать четыре полных HSV последовательно: изменённый первой зоной Hue
может попасть во вторую, а результат начнёт зависеть от порядка. Рекомендуемый
первый вариант — одновременно вычислить все веса по исходному Hue и применить
одну совокупную коррекцию.

```text
wi = hueWeight включённой зоны i
Z = max(1, sum(wi))
deltaHue = g * sum(wi * HueShift_i) / Z
satScale = 1 + g * sum(wi * (Saturation_i - 1)) / Z
valScale = 1 + g * sum(wi * (Value_i - 1)) / Z
```

- Если работает одна зона, feather постепенно ослабляет её параметры к нейтральным.
- При сильном пересечении используются нормированные поправки, а не удвоение силы. Две одинаковые полностью действующие зоны дают ту же коррекцию, что одна; это намеренная семантика, не stack двух FX.
- Hue Shift смешивается как подписанное указание направления: +60° и -60° компенсируются. Знак ±180° сохраняется, без канонизации и скачка на конце шкалы. При полном весе одной зоны оба дают один конечный оттенок, но при весе 0.5 это +90° и -90° — разные направления плавного перехода. Две перекрывающиеся зоны с противоположными большими сдвигами могут компенсироваться; это намеренное смешивание подписанных поправок, не круговое усреднение целевых Hue. Показать это в tooltip и тестах.
- Включённая нейтральная зона также участвует в Z и может ослаблять другую в пересечении. Для отсутствия влияния зону следует выключить. Это правило требует художественной проверки; режимов Average/Add/Priority в первый интерфейс не добавлять.
- g применяется после Z. Alpha не участвует в нормировке и остаётся исходной.

Затем один раз получить скорректированный RGB по правилам текущего HSV:
Hue циклический, S после множителя ограничен 0–1, V не имеет SDR-потолка,
decode обратно в linear; соблюдать диапазон рабочего HDR-формата.
В Result применять обычный `lerp(originalRGB, correctedRGB, Opacity)` с исходной
alpha. В Result при нулевом действии или нейтральных параметрах вернуть исходный
RGBA напрямую, сохранив signed/HDR и скрытый RGB без лишнего roundtrip.
Нейтральная коррекция не отключает mask-выход: выбранные зоны в нём всё равно
видны. Opacity = 0 возвращает original в любом Output.

Для All Ranges Mask использовать `g * min(1, sum(wi))`; для одной зоны — `g * wi`.
В mask-выходе показать выбранный вес, умноженный на входную alpha, как RGB-серый
с alpha = 1. Это покрытие выделяемого цвета, а не преобразованная альфа объекта.
В Result вес коррекции не умножать на alpha второй раз. Opacity = 0 возвращает
original и в mask-выходе, как у прочих FX с альтернативным Output.
При промежуточной Opacity mask-выход смешивается целиком:
`lerp(input, float4(maskCoverage.xxx, 1), Opacity)`; alpha растёт от input.a к 1.
Для чистой непрозрачной диагностики/маски использовать Opacity = 1.

## Стоимость, зависимости и edge cases

Один pass, без соседних выборок и readback; одна конверсия input RGB→HSV и одна
HSV→RGB, четыре небольших расчёта маски. Enabled/Output — uniforms, правка значений
не компилирует новый shader. Пока четыре зоны, LUT не нужен; для большого числа
зон позднее можно оценить циклический LUT поправок, включая точность HDR/границ.
Стоимость пока не измерена. Feather смягчает переход в цвете, а не blur деталей.

Проверить:

- Зону красных через 359°/0°/1°, центры 0°/360°, Width 0/360°, Feather 0/максимальный и область напротив Center.
- Все зоны выключены, нейтральные зоны, точное действие одной зоны против текущего HSV при полном весе. Действующая saturation gate должна быть учтена при сравнении.
- Два одинаковых диапазона, противоположные сдвиги, нейтральная зона поверх активной, +/-180° и near-wrap shifts, перестановку настроек зон. Маски не должны повторно рассчитываться из изменённого цвета.
- Серый, чёрный, почти серый цвет с шумом, насыщенные цвета, полупрозрачные пиксели, alpha = 0, HDR > 1 и signed вход. Фильтр не создаёт оттенок серого из неопределённого Hue; Value/Saturation этих серых пикселей остаются неизменными.
- Гладкую Hue-полосу и реальные цветовые переходы: отсутствие разрыва красного, ступеней feather и неожиданного banding. HSV не гарантирует сохранение воспринимаемой яркости при большом Hue Shift.
- Canvas, group/Target/Shader Processor, clipping, thumbnail/export; TIFF/JSON, preset, API, Undo/Redo и сохранение скрытых полей после Enabled/Output switching.

F16 может позднее переиспользовать математический helper кругового Hue, если
получит Hue-key режим; его alpha/despill не являются параметрами Selective HSV.
F13 улучшает UI, F01/F02 дают mixed values/привязки, но не блокируют обычные поля.
Новые ошибки и предупреждения проходят через общий FX diagnostic mechanism.

## Следующий шаг и решения перед реализацией

Прототип четырёх зон с обычной metadata-разметкой; визуально проверить
нормированное смешивание, особенно нейтральную пересекающуюся зону и сдвиги около
±180°. Если художественный результат требует кругового усреднения целевого Hue
или явного приоритета зон, выбрать это до закрепления API, а не добавлять несколько
режимов «на всякий случай». Согласовать четыре зоны как начальный объём; при
требовании произвольного числа сначала проектировать повторяемые параметры/API.
Эта карточка не разрешает реализацию, ассеты, запуск Unity-проверок или push.
