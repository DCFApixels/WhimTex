# Дальнейшее развитие профайлера

- Назначение: сохранить оставшиеся задачи F23 при переключении на векторную графику.
- Статус: отложено по запросу пользователя; текущий профайлер остаётся доступным.
- Источники истины: [контракт](../../Documentation~/AgentAPI.md#profiler-captures), [руководство](../../Documentation~/ru/preview.md), [проверки](../../Tests~/RUNNING_TESTS.md), `src/WhimTexProfiler*.cs`.

## Выполнено

Сбор этапов редактора с Unity markers, группами, именами слоёв, иерархией,
причинами пересчёта и восстановлением записи после перекомпиляции. Измеряются FX-блок
и отдельные FX, подготовка/отправка на CPU и доступные GPU-интервалы; результаты GPU
обновляются автоматически. Есть учёт принадлежащих инструменту ресурсов, ограниченные
бенчмарки снимка документа, baseline-сравнение и компактная сводка для агента.

Managed-выделения по этапам представлены количеством всего и без вложенных этапов;
байты всех потоков Editor показаны отдельно. Summary и Comparison поддерживают эти
показатели, сортировку, неполные измерения и цвет разницы. Архив записей не реализован.

## Оставшиеся задачи

| Направление | Следующий шаг и критерий |
| --- | --- |
| Накладные расходы записи | Измерить одинаковые операции без записи, с CPU/allocations и с GPU. Проверить, насколько сам сбор меняет короткие операции; документировать стоимость. |
| Дальнейшее покрытие | В Vector-прототип добавлены `vector.edit`, `vector.raster`, `vector.brush_trace` и `vector.brush_rebuild`. Дальше проверять полноту цепочки изменения → инвалидирование → расчёт и новые инструменты, а не только время SDF. |
| Рабочие потоки | Сейчас их исполнение видно в штатном Unity profiler, не в собственном дереве. Оценить отдельные worker spans без двойного учёта ожидания на main thread. |
| Полная задержка действия | Связать жест пользователя с окончательным обновлением изображения/GPU, включая отложенную работу. Текущий changeId сам по себе не измеряет input-to-present. |
| Память | По результатам замеров расширять покрытие native scratch и ранее созданных ресурсов. Не выдавать размер payload за физическую VRAM или память пула Unity. |
| Проверки среды и нагрузки | Проверить GPU ready/unavailable на других поддерживаемых конфигурациях, длинные записи, лимиты и накладные расходы автоматического обновления UI. |
| Архив записей | Пользователь ранее исключил его из реализации. Вернуться отдельно: несколько сохранённых captures, импорт/экспорт и сравнение между сессиями; текущий baseline не является архивом. |

Новые способы измерения через внутренние Unity API или нативные зависимости требуют
отдельного согласования. Перечень ограничений не означает, что каждое из них обязательно
нужно устранять; следующий объём выбирать по реальным случаям профилирования.
