# Дальнейшее развитие профайлера

- Назначение: сохранить оставшиеся задачи F23 при переключении на векторную графику.
- Статус: частично выполнено; переносимые измерения расширены 2026-10-20, ограничения проверки среды перечислены ниже.
- Источники истины: [контракт](../../Documentation~/AgentAPI.md#profiler-captures), [руководство](../../Documentation~/ru/preview.md), [проверки](../../Tests~/RUNNING_TESTS.md), `src/WhimTexProfiler*.cs`.

## Выполнено

Сбор этапов редактора с Unity markers, группами, именами слоёв, иерархией,
причинами пересчёта и восстановлением записи после перекомпиляции. Измеряются FX-блок
и отдельные FX, подготовка/отправка на CPU и доступные GPU-интервалы; результаты GPU
обновляются автоматически. Есть учёт принадлежащих инструменту ресурсов, ограниченные
бенчмарки снимка документа, baseline-сравнение и компактная сводка для агента.

Managed-выделения по этапам представлены количеством всего и без вложенных этапов;
байты всех потоков Editor показаны отдельно. Summary и Comparison поддерживают эти
показатели, сортировку, неполные измерения и цвет разницы. Архив записей не реализован.


Дополнение 2026-10-20: отдельные worker-события для записи страниц истории и подготовки
checkpoints, время очереди, доступные encode/write/hash, связи originId/inputId. Фон не
прибавляется к main-thread rootWallMs. Для кисти измеряется ввод/отпускание → готовность
холста; для остальных правок — запрос пересчёта → готовность. Доступна неблокирующая
проверка GPU fence с явным статусом и интервалом опроса. Это верхняя граница завершения GPU,
а не измерение физического показа на мониторе.

Учтены существующие paint-native pools, writer payload, transfer pages и Half atlases,
включая созданные до старта записи. Метрики не суммируются как независимая VRAM.
Глобальный опрос памяти ограничен 100 мс; Start API принимает gpu/allocations для сравнения.
[Проверки](../../Tests~/Cases/Automation/ProfilerFollowupTests.cs): потоки, отсутствие двойного
учёта, snapshot roundtrip, ограничение событий и pending workers, публичный GPU fence.
Микротест на этой машине: off 0,790 / CPU 1,778 / allocations 2,084 / GPU configured 2,224 мкс
на короткий этап, включая одинаковый reflection harness. Последний режим не измеряет стоимость
активированных GPU marker queries; её нельзя выводить из этого сравнения.

Отдельный тест с активными GPU queries выполнен: одинаковые пакеты из восьми Blit на
временной текстуре 256×256, по 30 замеров с обновлениями Editor между ними. Медиана
CPU-отправки: off 0,1273 / CPU 0,1368 / allocations 0,1292 / GPU + allocations 0,1720 мс.
GPU-результаты получены со статусом ready. Это стоимость отправки короткого пакета на
данной машине, не оценка влияния профайлера на FPS всех документов.

Общая история также проверена с активной записью на отдельных SDR/HDR 8K документах:
writer-события и paint pools попали в отчёт, точные Undo/Redo прошли. Проверки запускаются
профилями `profiler-followup`, `pixel-tool-history` и отдельно `pixel-tool-history-8k`.
Результаты текущего прогона сохранены в проектном `Temp/WhimTex/test-runs/`:
`2026-10-20T13-17-26.932Z-8088.json`, `2026-10-20T13-17-54.431Z-47576.json`,
`2026-10-20T13-18-25.100Z-79164.json`.

Автообновление окна проверено и доработано 2026-10-20:

- Сводка накапливается в числовых полях, JSON создаётся по итоговым строкам. Убран
  перевод ответа в строку и обратный разбор для собственного окна.
- Автоматическое чтение разделено между обновлениями Editor с целевыми 4 мс на порцию.
  Это не жёсткий предел: отдельный фрагмент, GC и привязка таблицы могут занять больше.
  Между чтениями есть пауза от 0,5 с, увеличивающаяся со стоимостью расчёта.
  События продолжают записываться; таблица показывает предыдущий готовый результат.
- На детерминированных записях 32 768 / 262 144 событий полное обновление данных UI:
  **328 / 2442 мс → 46 / 304 мс**. Максимальная автоматическая порция: **13,6 / 12,9 мс**.
  Это неподключённое окно без стоимости экранного layout; в реальном открытом окне
  минутного прогона максимальный callback занял **27,4 мс**.
- Три одинаковые минутные нагрузки: реальная кисть и рендер временного холста 512² плюс
  плотные короткие события. Медиана пакета off / запись / запись с окном:
  **1,315 / 2,005 / 1,945 мс**, p95 **1,987 / 2,635 / 2,713 мс**.
  Разницу последних двух медиан нельзя считать ускорением кисти; это сравнение
  накладных расходов на данной машине, без измерения FPS или физического показа.
- Лимиты времени/событий, позднее завершение worker после остановки, отказ очистки
  незавершённой записи, три цикла очистки/запуска прошли. Выборки managed heap
  колебались при GC; на этом интервале непрерывного роста не видно. Это не доказательство
  отсутствия утечек при многочасовой работе и не оценка всей памяти процесса.
- Данные совпали с замерами до правок для четырёх запросов на каждом размере.
  Отдельно проверены одинаковые результаты синхронного/порционного чтения, смена
  фильтра и записи, Clear, поздние GPU revisions и закрытие окна.

Профиль `profiler-load` и диагностические `profiler-load-before/after` описаны в
[проверках](../../Tests~/RUNNING_TESTS.md#profiler-window-load-and-lifecycle-2026-10-20).
Отчёты: `2026-10-20T13-48-29.780Z-61488.json` (до), `2026-10-20T14-01-45.668Z-16872.json`
(после), `2026-10-20T14-02-24.310Z-65940.json` (три минутных прогона),
`2026-10-20T14-10-22.644Z-54340.json` (lifecycle и worker/GPU regression).

## Оставшиеся задачи

| Направление | Следующий шаг и критерий |
| --- | --- |
| Накладные расходы записи | CPU/allocations, активные GPU queries и автоматическое обновление UI проверены на этой машине. При новых сценариях учитывать, что ручное обновление/фильтрация, первичное открытие и сравнение записей остаются синхронными. |
| Дальнейшее покрытие | В Vector-прототип добавлены `vector.edit`, `vector.raster`, `vector.brush_trace` и `vector.brush_rebuild`. Дальше проверять полноту цепочки изменения → инвалидирование → расчёт и новые инструменты, а не только время SDF. |
| Рабочие потоки | Основные writer/checkpoint Task подключены. Новые фоновые операции подключать по мере появления; Unity Jobs не считаются автоматически измеренными этим механизмом. |
| Полная задержка действия | Brush batch/release и запросы Canvas связаны с готовностью изображения/GPU. Для других жестов можно добавить точное начало принятого ввода; физический input-to-present требует отдельного платформенного измерения. |
| Память | Основные пулы рисования учтены. Остались scratch других подсистем и аппаратная память/driver overhead, недоступные через текущие переносимые счётчики. Worker allocated bytes остаются null, если runtime не поддерживает счётчик. |
| Проверки среды и нагрузки | GPU ready/unavailable на других поддерживаемых конфигурациях и многочасовые нагрузки. Лимиты, три минутных нагрузки и UI проверены. Максимальная синтетическая запись дала reload snapshot 278,9 МБ при существующем ограничении 256 МиБ: полный reload такого объёма не пройден, нужен отдельный выбор формата/лимита. |
| Архив записей | Пользователь ранее исключил его из реализации. Вернуться отдельно: несколько сохранённых captures, импорт/экспорт и сравнение между сессиями; текущий baseline не является архивом. |

Новые способы измерения через внутренние Unity API или нативные зависимости требуют
отдельного согласования. Перечень ограничений не означает, что каждое из них обязательно
нужно устранять; следующий объём выбирать по реальным случаям профилирования.
