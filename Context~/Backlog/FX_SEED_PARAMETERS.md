# F11. Seed-параметры FX с кнопкой Random

- Назначение: объявлять Seed в FX как обычное числовое поле с кнопкой генерации случайного значения справа.
- Статус: реализовано 2026-10-12; числовые Seed-контролы, Undo/Redo, экспорт и агентский путь проверены в Unity Test6.6.
- Источники истины: обсуждение пользователя, сохранённое здесь; текущие [FX-параметры](../../src/ShaderFX.cs), [парсер метаданных](../../src/ShaderFXMetadata.cs), [UI полей](../../src/Editor/ShaderFXParameterView.cs), [экспорт пресетов](../../src/ShaderFXPresetWriter.cs), [контракт параметров](../../Documentation~/ShaderFX.md).

## Требование пользователя

Нужен параметр для сидов: справа от поля кнопка Random, задающая случайное
значение с учётом Min/Max. Универсальная рандомизация цветов, векторов,
трансформов и остальных типов не входит в этот запрос.

## Выполнено

Добавить модификатор `seed` к существующему числовому параметру:

```hlsl
// @param seed float _Seed = 0 [0 .. 10000]
```

Это действующий синтаксис. Модификатор явно задаёт
назначение поля; не распознавать его по имени `_Seed`. В HLSL параметр остаётся
`float`: текущие Seed в CRT, Digital Glitch и VHS объявлены так. Новый алгоритм
шума или отдельное хранилище случайных значений не требуются.

- Сохранить обычное числовое поле и его поведение; добавить справа кнопку Random.
- По нажатию выбирать целое число в диапазоне объявления, включая обе границы. Для нецелых границ предложен интервал `ceil(min)` … `floor(max)`.
- Мягкие границы `~` тоже ограничивают генерацию. Ручной ввод сохраняет обычные правила hard/soft границ; сам модификатор не превращает все ручные значения в целые.
- Для первого варианта требовать две конечные границы и непустой диапазон целых значений. Не подставлять скрытый диапазон по умолчанию; некорректное объявление диагностировать общим механизмом FX.
- Random меняет сохранённое значение один раз, поддерживает Undo/Redo и обычное инвалидирование зависимого рендера. Preview, Save, импорт, Bake и проигрывание не вызывают рандомизацию самостоятельно.
- Каждая выполненная агентская FX-операция выбирает значение независимо; одинаковые выборки допустимы. Мультиредактирование UI пока не реализовано (F01).
- Экспорт пресета и copy/paste сохраняют модификатор, диапазон и текущее значение. UI и агентское API используют общий механизм изменения параметров.

## Связи и открытые вопросы

- [F01](MULTI_EDITING.md) задаёт принцип независимой работы кнопок для каждого объекта; новый Seed должен использовать его, не отдельный обход выбранных FX.
- [F02](DOCUMENT_PARAMETERS.md): определить действие Random при привязке Seed к параметру документа. Не переписывать общий параметр и не разрывать связь без явного выбора; при Replace изменение локального значения может вообще не влиять на результат.
- [F06](ANIMATION_DESIGN.md): выбранный Seed — стабильный вход расчёта кадров. Рандомизация по времени или на каждом кадре не входит в эту кнопку.
- Повторные seed-контролы используют свои диапазоны. `hidden` скрывает строку тела, но не явно связанный group/header-контрол; `label`, условия и группы сохраняют общие правила. Агентский `randomizeSeeds` использует первый seed-контрол указанного uniform.
- Границы ограничены −16777216…16777216: в этом диапазоне целые числа точно представлены `float`. Полный 32-битный integer Seed не обещается.

## Проверка и оставшиеся связи

`shader-fx-seed-parameters` проверяет границы, дробные/мягкие интервалы, фиксированные
значения, ошибки с номерами строк, копирование metadata, UI/header, Undo/Redo,
API copy-on-write, отсутствие рандомизации при validation/save, экспорт и JSON reopening.
CRT, Digital Glitch и VHS переведены по подтверждённому назначению `_Seed`.
Общие parser/view/writer дают тот же модификатор HLSL-кистям; валидатор и VSIX обновлены.

Смысл Random при будущих привязках F02 и независимая обработка кнопок в будущем
UI-мультиредактировании F01 остаются открытыми. Полная UI-матрица — в D02.
