# F29. Позиционирование и редактирование градиентов фигур

- Назначение: сделать размещение и растяжение градиента в Shape и Vector предсказуемыми, а настройки на холсте и в Properties — понятными.
- Статус: отложено по просьбе пользователя 2026-10-20. Предложение подготовлено; окончательные правила и реализация не утверждены. Запись не поручает начинать разработку.
- Источники истины: обсуждение с пользователем 2026-10-19–20; [FigureFill](../../src/Layers/FigureFill.cs), [поля оформления](../../src/Editor/FigureFillEditor.cs), [GradientCanvasTarget](../../src/GradientCanvasTarget.cs), [манипуляторы](../../src/WhimTexWindow.Gradient.cs), [GPU-расчёт](../../src/Shaders/FigureGradient.cginc), [F08](SVG_LAYER.md).

## Запрос пользователя

- При включении Radial ожидать центр примерно посередине самой фигуры.
- Независимо растягивать градиент, например получать овальный Radial, сохраняя форму объекта.
- Сделать параметры размещения в Properties понятными и согласованными с ручками на холсте.

## Причина текущего неудобства

В изученной реализации сохраняются Start/End в координатах слоя. При смене типа
Start становится центром Radial; исходное значение `(0, 0)` не вычисляется из
геометрических границ фигуры. Для Vector даже середина reference frame может
не совпадать с серединой нарисованного контура.

Поле Radius / Direction хранит координаты конечной точки, а не величину радиуса.
Расчёт использует одну ось: отдельной второй оси для растяжения самого градиента
в эллипс нет. Деформация всего слоя не заменяет независимую настройку градиента.
Перед реализацией повторно сверить это описание с текущим кодом.

## Подготовленное предложение

Это предложенный агентом дизайн, а не окончательно выбранный контракт.

1. **Собственное размещение градиента.** Хранить центр, размеры двух осей и поворот
   отдельно от трансформа фигуры. Fill и Stroke сохраняют независимые настройки.
2. **Первоначальное размещение по геометрии.** Брать реальные локальные границы
   фигуры или контура. Linear проходит слева направо через середину; Radial,
   Square и Angular начинаются по центру охватывающего прямоугольника. Для нового
   Radial предложен круг с диаметром по меньшей стороне фигуры. Границы вектора
   должны учитывать кривые, а не только позиции узлов или управляющих точек.
3. **Смена типа без неожиданного смещения.** Сохранять настроенное положение;
   при Linear → Radial использовать середину линейного градиента, а не его начало.
   Согласовать преобразование размера между типами.
4. **Манипулятор Radial.** Центральная ручка перемещает весь градиент; основная
   меняет размер и поворот; перпендикулярная растягивает вторую ось. Тонкий контур
   показывает эллипс. Связь осей сохраняет пропорции.
5. **Properties по смыслу выбранного типа.** Linear: Position, Length, Angle;
   Radial/Square: Center, Width/Height со связью пропорций, Angle;
   Angular: Center, Angle, Repetitions. Предложены проценты от границ фигуры для
   центра (`50%, 50%` — середина) и пиксели полного размера для Width/Height.
6. **Явные действия.** Center перемещает без изменения размера и поворота;
   Fit to Shape заново центрирует и подгоняет оси по границам. Edit on Canvas
   в конкретном блоке Fill/Stroke включает редактирование нужной заливки.
7. **Сохранение ручной настройки.** Границы используются при создании и явной
   подгонке. Правка узлов не должна постоянно пересчитывать уже настроенный
   градиент; трансформация всего объекта переносит градиент вместе с ним.

Сохранить существующее правило активации: выбор Shape/Vector сам по себе не
включает Gradient Handles; вручную включённый инструмент остаётся активным
при переходе между подходящими фигурами. Freeform не заменять двухосевой моделью.

## Перед реализацией и проверкой

- Подтвердить начальный размер, единицы, переходы между типами и поведение при
  изменении размеров Shape через параметры геометрии, а не общий Transform.
- Согласовать общий механизм с Boolean Group и её владельцем оформления,
  не расширяя задачу автоматически на Text или SVG import/export.
- Сохранить HDR, alpha, ключи цветов, интерполяцию и независимость Fill/Stroke.
- Обновить вместе CPU/GPU-расчёт, handles, Properties, сохранение TIFF/JSON,
  Undo/Redo и агентские поля; не вводить полноразмерные промежуточные текстуры.
- Проверить смещённые и вытянутые контуры, кривые, составные фигуры, поворот,
  неравномерный scale, трансформированные группы, переключение типа и повторную
  подгонку. Сверить composite, group/Target, clipping, thumbnail и export.
- Диагностический график RGBA под `WHIMTEX_DEEP_DEBUG` уже добавлен отдельно;
  он не означает, что описанное здесь размещение реализовано.
