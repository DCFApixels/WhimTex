# T03. Фиксация include рабочей версии Shader и FX

- Цель: после открытия документа восстанавливать именно последнюю успешно скомпилированную программу вместе с её пользовательскими `#include`.
- Статус: отложено пользователем 2026-11-03. Риск выявлен по коду; сценарий в Unity пока не воспроизведён.
- Источники: [сохранение рабочей программы](../../src/ShaderProgram.cs), [подготовка программы](../../src/ShaderProgramRuntime.cs), [переносимый Code](../../src/WhimTexDocumentJson.ShaderGraph.cs), [раскрытие include](../../src/ShaderSourceBuilder.cs).

## Проблема

В режиме Code пользовательские include раскрываются для резервной копии при
сохранении. Если после успешной компиляции изменить подключённый файл, сохранённая
рабочая версия может отличаться от отображаемого результата. Удаление зависимости
может помешать сохранению, хотя скомпилированная программа ещё работает.

## Предлагаемое решение

- Фиксировать точное содержимое пользовательских зависимостей, использованных успешной компиляцией, включая вложенные include.
- Сохранять и восстанавливать рабочую версию из этой копии, без повторного чтения изменившихся внешних файлов при Save.
- Применить общий механизм к Shader-слою и FX; редактируемый исходник хранить отдельно. Неудачная компиляция не заменяет рабочую копию.
- Переиспользовать общую таблицу исходников и сжатие; системные include Unity остаются зависимостями движка.

## Проверка при возврате к задаче

Для Shader-слоя и FX: успешная компиляция → изменение либо удаление внешнего include
→ Save → полный перезапуск Unity → открытие TIFF без исходного пресета/файлов.
Результат должен совпасть с последней рабочей версией, а черновик остаться
редактируемым. Дополнительно проверить вложенные include и неудачную перекомпиляцию.
