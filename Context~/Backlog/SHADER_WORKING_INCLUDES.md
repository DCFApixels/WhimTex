# T03. Фиксация include рабочей версии Shader и FX

- Цель: после открытия документа восстанавливать именно последнюю успешно скомпилированную программу вместе с её пользовательскими `#include`.
- Статус: отложено пользователем 2026-11-03. Риск выявлен по коду; сценарий в Unity пока не воспроизведён.
- Приоритет: не блокирует релиз; вернуться при практической необходимости хранить Code с внешними зависимостями. Текущий рефакторинг ради T03 не расширять.
- Источники: [сохранение рабочей программы](../../src/ShaderProgram.cs), [подготовка программы](../../src/ShaderProgramRuntime.cs), [переносимый Code](../../src/WhimTexDocumentJson.ShaderGraph.cs), [раскрытие include](../../src/ShaderSourceBuilder.cs).

## Проблема

В режиме Code пользовательские include раскрываются для резервной копии при
сохранении. Если после успешной компиляции изменить подключённый файл, сохранённая
рабочая версия может отличаться от отображаемого результата. Удаление зависимости
может помешать сохранению, хотя скомпилированная программа ещё работает.

Условие риска: внешний include изменён или удалён **после успешного Compile**,
до Save либо пересоздания Runtime. Проверять нужно не только сохранение:
смена режима, Undo/Redo и перезагрузка редактора тоже могут потребовать
восстановления Runtime из Working. Это потенциальный сценарий, не подтверждённый баг.

## Что уже защищено и почему отложено

- Graph уже хранит функции и вложенные пользовательские include в `graph.sources`; компилятор раскрывает архив без чтения внешних файлов. После успешной компиляции сохраняется отдельный `workingGraph`, который сериализуется вместе с исходниками. Изменение исходного HLSL само по себе не заменяет эту рабочую копию; обновление источника проходит через Draft и Compile.
- Самодостаточный Code без внешних include этим риском не затронут. Различие относится к Code/Graph, а не к Shader-слою/FX: они используют общую программу.
- Документ хранит оба режима. Даже при активном Graph может оставаться неактивная Code-ветка с внешними include; её сохранение и последующее восстановление входят в T03.
- Системные include движка остаются внешними зависимостями. Архив не обещает идентичный результат после обновления Unity или встроенной шейдерной инфраструктуры.
- Пользователь решил отложить задачу: сценарий узкий, а доработка затрагивает Compile, сохранение и восстановление Working. Переизобретать шейдерную систему не требуется; объём и частота проблемы ещё не измерены.

Опора для Graph: [архив исходников](../../src/ShaderGraphSources.cs),
[компиляция функций](../../src/Layers/ShaderGraphCompiler.Functions.cs),
[копирование Working](../../src/ShaderProgramStorage.cs).

## Предлагаемое решение

- Фиксировать точное содержимое пользовательских зависимостей, использованных успешной компиляцией, включая вложенные include. Снимок должен соответствовать входу компилятора, а не повторному чтению файлов после компиляции.
- Сохранять и восстанавливать рабочую версию из этой копии, без повторного чтения изменившихся внешних файлов при Save.
- Применить общий механизм к Shader-слою и FX; редактируемый Draft хранить отдельно. Working и его зависимости заменять вместе только после успешной компиляции; ошибка сохраняет предыдущую рабочую копию.
- Сохранить разделение: `ShaderProgram` владеет Draft/Working, `ShaderProgramRuntime` — временными Shader/Material/bindings. Undo восстанавливает данные, Runtime создаётся из Working; генерируемый ShaderLab не заменяет редактируемые исходники.
- Переиспользовать общую таблицу исходников и сжатие, не создавать параллельное хранилище или второй компилятор.

## Проверка при возврате к задаче

Для Shader-слоя и FX: успешная компиляция → изменение либо удаление внешнего include
→ Save → полный перезапуск Unity → открытие TIFF без исходного пресета/файлов.
Результат должен совпасть с последней рабочей версией, а черновик остаться
редактируемым. Дополнительно проверить вложенные include и неудачную перекомпиляцию.
Отдельно проверить пересоздание Runtime, Undo/Redo, переключение Code/Graph и
сохранение активного Graph с неактивным Code, чей include изменён или удалён.
Уже пройденные проверки открытия без пресета не подтверждают этот сценарий:
важно изменение зависимости между Compile и последующим сохранением/восстановлением.
