# Анимация, время и кеш

- Назначение: сохранить дизайн управляемого времени, таймлайна, Animation Sheet, частиц и зависимостей кеша.
- Статус: F06, частично выполнено. Ограниченный этап времени просмотра Canvas, Play/Pause/Reset, перемотки и live API реализован. Сохранение времени/анимаций, полный таймлайн, Animation Sheet и частицы отложены.
- Источники истины: [время документа](../../src/WhimTexDocument.Playback.cs), [панель просмотра](../../src/WhimTexWindow.Playback.cs), [live API](../../Documentation~/LiveAgentAPI.md#preview-time-and-playback), [LayerRenderContext](../../src/Layers/Layer.cs), [EffectRenderCache](../../src/EffectRenderCache.cs). Предложения следующих этапов ниже не являются реализованным контрактом.

Дата обсуждения: 2026-09-25.

Позднее пользователь разрешил ограниченный этап управляемого времени просмотра. Остальные
предложения этой карточки остаются дизайном для будущих запросов.

## Выполнено

- В FX, HLSL-нодах и Custom Function доступны `_WhimTexTime` и `_WhimTexInstanceIndex`; значения передаются на каждый расчёт без глобального shader state. Нода Time возвращает `Start + time * Scale`.
- Скомпилированные графы/FX сообщают зависимости через `UsesTime` / `UsesInstanceIndex` в C#. Анализ библиотек консервативный; использование времени не меняет pixel-local статус.
- Один отсчёт времени редактора обновляет видимые зависимые превью нод и результат графа, включая его FX. Часы Graph editor остаются независимыми от нового времени Canvas. Течение времени не создаёт Undo и не меняет документ.
- Контракт и границы: [ShaderFX](../../Documentation~/ShaderFX.md#evaluation-time-and-instance-index), [Shader layer](../../Documentation~/ShaderLayer.md).
- Время просмотра Canvas, Play/Pause/Reset, перемотка и отдельный live API реализованы.

## Текущий этап: время просмотра (реализовано)

- `WhimTexDocument.PreviewTime` — `double`, `IsPlaying` — `bool`; состояние общее для
  представлений одного документа, не сериализуется. После open/reload — `0`, paused.
  Закрытие окна или смена документа ставит проигрывание покидаемого документа на паузу.
- `SetPreviewTime(double seconds)` принимает конечные `0..float.MaxValue`; некорректное
  значение бросает `ArgumentOutOfRangeException`. `SetPlayback(bool)` не сбрасывает время.
  Ни проигрывание, ни пауза, ни перемотка не создают Undo, dirty или content revision.
- Внутренние `TimeRevision` (`ulong`) и `TickPlayback(double editorNow)` обслуживают окно.
  CPU-время вычисляется от начала проигрывания в double без покадрового накопления;
  shader получает float. Обновление просмотра — до 30 раз в секунду, это не FPS анимации.
- Штатная панель Canvas содержит Play/Pause, Reset, DoubleField **Time** в секундах и
  slider. Начальный диапазон slider — 0..10; при выходе он расширяется автоматически,
  не задавая длительность. Reset ставит на паузу и возвращает 0.
- User Settings → Experimental → Show Timeline скрывает панель и ставит проигрывание
  на паузу, сохраняя время. Предпочтение сохраняется между сеансами; по умолчанию выключено.
- Время одного расчёта Canvas передаётся всем зависимостям, включая группы, Target и
  ссылки на слои. Собственные часы Graph editor в этот этап не объединяются с Canvas.
- В документах с Time-зависимостями preview cache сохраняет также статические процедурные
  генераторы без FX, включая Noise/Gradient/Shape. Действует прежний бюджет кеша;
  недорогие File/Drawing дополнительно не дублируются. Save/default render cache не изменён.
  Статический inspector preview не обновляется по времени; косвенная зависимость через вход учитывается.
- Save, обычный export и default renders используют только `t=0`. Live Update
  импортированной текстуры тоже использует 0 и не публикует временные кадры.
- `LiveJson/LiveFile`, `op:"playback"`, явный `sessionId`: без setters читает состояние,
  `previewTime` и/или `isPlaying` меняют только время просмотра открытого документа.
  Все поля проверяются заранее; Play/Pause применяется перед seek для точного результата
  «пауза + время». Session discovery и live inspect также возвращают оба значения.
  Это не document edit, batch operation, job или сохраняемый receipt. Схема —
  [`livePlayback`](../../Documentation~/AI/agent-fields.schema.json#/$defs/livePlayback).
- Нет файлового render-at-time, Bake, сохранения времени/анимаций, ключей/кривых,
  длительности, loop или FPS. Эти возможности не следуют автоматически из Play/Pause.

## Оставшаяся задача

В перспективе WhimTex должен поддерживать создание анимаций, анимированные шейдеры
и отдельный слой системы частиц. При проигрывании зависимые слои, FX, группы,
маски и итоговая композиция должны корректно обновляться.

Главный принцип: анимация не отменяет детерминированность и кэширование.
Время становится явным управляемым входом расчёта, а не внешним глобальным состоянием.

## Историческая реализация до текущего этапа

- `src/Layers/Layer.cs`: `LayerRenderContext` не содержит времени документа.
- `src/ShaderSourceBuilder.cs`: встроенные временные входы Unity вызывают предупреждение.
  Это предупреждение, а не механизм заморозки времени в шейдере.
- `src/EffectRenderCache.cs`: FX с неподдерживаемыми временными входами отключают
  кэширование соответствующих зависимостей. Уже учитываются входы слоёв, группы,
  Target, ссылки FX на слои, clipping, изменения текстур и GPU Drawing.
- `src/WhimTexDocument.EffectCache.cs`: интерактивный расчёт переиспользует подходящий
  качественный результат, если он уже есть в кэше. Это поведение сохранить.
- CRT/VHS используют обычный параметр `_EffectTime`; это ручное время, не таймлайн.
- Окно использует время Editor для планирования preview, но не как время документа.

Эти наблюдения описывают исходное состояние, а не текущий код. Действующий ограниченный
контракт указан выше; перед следующим этапом перечитать реализацию.

## Предложения для расширения времени

Уточнение пользователя от 2026-10-17: сохранить в беклоге необходимость системы
времени именно для создания анимаций. Связанное новое требование —
[F27: экземпляры слоёв и Instance Index](LAYER_INSTANCES.md): при повторении
слоя его эффекты и генераторы смогут использовать индекс экземпляра для
вариаций Seed. Время и индекс — отдельные входы: проигрывание само по себе
не должно скрыто менять Seed. Детальный контракт расширений ещё не утверждён;
текущее время просмотра имеет отдельный ограниченный контракт выше.

Дополнительная идея пользователя от того же обсуждения: Time и Instance Index
используются как в свойствах слоя, так и в FX, которым нужен общий интерфейс
входных параметров для чтения этих значений. Предлагается определять реальные
зависимости и разделять результаты независимых повторов; подробности —
[идеи общих входов и оптимизации F27](LAYER_INSTANCES.md#дополнительные-идеи-пользователя-общие-входы-и-оптимизация).
Для HLSL выбраны встроенные `_WhimTexTime` / `_WhimTexInstanceIndex` и контекст каждого расчёта; привязки свойств слоя остаются открытыми.

- Единый контекст расчёта содержит время документа, при покадровом расчёте также номер
  кадра и частоту кадров, а также режим качества. На CPU время желательно хранить
  с двойной точностью; точное соответствие кадра времени определить отдельно.
- Контекст фиксируется один раз на весь расчёт изображения и передаётся во все
  ветки композиции, включая группы, Target и ссылки FX на другие слои.
- В будущем окно, headless/агентский API и экспорт смогут использовать общий путь «вычислить на момент t».
  Сам рендер не зависит от наличия окна или частоты его перерисовки.
  Текущий этап не предоставляет файловый API времени; default renders и экспорт остаются на 0.
- Шейдер получает управляемое время, условно `_WhimTexTime`. На паузе оно стоит,
  при перемотке принимает выбранное значение. Разрешённый с предупреждением
  глобальный Unity `_Time` не заменяет этот вход: он не синхронизирован с документом.
  Для поддержки анимации нельзя просто снять это предупреждение: требуется
  синхронизация с управляемым временем документа.
- Временную зависимость FX следует объявлять явно; один поиск токена в исходнике
  недостаточен, поскольку время может использоваться через include.
- Анимированные значения параметров вычисляются отдельно от сохранённых базовых
  значений. Не переписывать сериализованные параметры, включая `_EffectTime`, каждый кадр.
- Проигрывание, пауза и перемотка не создают Undo и не помечают документ изменённым.
  Редактирование кривых, ключей и настроек анимации меняет документ и поддерживает Undo.
- Статическая композиция не должна меняться от добавления контекста времени; предложенное значение по умолчанию: 0. Это требование к текущему результату, не обещание чтения старых форматов.

## Спрайтовая анимация и Animation Sheet

Требования пользователя от 2026-10-09:

- Создавать Animation Sheet как единую текстуру атласа через [F09](WHIMTEX_IMPORTER.md), при необходимости нарезанную на Sprite.
- Управлять анимацией через [параметры документа F02](DOCUMENT_PARAMETERS.md): например, связать поля слоёв и FX с параметром `Time`.
- Добавить временную шкалу и просмотр результата анимации прямо в WhimTex.

Предложенная модель: пользователь явно назначает параметру роль времени
таймлайна. Имя `Time` — пример, не зарезервированное имя и не способ обнаружения
времени. Таймлайн, привязки полей и возможный управляемый shader uniform получают
одно значение из общего контекста кадра. Не вводить параллельные часы для этих путей.

Предлагаемый будущий таймлайн: Play/Pause, перемотка, текущий кадр, длительность, FPS,
диапазон Bake и Loop для просмотра. Ключи и кривые не обязательны для первого
этапа анимации, уже вычисляемой слоем или FX из времени. Loop повторяет диапазон,
но сам по себе не делает изображения на его границе бесшовными.

Preview и запекание используют общий путь:
`время кадра → эффективные параметры → выбранный Output → изображение`.
[Outputs в F09](WHIMTEX_IMPORTER.md#выходы-документа) определяют источник результата;
не нужно дублировать рендер документа для нового экспортного режима.

Предлагаемый первый формат — равномерная сетка кадров с одинаковым размером
и общим pivot, без индивидуальной обрезки. Она подходит для последовательности
Sprite и flipbook в шейдере. Плотная упаковка — возможное расширение с отдельными
прямоугольниками кадров и сохранением их исходного размещения.

Кадры рассчитываются последовательно с фиксированным шагом; значения времени
не зависят от скорости проигрывания preview. Правила начала/конца диапазона и
соответствие номера кадра времени определить явно, включая отсутствие лишнего
дублированного последнего кадра при зацикливании.

Полный Animation Sheet предлагается пересчитывать отдельной командой Bake,
а не при каждом Save. Сохранять подготовленный результат и показывать его
устаревание после изменения зависимостей. Импортёр собирает атлас и Sprite из
готовых кадров; пересчёт документа и импорт результата остаются разными операциями.

Предусмотреть отмену, бюджет памяти, размер листа, padding и несколько листов
при превышении лимитов. Не держать все полноразмерные кадры одновременно в GPU.
При отмене или ошибке предыдущий успешно запечённый результат не теряется.
Хранение кадров и метаданных Bake ещё не выбрано.

Слой частиц не нужен для первого этапа. [F04](LAYER_UPDATE_DESIGN.md) тоже
не является условием запуска анимации, но при его появлении нужно явно определить
поведение On Refresh: нельзя скрыто пересчитывать ручной результат каждый кадр.
Возможные режимы такого запекания требуют согласования.

## Кэш и зависимости

Различать собственную зависимость от времени, зависимость от изменившегося входа
и полностью статическую ветку. Время включается в подпись только там, где оно
влияет на результат; далее изменения распространяются по обычным зависимостям.

Пример: `Частицы(t) → Blur → Outline → композиция`. Все эти зависимые результаты
обновляются, но независимый статический фон не теряет действительный кэш.
В текущем preview cache документов с Time-зависимостями сохраняются и статические
процедурные источники без FX, включая Noise/Gradient/Shape. Бюджет остаётся прежним;
недорогие File/Drawing дополнительно не дублируются. Это расширение относится только
к preview: Save/default render cache не изменён.

- Повторный запрос того же времени и тех же входов должен позволять повторное
  использование результата. Качество, разрешение и остальные параметры рендера
  остаются частью проверки пригодности кэша.
- Для stateful-источника учитывать версию/состояние симуляции: одинаковое время
  само по себе недостаточно после изменения seed или настроек системы.
- Сохранить повторное использование финального качества в интерактивном режиме.
- Не хранить неограниченную последовательность полноразмерных кадров.
  Результаты и снимки симуляции должны иметь ограниченный бюджет памяти.

Потенциальное узкое место: текущий расчёт подписей сериализует слои и FX через
`JsonUtility.ToJson`. При непрерывном проигрывании это кандидат для профилирования
CPU/GC. Желательно разделить ревизии настроек, вычисленные значения анимации
и изменения входных изображений, не сериализуя неизменившиеся настройки каждый кадр.
При оптимизации обязательно сохранить инвалидирование для Undo/Redo, внешних
ресурсов, перекомпиляции FX и GPU-рисования; одного dirty-флага недостаточно.

## Частицы и перемотка

Обычный анимированный шейдер может сразу вычислить изображение на момент t.
Система частиц обычно требует истории симуляции, поэтому ей нужен отдельный lifecycle:

- управляемый seed, сброс и фиксированный шаг симуляции;
- движение вперёд через последовательные шаги;
- движение назад через сброс и повторную симуляцию либо ограниченные снимки состояния;
- независимость шага симуляции от FPS preview и частоты экспорта: пропуск показанного
  кадра не должен произвольно пропускать необходимые шаги симуляции;
- инвалидирование состояния при изменении настроек и зависимостей.

Слой выдаёт обычную RGBA-текстуру, далее работают общие FX, маски и композиция.
Не создавать скрытых специальных выходов для отдельных пресетов.
Симуляция должна быть изолирована от пользовательской сцены. Обратную связь из
последующих эффектов в симуляцию не вводить неявно: это отдельный контракт истории/циклов.

Если выбран Unity `ParticleSystem`, публичные API дают ручное продвижение и seed:
[Simulate](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/ParticleSystem.Simulate.html),
[randomSeed](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/ParticleSystem-randomSeed.html).
Это основа для воспроизводимого проигрывания в контролируемых условиях, но не
обещание побитовой идентичности на всех платформах и версиях Unity.

## TIFF и экспорт

- На текущем этапе основное изображение TIFF, обычный экспорт и Live Update всегда
  используют `t=0`. Выбор другого сохраняемого кадра возможен только после отдельного согласования.
- Данные анимации в документе не превращают обычную импортированную Unity-текстуру
  в автоматически проигрываемую анимацию.
- Последовательность кадров, атлас и опциональные Sprite теперь входят в обсуждённый
  дизайн Animation Sheet выше. Runtime-проигрыватель и автоматическое создание
  AnimationClip остаются возможными расширениями, не обязательной частью первого этапа.
- Новые сохраняемые данные проектировать с явной версией формата. После 0.13.0
  совместимость со старыми документами не обязательна; применяется
  [действующая политика](../../AGENTS.md#identity-and-compatibility). В рамках записи дизайна
  структура TIFF и версия формата не меняются.

## Следующие этапы (отложены)

1. Выполнить оставшиеся ручные проверки native gestures и реального restart Editor.
2. Согласовать сохраняемые настройки анимации, связь с F02, длительность, FPS и loop.
3. Отдельно согласовать файловый расчёт заданного кадра, диапазон и хранение Bake Animation Sheet через F09.
4. Частицы и синхронизацию часов Graph editor проектировать отдельными запросами.

## Открытые вопросы

- Для последующего этапа частиц: слой отрисовывает существующий Unity `ParticleSystem`
  или это собственная система частиц с настройками внутри WhimTex?
  Предварительно предложено начать с Unity `ParticleSystem`, но пользователь
  ещё не выбрал этот вариант.
- Набор анимируемых свойств, привязка параметров к времени, длительность, FPS,
  loop и локальное время слоёв пока не согласованы.
- Роль параметра времени, единицы, sampling кадров, общий pivot, максимальный размер
  листов, метаданные и хранение Bake; сохранение ссылок Sprite при переимпорте.
- Поведение анимации при On Refresh и будущий выбор основного кадра/выхода TIFF; сейчас всегда `t=0`.
