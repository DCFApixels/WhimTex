# Векторные шумы и карты искажения

- Назначение: сохранить дизайн расширения Noise и способы использования шумов для distortion-карт.
- Статус: отложено пользователем; предварительный дизайн, не поручение на реализацию. Новые поля представлены только отдельным UI-прототипом.
- Источники истины: текущие [NoiseLayerBehaviour](../src/Layers/NoiseLayerBehaviour.cs), [Noise shader](../src/Shaders/Noise.shader), [Displacement Map](../src/FXPresets/DisplacementMap.hlsl), [HDR-контракт](../Documentation~/HDR.md). Предложения ниже не описывают уже реализованные алгоритмы.

Обсуждение отложено 2026-10-08. Цель — получать осмысленные направления для
искажения текстур и других vector-data задач, сохраняя понятный общий набор настроек.

## Направление дизайна

Расширить существующий Noise выбором `Field`, а не создавать отдельный слой для
каждого векторного алгоритма. `Noise Type` выбирает основу расчёта и показывает
только подходящие варианты.

| Field | Результат | Основы в текущем UI-прототипе |
| --- | --- | --- |
| Value | Обычный скалярный шум; у White/Blue также цветное зерно | Все существующие типы |
| Curl | Согласованные закручивающиеся направления | OpenSimplex2, OpenSimplex2S, Perlin |
| Gradient Vector | Направление и величина изменения скалярного шума | OpenSimplex2, OpenSimplex2S, Perlin, ValueCubic, Value |
| Cell Direction | Вектор к ближайшему центру ячейки; инверсия направляет от центра | Cellular, фиксированная основа |

Пользователь не считает три независимых скалярных шума достаточным основанием
для отдельного нового вида шума: такой результат можно собрать несколькими слоями
с разными Seed, Channel Mapping и наложением. Однако сами независимые каналы полезны для
distortion-карт и не заменяются Curl.

White/Blue Noise остаются отдельной группой со своими правилами. Не требуется
навязывать зерну Fractal, Domain Warp или все настройки гладких шумов ради унификации.

## Общие параметры и видимость

- Сохранять общие Seed, Scale, Offset, Dimensions и существующие правила Seamless.
  Scale/Offset показывать по размерности; связанные оси менять пропорционально.
- Для векторных полей предлагать 2D и 3D. В 2D `Z = 0`; в 3D изображение остаётся
  двумерным срезом поля с XYZ-компонентами, а не объёмной текстурой.
- Fractal и его Octaves, Lacunarity, Gain, Weighted Strength должны по возможности
  быть общими у Value, Curl и Gradient Vector. Пользователь отдельно попросил
  не делать Weighted Strength уникальным параметром Value: различия увеличивают
  когнитивную нагрузку. В прототипе он уже общий.
- У Cell Direction Fractal скрыт: смешивание нескольких ближайших центров
  перестаёт означать направление к одному центру. Cellular Return также скрыт;
  Distance и Jitter остаются.
- Domain Warp доступен Value, Curl, Gradient Vector и Cell Direction, но не зерну.
  У Cell Direction нужно определить согласованность центров и направлений после Warp.
- Скрытые параметры сохраняются при переключениях. Параметры, применимые сразу
  к нескольким Field, не должны становиться независимыми копиями без необходимости.

В прототипе векторный Fractal пока ограничен `None` и `FBm`. Позже обсуждалось
расширение на `Ridged` и `PingPong` через преобразование скалярного потенциала;
в UI это ещё не добавлено. Эти режимы создают изломы производной, поэтому их
художественное качество нужно проверить, а не обещать идентичную гладкость.

## Вывод векторов

- `Packed Vector`: линейные `RGB = XYZ * 0.5 + 0.5`; нулевой вектор даёт
  `(0.5, 0.5, 0.5)`. При величине вектора больше единицы результат может выходить
  за 0–1; не вводить неявное обрезание.
- `Signed Vector`: линейные `RGB = XYZ`, включая отрицательные компоненты.
- У обоих вариантов Alpha по умолчанию 1; гамма-преобразование не применяется.
- Необязательный `Normalize`, по умолчанию выключен, затем `Strength`.
  Нулевой вектор должен оставаться нулём, а не превращаться в случайное направление.
- Scalar Output остаётся `Color Values`, `Linear Data` или `Gradient`;
  палитра относится к скалярному выводу, не к кодированию вектора.

`Reverse` и `Inverted` обсуждались как один флаг с разным смыслом по типу данных:
скаляр 0–1 превращается в `1 - value`, signed-вектор — в `-vector`.
Для packed-вектора это тоже `1 - RGB`. Предложено единое название `Inverted`
с контекстной подсказкой, но переименование не выполнено: прототип ещё показывает
`Reverse` у векторов.

## Требования к расчёту

Curl строить из производных потенциала, а Gradient Vector — из производных
скалярного поля. Scale, Fractal и Domain Warp должны участвовать в функции,
производные которой вычисляются. Простое искажение уже готовой RGB-карты векторов
не эквивалентно этому расчёту.

Ненормализованный Curl может иметь свойство отсутствия дивергенции в непрерывной
постановке. Normalize обычно его нарушает; дискретизация, фильтрация и способ
интеграции также важны. Обычное одношаговое UV-смещение по Curl не гарантирует
сохранения площади и не является симуляцией жидкости.

Для Cell Direction отдельно определить систему координат и метрику ближайшей
ячейки, особенно при неравномерном Scale и Domain Warp. Векторы должны соответствовать
той структуре ячеек, которую пользователь видит.

## Что уже умеет рендер WhimTex

Signed RGB проходят через float-буферы, HDR-наложение и вход Shader Processor.
`Color Range = HDR` сохраняет собственный вывод слоя, `Blend Range = HDR`
вычисляет расширенные формулы наложения в линейном пространстве. Общий пресет HDR
устанавливает оба. Изолированная группа тоже может обрезать результат собственным
Color Range; Pass Through не добавляет эту границу. Alpha остаётся в 0–1.

Shader Processor получает композицию нижележащих слоёв, а не экранное отображение;
новые процессоры уже создаются с обоими диапазонами HDR. Отдельные FX могут сами
применять `saturate`, `abs` или другие преобразования, поэтому signed-данные не
гарантированы через произвольный эффект. См. [вход процессора](../src/WhimTexDocument.Processor.cs)
и [его defaults](../src/Layers/ShaderProcessorLayerBehaviour.cs).

Текущий скалярный Noise переводит результат в 0–1 через `saturate(raw * 0.5 + 0.5)`.
`Linear Data` отменяет цветовое преобразование, но не означает signed-вывод.
HDR сохраняет отрицательные значения, а не создаёт их вместо генератора.

## Старые шумы для distortion-карт

1. Два независимых Noise с разными Seed записать в R и G. R задаёт X-смещение,
   G — Y-смещение. Perlin/OpenSimplex подходят для плавных случайных искажений;
   Value/ValueCubic дают другой характер областей. Это не Curl, но полноценный
   художественный инструмент.
2. Один скалярный шум использовать как силу смещения в выбранном направлении.
   В Displacement Map уже есть Horizontal, Vertical, Angle, Radial и Tangential.
   Tangential вокруг общего центра не превращает скалярный шум в Curl.
3. Шум использовать как высоту, получить Normal Map и взять RG нормали.
   Тогда искажение связано с наклонами рельефа, а не непосредственно с яркостью.
   Нормализованная нормаль не равна исходному Gradient Vector по величине.
4. Cellular CellValue даёт кусочно-постоянные смещения ячеек; Distance-варианты
   связывают деформацию с их формой. Цветные White/Blue дают зернистые смещения;
   увеличенный Grain Size делает их блочными. Это ожидаемый художественный характер,
   не утверждённые визуальные эталоны.

У Displacement Map уже есть `VectorRG` и `Grayscale`. В VectorRG используется
`(RG - Neutral) * 2 * StrengthXY`; для packed-карты нейтральное значение 0.5.
Одинаковый скаляр в R и G при равной силе даёт только диагональное направление.
Цветная палитра одного скаляра не создаёт независимость направлений автоматически.
Для числовых карт выбирать `Linear Data`, а не Color Values.

Signed-карта требует согласовать декодирование с потребителем: текущая формула
Displacement Map при Neutral 0 удваивает исходный вектор. Можно компенсировать это
Strength либо позже явно разделить signed/packed encoding; такого переключателя сейчас нет.

Дополнительная идея, не принятое расширение Field: выводить собственный вектор
Domain Warp как `warpedPosition - originalPosition`. Он уже вычисляется внутри
генератора, но отдельный вывод карты пока не реализован. Это ещё один согласованный
источник смещений, не три независимо рассчитанных цветовых канала.

## UI прототип и возвращение к задаче

В проекте, вне пакета, сохранён [NoiseFieldUiWindow](../../../Assets/NoiseFieldUiPrototype/Editor/NoiseFieldUiWindow.cs)
с UXML/USS рядом. Открывается через `Window → Experiments → Noise Field UI`.
Это только настройки и условная видимость, без генерации изображения и без интеграции
в WhimTex. Состояние открытого окна не является сохранённой спецификацией алгоритмов.

При возвращении сначала сверить текущий код и прототип с этим дизайном. Затем
уточнить векторные Fractal, Cell Direction с Warp и декодирование signed-карт.
Перед интеграцией сравнить реальные рендеры: плавное независимое RG, Curl,
Gradient Vector, Cell Direction и зерно. Проверить нулевые векторы, Normalize/Strength,
2D/3D, Seamless, HDR, группы и вход Shader Processor. Проверки UI не подтверждают
качество или математические свойства будущего генератора.
