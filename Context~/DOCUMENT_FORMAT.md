# Формат документа WhimTex

Статус: контейнер реализован и проверен; сериализация модели и интеграция с редактором — не начаты.
Здесь только проверенные факты и контракт, а не план релиза.

## Задача

Документ должен быть одним файлом с одним `.meta`, который:

- редактируется в WhimTex как слоёный документ (аналог PSD: слои, группы, blending, FX);
- распознаётся Unity как обычная текстура со **штатным** инспектором текстуры;
- поддерживает компрессию, mipmap, нарезку спрайтов и **платформенные overrides**;
- не ломает текстуру в рантайме и не тащит данные документа в билд;
- сохраняет режим Live Update.

## Почему именно так

`TextureImporter` работает по расширению файла и владеет `.meta`. Overrides — это
`TextureImporterPlatformSettings`, штатный инспектор — редактор `TextureImporter`. Свой
`ScriptedImporter` не даёт ни того, ни другого, а на одном файле не могут работать два импортёра.

Отсюда единственная схема, удовлетворяющая всем требованиям одновременно:
**документ сам является настоящим файлом-изображением с нативным расширением**, его пиксели —
готовая композиция (её читает Unity), а слоёная часть лежит в необязательной секции, которую Unity
игнорирует. Структурно это PSD: слоёный блок + сплющенный результат в одном файле, только слоёный
блок наш и читает его WhimTex.

## Проверено на Unity 6000.7 (Direct3D12)

Спайки выполнялись разовыми скриптами в проектной `Temp/` (временная папка Unity, не часть репозитория).
Воспроизводимая проверка всех существенных фактов — `Tests~/DocumentContainerSmoke.cs`.

- PNG с приватным ancillary-чанком импортируется штатным `TextureImporter` без ошибок и предупреждений.
- Unity **не перезаписывает исходный файл** ни при импорте, ни при реимпорте, ни при смене платформы.
- После перезаписи содержимого файла сохраняются: тип текстуры, `spriteBorder`, `spritePixelsPerUnit`,
  mipmap, Read/Write, **платформенные overrides** (`Android` → `ASTC_6x6`, `maxTextureSize`) и
  мультиспрайтовая нарезка с индивидуальными border'ами спрайтов.
- Сохраняются идентичность объекта: `GetEntityId`, GUID, `localFileID` и ссылка на текстуру в материале.
- EXR: Unity импортирует файл с добавленными в конец данными, HDR-значения (>1) доходят до BC6H,
  ни заголовок, ни таблицу смещений патчить не нужно.
- Замеры на 4096² RGBA32 (пустое содержимое): `EncodeToPNG` 389 мс, запись 54 мс, импорт 192 мс.
- **Отрицательный результат, важный для реализации:** некорректно собранный PNG был молча импортирован,
  но спрайтовые сабассеты при этом потерялись. Поэтому писатель обязан валидировать свой вывод
  (парсить собственный файл) до замены оригинала.

## Live Update на новом носителе

Проверено спайком, воспроизводится последними проверками `Tests~/DocumentContainerSmoke.cs`:

- `Reinitialize` переводит импортированную текстуру (DXT1) в `RGBA32`, сохраняя тот же объект,
  `GetEntityId` и ссылку в материале.
- Перезапись файла и реимпорт **сохраняют идентичность и ссылки**: тот же entity, материал видит новые
  пиксели, Read/Write из `.meta` сохраняется, документ в файле читается.
- Но реимпорт **возвращает импортированное (сжатое) представление**: рабочая несжатая поверхность
  теряется. Значит сохранение обязано завершать сессию до реимпорта и при необходимости открывать её заново
  (`Reinitialize` + `Apply`), а не пытаться сохранить переключение сквозь реимпорт.
- Обратное включение mip-цепочки через `Reinitialize` работает (64×64 → 7 уровней).

## Носитель

Расширение обязано быть нативным: `.png` для LDR, `.exr` для HDR/float. Имя — `Name.whimtex.png`
(расширение оставляет нативный импорт, имя говорит, что это документ).

- **PNG**: чанк `whTX` вставляется непосредственно перед `IEND`. Длина и CRC — big-endian (ошибка здесь
  уже была допущена и поймана тестом).
- **EXR**: полезная нагрузка дописывается после последнего пиксельного чанка; в конце — `int64` длина и
  8 байт магии `WHIMTEXD`.

## Контейнер

Реализация: `src/WhimTexDocumentContainer.cs`. Тест: `Tests~/DocumentContainerSmoke.cs` (37 проверок).

```
WHIMTEXD            8 байт магии
int32               версия формата (1)
int32               число блоков
блок[]              int32 длина имени, имя UTF-8, int32 сжатие (0/1), int64 исходный размер, int64 размер в файле
данные блоков       подряд, в порядке таблицы
```

- Каждый блок сжимается отдельно (`DeflateStream`); если сжатие не уменьшило блок, он хранится как есть.
- Блоки читаются лениво: ненужный блок пропускается по размеру в файле без распаковки.
- Лимиты: 65536 блоков, 8 ГиБ суммарно, имя до 512 байт; проверяются до выделения памяти.
- Имена блоков: `document` — сериализованная модель, `pixels:<layerId>` — пиксели рисовального слоя.
- Запись только атомарная: временный файл, `Flush(true)`, затем `File.Replace`. `.meta` не трогается
  никогда — в нём живут настройки импорта, нарезка и overrides. Сбой записи не портит предыдущий документ.
- Версия формата несовместима — отказ, **миграций нет** (явное требование).

## Сериализация модели

Реализация: `src/WhimTexDocumentSerializer.cs`, обёртка файла — `src/WhimTexDocumentFile.cs`,
тест `Tests~/DocumentRoundTripSmoke.cs` (32 проверки, композиция после цикла совпадает бит-в-бит).

Обход идёт по сериализуемым полям каждого типа, поэтому все 14 поведений и будущие поля покрываются
без ручных писателей. Проверено на документе из рисовального слоя с нарисованными пикселями, группы
с дочерним слоем, поворотом и прозрачностью, обводки, нацеленной на рисовальный слой, и встроенного FX.

Правила, добытые практикой — нарушение любого ломает документы молча:

- **`[SerializeReference] private` — уже сериализуемое поле.** Unity пишет такие поля без
  `[SerializeField]`, и на этом держится полиморфизм поведений: фильтр «`[SerializeField]` или public»
  теряет `Layer.behaviour` целиком.
- **Идентичность объектов обязательна.** Один и тот же FX лежит и в `modifiers` слоя, и в списке
  встроенных: без отслеживания ссылок он восстановится двумя копиями и потеряет связь со слоем.
  Идентификаторы ссылок должны присваиваться в одном порядке и для объектов, и для встроенных текстур.
- **`isDataSRGB` и аргумент `linear` конструктора — противоположные вещи.** Хранить нужно второй.
- **Текстуры принадлежат слоям.** `GetPreviewTexture` возвращает текстуру слоя: её нельзя уничтожать,
  иначе слой перестаёт рендериться (эта ошибка была допущена в тесте и выглядела как потеря слоя после загрузки).
- **Числа с плавающей точкой двойной точности хранятся как `double`**, а не как `float`: трансформы и
  проективные матрицы иначе теряют точность.
- **Enum хранится по имени**: в модели есть enum с непоследовательными значениями.
- Производное состояние (`compiledShader`, применённый код, кеши, `outputTexture`, `sliceOutputs`)
  не хранится и восстанавливается: шейдеры встроенных FX компилируются заново при загрузке.

## Что ещё не сделано

1. **Интеграция с редактором:** открытие документа по двойному клику (`[OnOpenAsset]` с проверкой
   наличия блока документа), сохранение через окно, dirty/Undo/domain reload, несколько окон,
   `SaveAs`. Пока окно продолжает работать со старым путём `.asset`, поэтому новый формат доступен
   через API (`WhimTexDocumentFile.Save/Load`), но не из интерфейса.
2. **Замена старого пути.** Окно, `WhimTexApi` и экспортёры продолжают опираться на
   `AssetDatabase.Contains(compositor)`, путь `.asset`, сабассеты и `SetDirty`. Пока это так, новый
   формат сосуществует со старым, а не заменяет его.
3. **Live Update на новом носителе:** сессия, временный Read/Write без грязного `.meta`,
   согласование с сохранением (перезапись файла переимпортирует текстуру и сбрасывает несжатое
   представление — правило порядка установлено выше).
4. **Судьба `OutputSettings`:** компрессия, mipmap, wrap, aniso, нарезка и overrides переезжают в штатный
   инспектор; решить, что остаётся в своём окне.
5. **Sprite-провайдер:** свой `WhimTexSpriteDataProvider` для документа нужен только потому, что сейчас
   текстура — сабассет; у импортированного PNG работает штатный редактор спрайтов.
6. **Проверка в билде:** overrides дают платформенный вариант, данные документа в билд не попадают
   (исходный файл в сборку не включается — попадает только импортированный артефакт).
7. **Документация** EN/RU/ZH, когда появится пользовательский сценарий.

## Принятые решения

| Решение | Причина |
| --- | --- |
| Нативный носитель вместо своего расширения | иначе нет штатного инспектора и overrides |
| Монолитный PNG/EXR вместо ZIP | файл обязан быть изображением; ZIP не даёт ни того, ни другого |
| Композиция = пиксели файла | её и импортирует Unity; отдельное хранение не нужно |
| Внешние редакторы не поддерживаем | явное требование: формат читает только пакет |
| Миграций нет | явное требование: старые `.asset` не переносим |
| Атомарная запись обязательна | файл — одновременно документ и поставляемая текстура |
