# Формат документа WhimTex

Статус: экспериментальная ветка с сохранением, открытием, сериализацией модели и Live Update.
Это контракт текущего кода, не утверждение о готовности релиза.

## Файл и импорт

- Один `Name.whimtex.tiff` и его обычный Unity `.meta`.
- Пиксели TIFF — готовая композиция; после них находятся контейнер модели и пиксели Drawing.
- Нативный `TextureImporter` предоставляет Inspector, mipmaps, компрессию, Sprite Editor и platform overrides.
- `outputPrecision` (`WhimTexOutputPrecision`, default Auto): Auto выбирает 8 бит на канал для LDR
  и RGBA float32 для HDR/отрицательных значений; EightBit явно квантует/обрезает только composite;
  Float32 сохраняет fine values внутри 0–1. Поле есть в canvas toolbar временных/TIFF-документов,
  поддерживает Undo и tagged serialization. Рабочая композиция остаётся half-float — Float32 не повышает её точность.
  Расширение и GUID при переходе между LDR/HDR не меняются.
- При первом LDR-сохранении линейный RGB кодируется в sRGB; **альфа всегда линейная**.
  Последующие LDR-сохранения учитывают sRGB импортёра. HDR TIFF хранится линейно и отключает sRGB.
  Возвращение в LDR сохраняет выбранный импортёром режим.
- `carrier` содержит флаг кодирования. Первый импорт читает только footer, таблицу блоков и этот флаг.
  Чужой `userData` сохраняется; маркер WhimTex дописывается к нему.
- Слоистые PNG/EXR удалены: ни чтения, ни записи, ни миграции. Обычный экспорт изображения остаётся.
- TIFF нельзя пересохранять внешним графическим редактором: дополнительные данные документа могут исчезнуть.
- Старый `.asset`-путь остаётся отдельным механизмом; настройки встроенного output не управляют TIFF-импортёром.
- Output выбирает TIFF для штатного Inspector Unity. Отдельное окно настроек оставлено только legacy-ассетам.

Реализация: `WhimTexTiffImage`, `WhimTexTiffCarrier`, `WhimTexDocumentFile`,
`WhimTexDocumentPostprocessor`.

## Контейнер

```
TIFF: заголовок, каталог, zlib-полосы изображения
WHIMTEXD + int32(version=1) + int32(blockCount)
таблица всех блоков:
    int32(nameUtf8Length), nameUtf8, int32(compression), int64(rawLength), int64(storedLength)
данные всех блоков в порядке таблицы
int64(containerLength) + WHIMTEXD
```

Таблица и данные — **раздельные последовательности**, не чередующиеся записи.
Compression 0 = исходные байты, 1 = raw Deflate. TIFF-полосы используют zlib с Adler32.
Блоки контейнера распаковываются по запросу; модель затем запрашивает принадлежащие ей текстуры.
Потоковый загрузчик читает только каталог и востребованные блоки, не загружает весь TIFF/контейнер в byte[].
При чтении Drawing проверяется SHA и распаковывается только текущий pixel block; соседние блоки
не предзагружаются, чтобы не удерживать несколько больших raw-массивов одновременно.
256 МиБ на пакет (первый блок допускается отдельно). Stream seek/read защищены lock, проверка/распаковка
параллельны; Unity Texture2D создаются только main thread. При Open TIFF Drawing хранит метаданные
блока и материализует Texture2D при первом обращении из рендера, превью, редактирования или Save.
Если файл изменился после открытия, отложенная загрузка отклоняется и требует переоткрыть документ.
Новые контейнеры содержат `integrity:sha256`: count + BinaryWriter string(name) + 32 байта SHA-256
**хранимых** байтов каждого прочего блока. Проверка выполняется перед распаковкой, включая сырой Drawing.
Старые TIFF-контейнеры без manifest читаются; checksum не является подписью и не защищает от намеренной подмены.

Ограничения: файл до 4 ГиБ, контейнер до Int32.MaxValue; 65536 блоков с manifest, имя до 512 байт, размер блока не больше Int32.MaxValue,
сумма объявленных размеров до 8 ГиБ. Загрузчик модели дополнительно ограничен:
64 МиБ модели, 1 МиБ на строку, миллион значений, глубина 128, 65536 ключей кривой,
256 МиБ на встроенную текстуру и 1 ГиБ встроенных пикселей суммарно.
Сохранение проверяет соответствующие ограничения, чтобы не записать заведомо нечитаемый документ.
Дублирующиеся имена, неверные длины, переполнения и неподдерживаемые версии отвергаются.

## Модель

`WhimTexDocumentSerializer`: tagged binary, версия 1. Обход публичных,
`[SerializeField]` и `[SerializeReference]` полей; static/readonly/NonSerialized исключены.
Unity-типы обрабатываются явно. Типы хранятся по полному имени; наследование и ссылочная
идентичность восстанавливаются. Double остаётся double.

- `[FormerlySerializedAs]` и публичные аргументы `[MovedFrom]` сохраняют переименования.
- Неизвестные поля/типы и отсутствующие GUID/local ID диагностируются. Документ можно осмотреть,
  но **его сохранение, включая Save As, блокируется**, чтобы не уничтожить непрочитанные данные.
  Это защита, не lossless-перенос неизвестных объектов. Нужно восстановить нужную версию/зависимости и открыть файл снова.
- Ошибка загрузки освобождает уже созданные transient Unity objects.
- Внешний asset хранится как GUID/local ID; отсутствующий subasset не заменяется случайным главным asset.
- Drawing: сырые пиксели, размеры, формат, mip count, linear-флаг. Новый необязательный блок
  `texture:n:sampling` сохраняет фильтр, wrap U/V/W, aniso и mip bias без изменения версии payload.
- Владение Drawing определяется обходом слоёв, не типом main asset: у legacy `.asset` главный объект — Texture2D.
  Сам root legacy-документа тоже пишется значением, не GUID-ссылкой на исходник.
- Незавершённая GPU-рисовка синхронизируется перед сериализацией. Окно завершает активный жест перед Save.
- Встроенные Shader FX принадлежат документу, в том числе при сохранении из legacy-asset.
  После загрузки owner восстанавливается; относительные include в записываемом коде нормализуются к
  project/package paths без inline методов. Внешние FX остаются ссылками и не мутируются при загрузке.
  Окно подготавливает встроенные шейдеры; независимая build-сессия — лениво при Render/Save.
  Производные GPU-кеши не записываются. Неприменённый/ошибочный HLSL блокирует Save.

## Сохранение и окна

- Запись атомарная: уникальный временный файл → Flush(true) → замена. `.meta` не пересоздаётся.
- TIFF кодируется из native composite по полосам прямо в staged stream, без full managed raw,
  full converted image и собранного image byte[]. До четырёх полос в пакете; header с offsets/sizes
  дописывается через seek. Half→byte/float преобразование использует небольшие таблицы.
  Валидация перечитывает полосы пакетами до четырёх/64 МиБ stored (одна большая полоса отдельно),
  проверяя размеры и Adler32 без второго полного декодированного изображения. Modulo Adler отложено
  до безопасного блока из 5552 байт; byte-exact сравнение с прежним writer включено в тесты.
  Контейнер пишется непосредственно в staged-поток, без отдельных payload[] и объединённого TIFF+payload[].
  Каталог/flags проверяются в готовом staged-файле до замены назначения.
- Неизменившиеся документы без внешних inputs/произвольных FX могут пропустить compose/encode/import:
  проверяются сигнатура модели и пикселей, настройки импортёра, путь, размер и время изменения файла.
  Произвольные FX и внешние assets не считаются постоянными; для них остаётся сравнение итоговых байтов.
- Drawing-поверхность перечитывается с GPU только при незавершённой рисовке или отсутствии CPU-копии.
  Preview сам по себе не является правкой: сохранение/копирование не квантует нетронутые исходные пиксели.
- После успешной записи ревизия диска фиксируется даже при ошибке импорта. Ошибка TextureImporter
  диагностируется через публичный `AssetImporter.GetImportLog`; повторный Save повторяет импорт
  даже при совпадающих байтах. Отложенный импорт проверяется после завершения обновления Editor;
  при ошибке документ снова dirty, записанный TIFF не удаляется.
- Drawing использует bounded LRU-кеш готовых блоков: до 256 МиБ и 1024 записей, включая
  несжимаемые блоки. Native Hash128 выбирает кандидата; перед reuse исходные пиксели сравниваются
  **побайтно**, при необходимости через streaming inflate с небольшим pooled-буфером. Это не
  вероятностное принятие совпадения, не доверие dirty/updateCount и не замена integrity на Hash128.
  Cache hit удерживает неизменяемый блок вместе с SHA-256, без повторного сжатия/хеширования SHA
  и без ещё одной полной native-копии. Прямые CPU-правки и Undo учитываются фактическими байтами.
- Новые блоки сжимаются и хешируются совместно, максимум четырьмя worker jobs с ограничением
  суммарного одновременно обрабатываемого raw input примерно 256 МиБ. Это не общий лимит памяти:
  snapshots, compressed buffers, output и GPU-текстуры учитываются отдельно. После подготовки
  native snapshots освобождаются до Compose/TIFF encode. Сигнатура Save строится по SHA-256
  фактически сохранённых блоков, а не быстрым cache keys. In-memory copy пропускает storage cache.
- Save не является O(1): синхронизация изменённой рисовки, сериализация/хеширование, рендер и импорт
  остаются пропорциональны данным, когда они действительно требуются. Первый/изменённый большой документ
  всё ещё требует CPU/GPU composite и snapshots Drawing; streaming не ограничивает всю память Editor.
- `WhimTexDocumentOperation` — scope для UI Save/Open/Recovery. Progress появляется после 400 мс,
  опрашивается не чаще 80 мс. Byte-only jobs выполняются через Task, main thread опрашивает отмену;
  перед освобождением native buffers всегда дожидается jobs. Это не async API и не разрешение продолжать
  рисование во время Save. Render/readback/import и одиночные Unity-вызовы не прерываются.
  До Commit отмена удаляет свой staging и оставляет правки; финальная замена/import не отменяются.
  Существующие agent API не менялись и без этого scope не показывают progress.
- `WhimTexDocumentLimits` проверяет размеры/пиксельный бюджет до GPU sync/render, directory при Open,
  а ожидаемую длину pixels по формату/mips до выделения Texture2D. Повторная serializer-проверка
  защищает embedded textures вне Drawing. Рабочий half-float buffer и decoded composite каждый
  ограничены Int32.MaxValue байт; 16384 — предел стороны, не гарантия допустимости квадратного canvas.
- Привязка файла теперь принадлежит модели через отдельный transient `WhimTexDocumentBinding`, не окну.
  Она переживает reload, а Undo модели не откатывает disk revision. Перемещение asset разрешается через GUID.
  Повторное открытие фокусирует существующее окно; File-ссылки и document field распознают TIFF.
- Общий сервис запрещает запись поверх другого открытого root и проверяет внешние изменения по GUID/размеру/mtime.
  Защита работает и без окна. При конфликте — reopen или Save As, не перезапись чужой версии.
- Удаление последнего слоя остаётся dirty-изменением; закрытие такого документа предлагает сохранение.

### Ручное восстановление

`Tools/WhimTex/Recovery/Recover Staged TIFF…` проверяет TIFF strips, контейнер и integrity каждого блока,
копирует байты только в новый TIFF и импортирует его. Исходный/временный файл не удаляет и не меняет.
Новый GUID/default importer ожидаемы: `.meta` не входит в staging. Не является autosave и не обещает
восстановление незапущенного/неполного Save; модель не пересериализуется, unknown fields не теряются.
`Retry Live Update Recovery` повторяет существующее journal-восстановление после возвращения asset/
исправления importer, не сбрасывая неуспешный journal. Реальный crash/power-loss не моделировался убийством Editor.
- Копирование legacy `.asset` в TIFF оставляет исходник и его output неизменными; ссылки не мигрируются автоматически.

## Live Update

`WhimTexDocumentSession` сохраняет объект импортированной Texture2D: ссылки материалов не меняются.
Рабочая поверхность временно несжатая; исходные GraphicsFormat, ширина, высота, mipmaps и пиксели
восстанавливаются при остановке.

- GPU preview окна → GPU staging → GPU CopyTexture; CPU ReadPixels/Texture2D на каждый кадр отсутствуют.
- Без FX/внешних inputs публикация запускается изменениями. Для произвольных эффектов/внешних текстур
  сохраняется обновление до 30 Гц; нельзя предполагать, что шейдер не зависит от времени.
- Если Read/Write выключен, он включается временно. Исходное состояние восстанавливается при Stop,
  закрытии/смене документа, reload, Play Mode и завершении Editor. Переприменяется нативный импорт.
  До восстановления `.meta` временно изменён; это не override, невидимый для Git.
  Project-specific EditorPrefs journal позволяет восстановить флаг также после перезапуска Editor.
- Сохранение владельца приостанавливает GPU-подмену, но удерживает временный Read/Write до конца сессии.
  После импорта новая backup-копия берётся из сохранённого результата и Live возобновляется.
  Нет дополнительных импортов только ради пары Read/Write off→on вокруг Save; чужие документы не затрагиваются.
  Внешний переимпорт завершает сессию без записи старого backup поверх нового результата.
- Импорт в отдельном worker не выполняет операции с живым окном; завершение импорта обрабатывается в Editor.
- Ошибка старта освобождает staging и восстанавливает исходный импорт. Неполная mip-цепочка отклоняется
  до переключения: публичный Reinitialize не позволяет задать произвольное число mip-уровней.
- Сейчас сервис допускает одну TIFF Live-сессию одновременно; запуск другой переключает владельца.
  Это не ограничение количества одновременно открытых документов.
- Поддерживаются Texture2D Default/Sprite без Crunch. Другие texture types отклоняются до изменения Read/Write.
- Live preview не заменяет финальную платформенную компрессию/обработку импортёра.
- `IPreprocessBuildWithReport` прекращает Live Update перед Player build, восстанавливает Read/Write
  и принудительно импортирует **сохранённый** TIFF. Несохранённые правки не записываются и не теряются.
  После билда Live не возобновляется автоматически. Неудавшееся восстановление блокирует билд.
- Recovery journal удаляется только после успешного восстановления импортированной текстуры.
  При пропавшем asset или ошибке импорта он остаётся; новая Live-сессия не может затереть его своим GUID.

## Проверки

Unity Editor 6000.7, DX12. Запускать через подключённый Unity Pipeline, не отдельный сборщик:

- `Tests~/DocumentReliabilitySmoke.cs` — `run_script`, entry `DocumentReliabilitySmoke.Run`.
  Уникальная временная папка Assets, cleanup в finally. Проверяет контейнер, Bounds, лимиты,
  sRGB/alpha/HDR, незавершённую рисовку, FX ownership, sampling, GUID/окна и lifecycle Live Update.
- `Tests~/DocumentPayloadCoverageSmoke.cs` — `eval_file`. 14 поведений, 694 поля, 46 проверок.
  Уникальные временные assets удаляются в finally.
- `Tests~/DocumentReloadSmoke.cs` — `run_script`: `DocumentReloadSmoke.Prepare`, затем реальная
  перекомпиляция Unity и `DocumentReloadSmoke.Verify`. 8 проверок привязки, несохранённого содержимого,
  восстановления Read/Write и сохранения после reload. Verify удаляет только окно и папку этого теста.
- `Tests~/DocumentPreparationSmoke.cs` — `run_script`, entry `DocumentPreparationSmoke.Run`: checksum,
  streaming, external-write conflict, Undo/disk revision, independent authoring, Drawing migration,
  external FX, pending code, relative includes, Live→Save→Live.
- `Tests~/AgentApiSmoke.cs` — `eval_file`: старый API создания `.asset`, рисование, группы, рендер и Undo/Redo.
  Использует уникальную папку, удаляет свои assets и временные PNG в finally.
- Исторические спайки: `DocumentRoundTripSmoke`, `DocumentLiveUpdateSmoke`.
  Перед запуском проверить их фиксированные пути Assets; они не обладают одинаковыми гарантиями cleanup.

- `Tests~/DocumentReleaseValidation.cs` + `Fixtures/WhimTexPlayerProbe.cs` — разрешённый Windows Player
  build, artifact/runtime проверки, сбои staged-записи, импорта и восстановление journal.
- `Tests~/DocumentPerformanceProbe.cs` — замеры Drawing LDR/HDR, first/unchanged/changed Save и Open.

Результаты, команды и ограничения: [TIFF_VALIDATION.md](TIFF_VALIDATION.md).
Проверен Windows64 Mono/DX12 Player; не проверены все платформенные компрессоры, AssetBundles/Addressables,
все режимы Sprite Editor, реальный hard crash/power loss и все варианты import worker.
Новый Player build по-прежнему требует запроса пользователя.

Независимая сборка и следующий адаптер агента: [TIFF_AUTHORING.md](TIFF_AUTHORING.md).
Старый тип данных и публичные команды агентов на этом этапе не заменяются.
