# WhimTex — инвентаризация переименований и легаси

- Назначение: зафиксировать подтверждённые исправления и места, требующие согласования.
- Статус: локальные изменения в `dev`, 2026-10-08; это срез аудита, не гарантия полного тестового покрытия.
- Источники истины: текущий код, [политика совместимости](../AGENTS.md#identity-and-compatibility), [JSON](../Documentation~/JSON_FORMAT.md), [TIFF](../Documentation~/TIFF_FORMAT.md), [Shader FX](../Documentation~/ShaderFX.md).

## Границы аудита

Проверены семейства имён и механизмов совместимости в 339 исходных файлах `src`
(`cs`, `hlsl`, `shader`, `cginc`, `uss`, `uxml`), их связи с UI, сериализацией,
агентским API, генератором схемы и внешним редактором. Это систематический аудит
терминов и переходных механизмов, а не полное ревью каждого алгоритма.

Приоритет — термин в UI. Сокращённый лейбл и более полное техническое имя допустимы.
Совпадение слов само по себе не доказывает одинаковое назначение: например,
процедурный слой и FX-блок, Canvas View и геометрический viewport.

Текущие версии TIFF-контейнера и JSON документа уже подняты до **2** на предыдущем
этапе. В этом аудите дополнительного повышения версии нет. Пользовательские документы,
библиотеки пресетов, сцены и настройки проекта не переписывались.

## Завершённые переименования

| Было → стало | Причина → действие |
| --- | --- |
| `TextureCompositor` → `WhimTexDocument`; `TextureCompositorWindow` → `WhimTexWindow` | Пользователь подтвердил имена всей модели и всего окна. Обновлены типы, partial-файлы, вызовы API, reflection в тестах, актуальные ссылки и генератор JSON-схемы. Canvas/Canvas View остаются именами области и панели. Старых типов-алиасов нет. |
| `SetCompositor` → `SetDocument`; `CreateTemporaryCompositor` → `CreateTemporaryDocument`; `CompositorOutputChange` → `WhimTexDocumentOutputChange` | Связанные методы, события, переменные, drag-data keys и UI-привязки приведены к Document. Локальный владелец окна называется `activeDocument`; защищённое свойство поведения слоя — `Document`. |
| `Hidden/TextureCompositor/*` → `Hidden/WhimTex/*` | Обновлены имена встроенных шейдеров и соответствующие lookup-вызовы. USS-акцент ссылки на модель переименован в `whimtex-document-reference-accent`, без изменений внешнего вида. |
| `_PreviewScale` → `_RenderScale` | Uniform описывает масштаб рендера и используется не только в Canvas View. Переименованы binding, генерация HLSL, резервирование имени, встроенный Bevel Emboss, примеры и проверки. Алиаса нет. |
| `SdfBevel.hlsl` → `BevelEmboss.hlsl` | UI и каталог уже называли эффект Bevel Emboss, а вход — обычная карта высоты, не SDF. Имя файла и ссылки приведены к назначению. `.meta` перенесён с прежним GUID. |
| Pixelate `_OneBit` → `_ColorMode` | Старое имя булевого режима осталось у enum, выбирающего Quantization/OneBit в группе Color. Обновлены декларация, условия UI, вычисления и тест. Старое имя не переносит значения. |

Ранее выполненные `LayerSwizzle` → `LayerChannelMapping`, `swizzle` → `channelMapping`
и `LayerColorSettingsView` → `LayerRenderingSettingsView` повторно сверены.
UI Mapping/Rendering, поля модели, TIFF/JSON, API и схема используют текущие имена.
Это изменения предыдущего этапа, не новые переименования этого аудита.

Для Document/Window перенесены **68 пар `.cs`/`.meta`**; содержимое всех перенесённых
`.meta` и GUID сохранены. TIFF model block теперь записывает имя `WhimTexDocument`.
JSON не хранит имя корневого C#-типа: его ключ `document` сохранён, а reader и `$defs`
схемы используют новый тип. Версии форматов остаются 2. Пользовательские файлы и
сохранённое состояние окон не мигрировались. Старые имена остаются только в истории,
замороженных fixtures, отрицательных проверках и описании переименования.

## Удалённые механизмы

| Что удалено | Где и зачем |
| --- | --- |
| Адаптер `WhimTexFileCompatibility0125` и его `.meta` | Удалён файл и вызовы из JSON/TIFF reader, ShaderFX и каталога. Отдельного пути чтения файлов 0.12.5 больше нет. |
| `modifiers` → `fx` и allowlist снятых полей | Больше нет приёма старого имени списка FX и молчаливого пропуска старых `outputSettings`, `savedOutputSettings`, `spriteSlices`, ревизий/URL Drawing и `declaredInCode`. Неизвестные поля не объявляются безопасными задним числом. |
| Нулевые Y как наследование X | Убраны адаптации Noise/warp/Pattern. Отсутствующие оси получают текущие фиксированные defaults, а не копируют соседнюю ось. В примерах старые нулевые sentinels заменены явными значениями. |
| Сериализованное Shape `roundness` → углы | Удалено принятие старого поля и перенос через отрицательные sentinels. В документе используются явные `cornerRoundness`. Действующий API-helper рассмотрен отдельно ниже. |
| Восстановление ручных FX-параметров | Удалены дописывание `@param` в старый код, старая provenance-метка и специальный hard-clamp при загрузке. Параметры объявляются только через `@param`. |
| Специальные обновления старых Polar Coordinates/Displacement Map | Нет преобразования Area/Source Center/одного frame в Input/Output и скрытого включения прежнего Repeat-поведения. Обычный refresh связанных пресетов по текущим именам сохранён. |
| HLSL `@formerlyserializedas` | Удалены parser, проверки, matching, metadata-поле, копирование и экспорт в FX/brush-tip. Убраны пять встроенных маркеров Tiling и поддержка в VS Code: validation, completion, grammar. VSIX пересобран штатным скриптом. |
| Автоматическое расширение бинарных векторов | Удалены Vector2 → Vector3/4 и Vector3 → Vector4. TIFF-тег должен соответствовать типу поля; несовпадение диагностируется. Короткие JSON-массивы — другой, действующий синтаксис ввода. |
| `_RepeatFiltering` и `SampleInput(uv, tiling, filterRepeat)` | Удалён скрытый compatibility-switch в Displacement Map и третий аргумент helper. Repeat использует текущее Point/Bilinear-поведение на шве без изменения исходной текстуры. |
| Устаревшие defaults, схема и обещания миграции | Из актуальной таблицы и генератора убраны снятые поля/алиасы; схема пересоздана. Контракты, контекст и руководства EN/RU/ZH больше не обещают миграцию через 0.12.5 или старые Polar/ручные параметры. |

Unity-атрибуты `FormerlySerializedAs` и `MovedFrom` в текущем production-коде
уже отсутствовали. В этом проходе подтверждено их отсутствие; не следует считать,
что здесь заново удалён большой набор таких атрибутов.

Из **47** актуальных рецептов (38 samples и 9 clipboard-примеров) удалены **1040**
записей старой метаинформации: 47 `spriteSlices`, 991 `declaredInCode`, 2 Shape `roundness`.
В **55** полях осей старый нулевой sentinel заменён явным значением. Остальные данные
не переформатированы целиком. Замороженные fixtures, их хеши и provenance не обновлялись.

| Преобразование старых Polar frames | Независимые текущие Input/Output, projective/translated frames, JSON parity и обычный linked refresh. |

Это не означает, что все сценарии запускались или полностью актуализированы
под весь незавершённый рефакторинг.

## Не подтверждено — оставлено для согласования

| Место | Почему не менялось / возможный следующий шаг |
| --- | --- |
| `CanvasViewport` | Геометрическое преобразование координат и видимой области. Viewport может быть самостоятельным техническим термином, а не забытым именем Canvas View. |
| `EffectRenderCache` и общая инфраструктура рендера | Кеш может обслуживать разные сущности. Разделение Effect Layers/FX согласовано, но конкретное имя общего сервиса требует сверки области ответственности, а не механической замены Effect на FX. |
| `Inspector` в именах внутренних UI-методов/partial | UI называется Layer Settings, но Inspector описывает способ отображения свойств. Не доказано, что это незавершённый rename, а не название UI-паттерна. |
| Bevel `_Smoothing` / Normal Radius; `_Amount` / Channel Offset или Dither Strength; `_Smooth` / Transition Width | Разные слова между uniform и лейблом есть, но лейблы могут намеренно пояснять значение. Кандидаты `_NormalRadius`, `_ChannelOffset`, `_DitherStrength`, `_TransitionWidth` требуют согласования, поэтому не заменены. |
| Shape `kind` / Shape; SDF/Outline `metric` / Distance Algorithm; Noise/SDF `encoding` / Output; Make Seamless `histogramContrast`/`quiltingChannels` / Contrast/Channel Matching | Более общий UI-термин не доказывает старое имя поля. Возможная унификация затронет модель, данные и API; оставлено без вкусовых правок. |
| Shape property/API `roundness` рядом с `cornerRoundness` | Это не удалённое сериализованное поле: helper активно устанавливает все четыре угла, а snapshot API показывает первый. Есть пересечение возможностей и неоднозначность при разных углах. Можно отдельно убрать helper или назвать `uniformCornerRoundness`; сейчас не менялось. |
| `ShaderFXParameterType.Vector` для float4 и сохранение Vector → Vector3 при редактировании кода | Можно обсуждать имя Vector4 и более строгие переходы. Но текущая редакторская операция — не reader старых файлов; удаление только по похожему имени не обосновано. |
| Числовой fallback бинарного enum при неизвестном имени | Может скрыть rename значения enum, но также нужен для flags и значений без отдельного имени. Нужна отдельная политика допустимых enum, а не слепое удаление. |

## Сохранённое действующее поведение

- Unity time uniforms согласованы как warning-only, не legacy-исключение. Компиляция и Apply
  разрешены; предупреждение остаётся в Diagnostics и ответах агентского API. Time использует
  общий `ShaderFXDiagnostics`, как ошибки компилятора, деклараций, source/includes и каталога.
  UI/API читают одинаковые записи Error/Warning/Info; отдельного Time-репортера или разбора
  severity в API нет. Console выводит Error как Error и Warning как Warning, подавляя повтор
  source path + severity/location/message до reload, включая transient-компиляции.
  Предупреждения видны также в свёрнутых заголовках и возвращаются при JSON/clipboard подготовке.
  Reusable result cache для Time отключается, а thumbnail snapshot не
  считается обещанием одинакового результата. Описание в техническом контракте и EN/RU/ZH
  руководствах синхронизировано; внутреннее имя `UsesUnsupportedTimeInputs` заменено на
  `UsesUnityTimeInputs`.
- Effect Layers (например, SDF и Outline) и шейдерные FX — разные сущности; различие
  внесено в [глоссарий](DECISIONS.md#глоссарий) после уточнения пользователя.
  `TargetedLayerBehaviour` и относящиеся к таким слоям `effectInput` не являются
  забытым переименованием в FX. Разделение подтверждено, а не оставлено спорным.
- Layer/Brush/PostFx Preview действительно обозначают предварительный просмотр.
  Это не всеобщая замена Preview на CanvasView.
- Native `.asset` для FX-пресета — актуальный формат Unity-ассета, не старый формат документа `.asset`.
- In-place сохранение значений FX при редактировании того же параметра, header/control/helpbox,
  текущие scalar/vector presentation-переходы и JSON-синтаксис коротких массивов не являются alias старых файлов.
- GUID/path fallback, includes и generic unknown-type/field diagnostics сохранены. Это устойчивость
  текущего формата к отсутствующим зависимостям, а не версия-специфическая миграция.
- Защита от потери данных, предупреждение при открытии и явный выбор Save/копии сохранены.
- Замороженные старые документы остаются отрицательными входами для границ версии;
  старый HLSL с теми же текущими именами может оставаться обычным входом shader-теста.
  Историческая provenance в имени fixture не создаёт runtime-совместимость.
- Условия для поддерживаемых версий Unity, геометрические/клавиатурные modifiers,
  отдельные brush settings для разных контекстов и отложенные алгоритмы не удалялись по совпадению слов.
- История релизов, исторические ссылки и существующие URL/якоря руководств не переписывались.

## Проверки и ограничения

После объединения FX-диагностик штатная Unity-компиляция прошла без ошибок.
`shader-fx-diagnostics` прошёл 83 проверки, `shader-fx-time-warning` — 74.
Сверены Error/Warning/Info, normal/transient Apply, сообщения UI и агентского compile/live
API, JSON и clipboard, совместное присутствие compiler errors и Time warnings,
приоритет ошибки над предупреждением в индикаторе слоя, очистка устаревшей диагностики,
ошибка отсутствующего пресета и общее подавление повторов Console.
Первый запуск нового теста ожидал имя параметра в общем сообщении о неверном `@param`;
проверка уточнена по фактическому сообщению, повторный и расширенный прогоны прошли.
Окна пользователя, ассеты и Undo не менялись; UI проверялся на собственных unattached
деревьях, без визуального прогона. Документация и схемы прошли точечные проверки.
Полный набор тестов, Player и GitHub Pages build повторно не запускались.

После переименования Document/Window штатная перекомпиляция Unity завершилась без
ошибок. Прошли три целевых сценария: `document-window-naming` (70 проверок),
`canvas-render-naming-v2` и `document-json-schema-v2`. Проверены отсутствие старых
типов, GUID/MonoScript binding, поиск встроенных шейдеров, все три режима JSON,
бинарный model-block round-trip, рендер и построение интерфейса собственного временного
окна. Первый запуск нового теста выявил пропущенную нормализацию ID тестового слоя;
подготовка исправлена, повторный запуск прошёл. Тест не записывал пользовательские
файлы или Unity-ассеты, восстановил заимствованное состояние рендера/drag data.

JSON-схема пересоздана штатным генератором в Unity (31 тип), агентская и brush-схемы
прошли проверки актуальности. Проверка исходников документации прошла: 84 страницы,
связи EN/RU/ZH и локальные Markdown-ссылки. Проверен `git diff --check`.
Полный набор тестов и сборки Player/GitHub Pages заново не запускались;
результаты предыдущих прогонов ниже — история, не повторная проверка после rename.

Отдельная проверка после согласования Unity time uniforms: штатная перекомпиляция Unity
завершилась без ошибок; `shader-fx-time-warning` прошёл. Проверены оба пути компиляции,
warning вместо ошибки, Diagnostics/API, Console severity, подавление повторов и cache policy.
Первый запуск выявил проблему тестового чтения JSON из ephemeral-сборки; помощник заменён
на публичный JSON API пакета и повторный запуск прошёл. Пользовательские документы, окна,
ассеты и Undo не изменялись. Этот прогон не обновляет результаты остальных сценариев ниже.

Штатная компиляция подключённого Unity Editor завершилась без ошибок.
Прошли **15 целевых сценариев**: 6 Node и 9 Unity.

- Node: `rename-marker-cleanup-v2`, `remaining-legacy-cleanup-v2`, `document-json-schema-v2`,
  `canvas-render-naming-v2`, `shader-fx-external-code-v2`, `distortion-presets-v2`.
- Unity: `canonical-reader-v2`, `shader-fx-parameter-identity`, `unknown-field-reader`,
  `document-vector-types-smoke-v2`, `remaining-legacy-cleanup-unity-v2`,
  `polar-coordinates-unity-v2`, `lighting-bevel-v2`, `native-fx-preset-file-v2`,
  `document-json-smoke-v2`.

Схема сгенерирована из текущего генератора (31 тип); проверка VSIX и `git diff --check`
прошли. Первые запуски выявили старые поля в примерах и два недостающих шага подготовки
тестового документа; это исправлено, затронутые сценарии повторно прошли.

Полный набор, Player build, reload/performance-профили и полная сборка GitHub Pages
в этом проходе не запускались. Изменённые соседние UI/conditional/payload cases,
не включённые в эти 15, не считаются проверенными. После группы следующих переделок
нужен общий прогон документов, FX и UI; старый PASS не подменяет такой прогон.

## Последствия

Старые версии документов отвергаются. Неизвестные поля в текущем формате
диагностируются; автоматическое сохранение по-прежнему не должно молча терять их.
Старые имена uniform, удалённый helper и прежние параметры пресетов не имеют alias.
Для старых файлов нужен соответствующий старый checkout, а не обещание миграции через 0.12.5.

Удалённые исходники и прежние преобразования можно восстановить из Git; отдельная
резервная копия не создавалась. Изменения только локальные: commit/push и опубликованный
релиз `v0.13.0` этим аудитом не изменены.
