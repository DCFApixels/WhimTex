# Независимая сборка TIFF-документов

Статус: внутренний backend подготовлен; `WhimTexApi` и `whimtex_*` команды **не переключены**.
Старый `TextureCompositor` остаётся рабочей моделью и поддерживает чтение прежних `.asset`.
UI больше не создаёт новые legacy `.asset`: выбранный старый документ переносится через
`Assets → WhimTex → Migrate Legacy .asset to TIFF…`, оставляя исходник и его GUID без изменений.
Это замена способа хранения и lifecycle сессии, не переписывание движка композиции.

## Реализованная граница

`WhimTexDocumentBuild` — disposable-сессия внутри Unity Editor, без WhimTex window:

1. `Create(width, height)` — transient-модель, без создания файлов.
2. `Open(path)` — TIFF → модель и Drawing-пиксели, без компиляции HLSL.
3. `Copy(source)` — независимая копия, включая Drawing и собственные FX. Legacy-ассет не перепривязывается.
4. Изменения — через существующие типы слоёв/трансформов/кистей. Источник истины один: `Document`.
5. `Render()` — лениво подготовить встроенные FX, выполнить текущий движок. Возвращённой Texture2D владеет вызывающий код.
6. `Save(path)` — подготовка FX → общий writer → staged TIFF → атомарная замена → TextureImporter.
7. `Dispose()` — освобождение принадлежащих сессии transient-объектов. Внешние assets не уничтожаются.

Unity objects, ShaderUtil, композиция и AssetDatabase — только main thread подключённого Editor.
Фоновым потокам доступны лишь изолированные байты/математика/сжатие; это не standalone .NET renderer.
Сохранение проверяет неприменённый/ошибочный HLSL. Внешний FX не компилируется через мутирующий `Apply` при открытии TIFF.

`WhimTexDocumentFile.InspectStorage` читает каталог блоков и размеры без создания Unity objects,
распаковки Drawing и HLSL. Это metadata-only inspection, не полный анализ структуры слоёв.
Обычный `Open` материализует Drawing; ленивой подгрузки отдельных растров в рабочую модель пока нет.

## Идентичность, владение, конфликты

- `WhimTexDocumentService` владеет правилами пути/записи; `WhimTexDocumentBinding` — transient-состояние
  связи модели с GUID, disk revision и dirty. В TIFF оно не сериализуется.
- Binding — отдельный объект, чтобы Undo слоёв не откатывал ревизию диска. Ссылка переживает domain reload.
- Внутрипроцессная блокировка по пути; запрещена запись поверх другого открытого документа.
- При повторном сохранении проверяются GUID, длина и время изменения файла. Дополнительная проверка
  непосредственно перед заменой обнаруживает изменение во время подготовки файла. Это optimistic lock,
  не распределённая блокировка и не гарантия против внешнего инструмента, сохраняющего timestamp и размер.
- Не создавать второй редактируемый root поверх открытого окна: будущий адаптер должен либо использовать
  его live-сессию с существующими locks, либо вернуть конфликт. Сейчас независимый writer откажет в записи.
- Save As оставляет прежний файл. Конвертация `.asset` не копирует его GUID и не переназначает material/sprite references.
- Относительные `#include` в сохраняемом коде приводятся к project/package paths без разворачивания методов
  и без изменения текста в открытом FX. Внешние зависимости остаются внешними.

## Следующий адаптер API — только после отдельного согласования

Существующие `.asset` команды остаются рабочими. Не выдавать internal backend за уже доступные команды;
следующим этапом нужно дать агентам тот же backend для TIFF, не дублируя операции.
Предлагаемый набор команд и разделение обязательных/диагностических возможностей зафиксированы в
[TIFF_AGENT_COMMANDS.md](TIFF_AGENT_COMMANDS.md).
При подключении TIFF не дублировать алгоритмы операций: отделить применение проверенных операций к модели
от загрузки/commit, затем дать им backend-сессию вместо поиска окна или прямого AssetDatabase.LoadAssetAtPath.

- Явные `assetPath` и ожидаемая ревизия; inspect перед edit. Не выбирать произвольное открытое окно.
- `dryRun` проверяет запрос без файла и чужих mutations; render/commit — отдельные явные этапы.
- Операции со слоями сохраняют ID, локальные трансформы групп, источники texture-параметров и владение Drawing.
- Ошибки возвращают структурированный результат; неизвестные типы/поля/refs блокируют lossy commit.
- Рендер и сохранение отменяются до атомарной замены; отмена не оставляет неполный TIFF.
- После commit возвращать итоговый путь/GUID/revision, затем повторно inspect/render для проверки.
- Живой API сохраняет нынешние lock/begin/transfer правила, независимый не меняет пользовательскую сцену.

## Что ещё требует отдельных измерений

Большой TIFF всё ещё использует буферы композитного изображения; полностью потоковое кодирование полос
и ленивые Drawing требуют отдельного профилирования/изменения lifecycle. HLSL-кеш для произвольного
шейдера нельзя считать вечным: includes, внешние текстуры, время и параметры могут менять результат.
Windows64 Player проверен: runtime получает texture artifact, не этот backend и не слои документа.
Результаты разрешённого билда и замеров больших Drawing: [TIFF_VALIDATION.md](TIFF_VALIDATION.md).
Замеры не заменяют проверку скорости загрузки на целевых устройствах.

Проверки: `DocumentPreparationSmoke`, `DocumentReliabilitySmoke`, `DocumentPayloadCoverageSmoke`,
`DocumentReloadSmoke`, `AgentApiSmoke` в `Tests~`. Перед запуском проверять runner и cleanup каждого файла.
